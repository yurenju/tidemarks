# 檢查這次改動的中文

規則本來就寫在 `CLAUDE.md` 與 output style 裡，而 agent 照樣寫出翻譯腔。原因不是規則不清楚，
是**寫的人讀回去看到的是自己本來想寫的意思，不是實際打出來的字**。所以這份文件的工作不是再講
一次規則，是給一套照著做就會發現問題的步驟。

## 什麼時候跑

- 開 PR 之前，`/code-review` 之後、push 之前
- 寫 PR 說明或 issue 內文的時候
- 改完任何 `docs/`、`CONTEXT.md`、`CLAUDE.md`、`README.zh-TW.md`

## 三個步驟

### 一、跑腳本

```bash
node scripts/zh-lint.ts
```

不帶參數就是讀這個分支比 `main` 多出來的那些行，含還沒 commit 的。

PR 說明與 issue 內文**先寫成檔案再檢查**，不要直接塞進指令：

```bash
node scripts/zh-lint.ts .scratch/pr-body.md
```

過了再 `gh pr create --body-file .scratch/pr-body.md`。`.scratch/` 被 `.gitignore` 擋著，不會進 repo。

### 二、處理報告

報告分兩種，差別只有一件事：**腳本分不分得出對錯**。

| 標記 | 意思 | 你要做什麼 |
| --- | --- | --- |
| `[一定要改]` | 這個字串在這個 repo 的文件裡沒有正確用法 | 照 `改成` 那行改掉，不用判斷 |
| `[要檢查]` | 有正確也有錯的用法，腳本分不出來 | 讀正例與反例，判斷這句是哪一種 |

⚠️ **`[要檢查]` 的每一條都要給出結論**，兩種結論都算數：改了，或者這是正例所以不動。跳過不算
檢查過。⚠️ 不要照著 `改成` 那行盲目取代，把對的中文改壞比留著一個錯字更糟。

改法有三種，報告會講明是哪一種：

| 報告上寫 | 意思 | 例子 |
| --- | --- | --- |
| `改成` | 換一個中文說法 | 判準 → 怎麼分 |
| `用英文原文` | 中文沒有這個詞，硬翻只會造一個查不到的字 | 鉤子 → hook、回呼 → callback |
| `把動作寫出來` | 那個詞把「做了什麼」整個藏起來了 | 優雅地關閉連線 → 關之前先把還沒回完的請求做完 |

### 三、逐段讀一次

腳本抓的是字串，而最難的那種問題**每個字都對**：「成本是真的」五個字沒有一個字有問題，但中文
不會這樣講。這種只能讀。

**把這次新增或改寫的中文段落一段一段列出來**，每段回答三個問題。不要整批回答「檢查過了沒問
題」，那句話不算檢查。

1. **這句話你會這樣講出口嗎？** 會停頓的地方通常就是直譯來的
2. **有沒有哪個名詞比喻出現了第二次？** 出現第二次就表示你已經把它當術語在用，而讀的人手上沒有
   那個定義
3. **有沒有抽象名詞可以直接寫成一件事？**

實際發生過的三個例子，各對應一個問題：

| 寫出來的 | 問題 | 該寫成 |
| --- | --- | --- |
| 讀到那份文件，成本是真的 | 3 | agent 每次都要讀完那 250 行，然後照著它做事 |
| 墓碑化 → 墓碑要寫成什麼格式 | 2 | 被取代的 ADR 要留成什麼樣子 |
| 量到多少墨水覆蓋率 | 2 | 量了字會糊掉多少（做法是算那一行有多少比例被筆畫蓋住） |

## 規則清單在哪

在 `scripts/zh-rules.ts`。每一條都帶著抓什麼、正例、反例、改法，型別上就要求第二級的規則一定要
有正例，因為**一條沒有人分得出對錯的規則，會被用刪掉正確句子的方式遵守**。

### 要加新規則的時候

1. 加進 `MUST_RULES` 或 `CHECK_RULES`
2. `scripts/zh-rules.test.ts` 會自動測它抓不抓得到自己的反例，不用另外寫
3. **想放第一級就先問：這個字在這個 repo 的文件裡有沒有正確用法。** 有的話放第二級

這道門檻擋過真的東西：`返回` 本來在第一級，掃全 repo 的時候誤抓了「Android 的返回鍵」；簡體字
本來在第一級，誤抓了日文漢字（`体`、`学`、`会`、`読`）跟 `chinese.ts` 那張簡繁對照表。第一級一旦
有誤抓，人就會開始整份跳過報告，那時候真的那幾條也一起被跳過。

## 為什麼是 skill 不是 sub agent

開一個 agent 起來要花的時間太多，而這件事一天會做很多次。腳本負責找（誰跑都一樣），skill 負責
讓規則在你正要寫字的時候就在眼前。剛載入的文字比較會被照著做，這正是這份文件存在的形式理由。
