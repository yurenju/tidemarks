# 介面文案與翻譯

Tidemarks 的介面有三種語言：**英文（原文）、繁體中文、日文**。三種地位相同，少一條 CI 就紅。
為什麼英文是原文、代價是什麼，見
[ADR-0031](../adr/0031-english-is-the-source-and-chinese-becomes-a-translation.md)。

**翻譯不是一個回合，是寫程式的一部分。** 加一條文案的那個 commit 就要把三種語言補齊——那一刻
是唯一一次你手上有完整脈絡的時機，隔一個禮拜回來補是用猜的。CI 是後盾，不是流程。

## 加一條文案

```tsx
import { Trans, useLingui } from "@lingui/react/macro";

// JSX 裡：
<Trans comment="書架空的時候的全部內容。兩個短句：先講事實，再講怎麼辦。">
  No books yet. Drop an epub in, and start here.
</Trans>;

// 屬性、字串的位置：
const { t } = useLingui();
t({ message: "Close", comment: "關掉抽屜或面板的 ✕ 的螢幕閱讀器名稱。動詞。" });
```

**英文寫在程式碼裡，它同時就是這條詞條的 id。** 不用取名字。

補完之後：

```bash
npm run i18n:extract          # 掃程式碼，更新三份 .po
```

然後把 `packages/app/src/locales/zh-TW.po` 與 `ja.po` 裡新出現的 `msgstr ""` 填掉。

## `comment` 是必填的，而且它是這整件事的重點

CI 會擋掉沒有 `comment` 的詞條。原因不是形式主義：**翻譯出錯最常見的形式不是翻得爛，是拿另一個
地方的詞條來用。** 從英文字面看不出來的差別，只有 comment 講得出來——

- `Order` 在書架上是名詞（排序方式），不是動詞「排序」
- `Publisher's` 是「照書自己的」，不是「出版社的」
- `Serif`／`Sans` 在中日文是**字體的名字**（明體／ゴシック体），不是「有襯線／無襯線」
- 四種螢光是**顏料**（蓼藍、赭石、苔綠、松煙），不是色相

comment 要寫的是：**這句話出現在哪、旁邊有什麼、哪個字有陷阱**。不要寫「按鈕的標籤」這種
從程式碼看得出來的東西。

`{value}` 這種值一律說明它是什麼、會不會被翻譯（書名、章節名是書的，永遠不翻）。

## 同一個英文要有兩種翻法的時候

加 `context`。它會進 id，所以兩條詞條從此各自獨立：

```tsx
t({ message: "Order", context: "verb", comment: "…" });
t({ message: "Order", comment: "…" }); // 另一條
```

⚠️ **`context` 只在真的撞到的時候才寫。** 預設是共用——`Close` 在兩種抽屜上就是同一個詞，
拆開只會生出二十條 `Cancel`，然後改的時候漏掉十九條。

## 跨檔共用會被看見

同一條詞條被兩個以上的檔案用到時，CI 會列出來要你確認一次：

```bash
npm run i18n:check -- --write   # 確認過，寫進 shared-messages.json
```

那個檔案進版控，所以每多一筆共用就是 diff 裡的一行。**看到它出現的時候先想一秒**：這兩個畫面
真的該講同一句話嗎，還是其中一個需要 `context`？

## 刪掉文案

刪掉程式碼裡的 `<Trans>` 或 `t()` 之後跑 `npm run i18n:extract`，三份 catalog 裡的孤兒條目會
一起被掃掉。忘了跑的話 `npm run i18n:check` 會擋下來。

## CI 在檢查什麼

`npm run i18n:check`（CI 在 `npm test` 之前跑）擋四件事：

| 擋什麼 | 症狀 |
| --- | --- |
| 譯文缺漏 | 介面講到一半跳回英文 |
| 沒有 `comment` | 下一個 agent 只看得到那幾個英文字 |
| 孤兒條目 | 沒人用的詞條看起來像有人做過的事，還會被持續維護 |
| 新的跨檔共用 | 一句話悄悄開始服務兩個畫面 |

判斷的部分是純函式，在 `scripts/i18n-audit.ts`，由 vitest 的 `scripts` project 蓋。

## Worker 那半邊不一樣

⚠️ **`packages/app/worker/` 底下不能用 macro。** wrangler 用 esbuild 打包 Worker，那條路上沒有
Babel，macro 會在執行期爆炸。Worker 的訊息自己取 id：

```ts
i18n._({
  id: "email.magicCode.subject",
  message: "Tidemarks sign-in code: {code}",
  comment: "…",
  values: { code },
});
```

三件事要記得：

- **descriptor 一定要寫在 `i18n._()` 裡面。** 存成 `const` 再傳進去的話，`lingui extract` 看不見
  它，那條詞條會安靜地永遠不存在。
- **改英文不會讓譯文失效**（id 是自己取的，不是算出來的）。動 Worker 訊息的英文時，同一個
  commit 要把中日文一起改。
- **Worker 碰得到的 app 模組也不能有 macro。** 哪些模組碰得到，看 `tsconfig.worker.json` 的
  `include`——那份清單就是這條線。`SHELF_ORDERS` 搬到 `shelf-order-choices.ts` 就是為了這個。

Worker 怎麼知道要用哪種語言：請求的 `Accept-Language`。app 每一個請求都帶上讀者選的介面語言
（`src/lib/api.ts`），瀏覽器直接開的同意頁則帶自己的。`I18n` 每個請求建一個——Worker 的 isolate
服務很多人，共用一個再 activate 會讓別人的語言漏進來。

## 純模組拿 `i18n` 的方式

**會被測試的決策模組用參數收 `i18n`**，跟 `statusLines` 收 `now` 是同一個道理：

```ts
export function statusLines(i18n: I18n, progress, sessions, now) { … }
```

**本來就有副作用的模組**（`sync.ts`、`version.ts`）直接用共用的那一個就好。

## 語言怎麼決定

`navigator.languages` 自動判斷，讀者可以在〈設定〉的語言分頁覆寫，存在 localStorage，
**不同步到帳號**（[ADR-0005](../adr/0005-typography-settings-follow-the-device.md)）。

- `zh-CN`／`zh-Hans` 也給 `zh-TW`，**不做簡繁轉換**。`chinese.ts` 那張對照表是給**書**用的。
- 認不出來的語言落回英文。

## 什麼不進 catalog

- **語言選單自己的三個名字**（English／繁體中文／日本語）。會來按這個設定的人，正是看不懂
  當前語言的那個人。
- **`chinese.ts` 的簡繁對照表、fixture 的文字、直排測試裡有鑑別力的字元**——它們是被測對象，
  換成英文那句話就不成立（CLAUDE.md 的〈例外〉那節）。
