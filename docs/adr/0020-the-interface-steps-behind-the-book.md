# 介面退到書後面去

日期：2026-08-12。

> **2026-08-13：點擊分區那一半已被
> [ADR-0024](0024-turning-a-page-is-a-swipe-and-nothing-else.md) 取代。** 手指翻頁只剩拖曳，tap
> 一律叫出 chrome、不分區。底下寫的三個狀態、拒絕自動退場、以及 `preventTapDefault()` 不必動的那段
> 論證全部照舊——那段論證在新的分法底下反而更乾淨：整頁的 tap 都有動作要保護。

## 決定

閱讀器同一時間只成立三個狀態的其中一個（讀／找／標），chrome 不再常駐。定義在
[CONTEXT.md](../../CONTEXT.md)〈chrome〉，版面與工作項目在
[docs/specs/ux-replan/spec.md](../specs/ux-replan/spec.md)。

跟著改的是點擊分區：**畫面下方三成分左右兩半翻頁，其餘任何一處輕觸一次叫出 chrome。** 桌機的滑鼠
點擊也叫出 chrome，而且不分區。

## 為什麼要有一個狀態，而不是五個開關

今天閱讀器上有五層東西可以同時在畫面上：頂列、Scrubber、目錄側欄、筆記側欄、設定 popover。每一層
各自有自己的顯示條件，而**沒有任何一層負責回答「這一刻讀者在做什麼」**。結果是三個看起來無關的症狀：
閱讀時介面太吵、匯出匯入像 debug 按鈕、書架答錯問題。它們是同一件事的三種長相。

換成狀態機之後，每一層的出現都是讀者剛剛做的動作換來的，而**互斥是它的全部價值**。留一個例外
（例如 chrome 開著的時候允許顏色列疊上去）等於留五個，因為每個例外都會長出自己的條件，那正是
現在這個樣子。

## 這筆分區的帳付給誰

[#60](https://github.com/yurenju/folis/issues/60) 拆掉了中間那條中性帶，換到的是「整頁沒有一處點了
沒反應」。現在把上方七成收回去，看起來像是把那筆交易反悔。

不是。**中性帶是一段點了沒有動作的地**，而新分區裡上方七成點下去會出事（chrome 出現）。#60 換到
的那一條在新分區底下照樣成立，翻頁與叫介面各佔一塊，沒有死區。

`preventTapDefault()` **不必動**，這一點跟 replan 初稿寫的相反。它現在是
`return turnsPageByTap(e)`，條件是「手指或觸控筆、不是連結」，**本來就不看位置**。CONTEXT.md 舊版
留了一句預言：「哪天中性帶回來了，位置這個條件要跟著回來」。那句預言假設回來的會是一段沒有動作的
地，而實際回來的不是，所以不觸發。上方七成的 tap 一樣要取消預設動作，否則 Chrome for Android 會在
那裡一點就選走一個詞，而讀者以為自己在叫出介面。

## 為什麼是下方三成，不是別的比例

手指構得到的就是下方那一帶，而讀者要叫介面的時候本來就會往上點。這是一個猜測，不是量出來的，所以
它的門檻寫在 spec 而不是這裡：**真機上滑十分鐘，每 50 次翻頁誤觸超過 5 次就回頭放大翻頁帶。**

明確拒絕的是**自動退場**（chrome 出現後 N 秒沒動作自己收）。那是一個讀者看不見的計時器，人正在
目錄裡找章節時它會把東西收走，比誤觸更難受。誤觸的代價只有一次多餘的 tap。

## 桌機那一半是白撿的

CONTEXT.md〈Navigator〉早就寫死「滑鼠點擊一律不翻頁」，理由是它會跟「點一下定位游標」「雙擊選詞」
打架。所以桌機上點擊這個動作的語意本來就是空的，拿來叫 chrome 不必付任何代價，也不必在桌機上解釋
一條讀者看不見的三成線。

## 代價

- `tap.spec.ts` 有一條斷言「中間點也前進」，那是 #60 留下的守門。它要改寫，而改寫一條守門測試永遠
  值得停下來看一眼：新的斷言守的是「中間點叫出 chrome、不翻頁」，不是「中間點沒事」。
- 桌機的目錄／筆記側欄收掉，一律走底部浮層。桌機使用者失去「邊讀邊看目錄」，換到的是不必維護兩套
  版面。〈找〉狀態下讀者本來就不是在讀，這個交易划得來。
- 讀者的肌肉記憶要重建一次。這是這個決定裡最難逆轉的部分，也是它值得一支 ADR 的原因。
