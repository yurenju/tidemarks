# 介面退到書後面去

日期：2026-08-12。

## 決定

閱讀器同一時間只成立三個狀態的其中一個（讀／找／標），chrome 不再常駐。定義在
[CONTEXT.md](../../CONTEXT.md)〈chrome〉，版面與工作項目在
[docs/specs/ux-replan/spec.md](../specs/ux-replan/spec.md)。

**輕觸一次叫出 chrome**，桌機的滑鼠點擊也是。翻頁不由 tap 負責
（[ADR-0024](0024-turning-a-page-is-a-swipe-and-nothing-else.md)）。

## 為什麼要有一個狀態，而不是五個開關

今天閱讀器上有五層東西可以同時在畫面上：頂列、Scrubber、目錄側欄、筆記側欄、設定 popover。每一層
各自有自己的顯示條件，而**沒有任何一層負責回答「這一刻讀者在做什麼」**。結果是三個看起來無關的症狀：
閱讀時介面太吵、匯出匯入像 debug 按鈕、書架答錯問題。它們是同一件事的三種長相。

換成狀態機之後，每一層的出現都是讀者剛剛做的動作換來的，而**互斥是它的全部價值**。留一個例外
（例如 chrome 開著的時候允許顏色列疊上去）等於留五個，因為每個例外都會長出自己的條件，那正是
現在這個樣子。

## 明確拒絕自動退場

chrome 出現後 N 秒沒動作自己收，不做。那是一個讀者看不見的計時器，人正在目錄裡找章節時它會把
東西收走，比誤觸更難受。誤觸的代價只有一次多餘的 tap。

## 整頁的 tap 都要取消預設動作

`preventTapDefault()` 的條件是「手指或觸控筆、不是連結」，**不看位置**，而現在整頁的 tap 都有
動作要保護，所以那個條件正好。不取消的話 Chrome for Android 會在那裡一點就選走一個詞，而讀者
以為自己在叫出介面。

## 桌機那一半是白撿的

CONTEXT.md〈Navigator〉早就寫死「滑鼠點擊一律不翻頁」，理由是它會跟「點一下定位游標」「雙擊選詞」
打架。所以桌機上點擊這個動作的語意本來就是空的，拿來叫 chrome 不必付任何代價。

## 代價

- 桌機的目錄／筆記側欄收掉，一律走底部浮層。桌機使用者失去「邊讀邊看目錄」，換到的是不必維護兩套
  版面。〈找〉狀態下讀者本來就不是在讀，這個交易划得來。
- 讀者的肌肉記憶要重建一次。這是這個決定裡最難逆轉的部分，也是它值得一支 ADR 的原因。
