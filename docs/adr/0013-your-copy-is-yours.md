# 你的書就是你的那一份

日期：2026-08-06。

## 決定

spine 對使用者上傳的檔案做什麼、不做什麼，一次列完：

| 做 | 不做 |
| --- | --- |
| R2 一個使用者一份，永不去重 | 掃描內容 |
| 一律經 Worker 驗證後串流，不發簽名 URL、不發公開網址 | 判讀誰在怎麼用 |
| 匯出原封不動 | 人工審核 |
| 帳號的裝置數設上限 | |

這是 [ADR-0010](0010-spine-is-never-the-path-to-a-book.md) 的另一半：那份講**不做什麼功能**，
這份講**檔案本身怎麼被對待**。

## 為什麼要一次列完

每一條的反面都很容易做：去重省儲存費、簽名 URL 省一趟串流、掃描內容「順便做一下也好」。
單獨看每一條都像小事，合起來卻會讓 spine 變成另一種東西。

寫下來就是為了擋那一天，跟 ADR-0010 擋「分享一段書摘」是同一個手法。

## 永不去重

R2 的 key 是 `${userId}/${bookId}/${kind}`（[worker/index.ts](../../packages/app/worker/index.ts)），
**每個使用者一份**。兩個人上傳同一本書，伺服器上就是兩份，一個 byte 都不合併。

誘因是省儲存費，而那筆錢小到不存在，R2 每月免費 10GB，
[ADR-0011](0011-the-account-is-free-and-the-quota-is-paid.md) 量過一個典型使用者一年不到 US$0.05。

但真正的理由不是錢：**去重之後，你的書就不再是你的那一份了。** 刪掉它的時候刪掉的是什麼？
別人動了它會不會影響到你？這些問題本來不存在，去重會把它們造出來。

## 不發簽名 URL、不發公開網址

epub 與封面一律經 Worker 串流，先確認是你的書才給。

R2 的 presigned URL 能省掉那一趟，但它在有效期內**誰拿到誰都下得到**。那就長出了 ADR-0010
明講不能有的東西：一個掛著書裡文字、不需要登入的網址。

## 匯出原封不動

**你存什麼，領什麼。** 匯出的 epub 就是當初上傳的那個檔案，spine 不在裡面塞 highlight、
不改寫 metadata、不重新打包。

筆記與進度是分開的一份 JSON，跟 epub 放在同一包 zip 裡。想丟掉 spine 的部分就丟掉那個 JSON，
epub 是乾淨的，別的閱讀器直接讀得下。

這是〈退路〉的一部分：搬得走要真的搬得到別的地方去，不是只搬得到另一個 spine。

## 帳號的裝置數上限

一個使用者能綁的 passkey 數有上限。（原本還有一句「recovery code 一次只發一組」，recovery code
已隨 [ADR-0015](0015-an-account-is-only-as-strong-as-its-inbox.md) 拿掉，那句跟著失效。）

理由是成本。ADR-0011 講了 CPU 是唯一會長大的成本（MCP 的取節與搜尋要 Worker 真的 parse
epub），而共用帳號是唯一能把一份訂閱的用量無上限放大的形狀。

**一份訂閱給一個人用，是為了讓價格算得出來**，不是為了防誰。上限訂在真實讀者用不完的地方
（手機、平板、筆電、桌機還有餘裕），碰得到它的只有另一種用法。

## 不掃描內容、不判讀誰在怎麼用

**spine 不看你的書。**

這一條沒有例外，包括「為了改善服務」「為了做推薦」那些。伺服器**讀得懂**你的書是 MCP 的前提
（[ADR-0009](0009-open-source-buys-an-exit-not-contributions.md) 已經講明那件事開源換不到，
所以不承諾），但讀得懂跟主動去讀是兩件事。

第二個理由跟 ADR-0010 的第二個理由同一個：**一個人扛不起永遠不會結束的工作。** 掃描、審核、
判讀誰在怎麼用，每一項都是那種永遠做不完的工作，而換到的東西沒有一項是讀者要的。

## 只收 DRM-free 的 EPUB

帶 DRM 的檔案 spine 讀不了。匯入失敗時要**明講是 DRM**，而不是丟一句「無法讀取這個檔案」，
後者只會讓人以為是 bug，然後去試第二次、第三次。

這條線 Readwise 也是畫在這裡（ADR-0010 對照過）：書如果是從 Amazon 那種只給 DRM 檔案的
地方買的，就是匯不進來。
