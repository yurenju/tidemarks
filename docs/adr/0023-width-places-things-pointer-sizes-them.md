# 寬度決定東西排在哪裡，指標決定東西多大

日期：2026-08-12。

## 決定

介面的分岔用**兩種互不重疊的判斷**，一種都不嗅 user agent：

| 問的是 | 用什麼 |
| --- | --- |
| 一欄還是兩欄、bar 在頂還是在底 | 視窗寬度（600 / 820 / 1280 / 1680） |
| 命中區多大、底部 bar 出不出現 | `any-pointer: coarse` |
| 字多大 | `pointer: coarse` |
| 拖曳吸不吸附、位移算不算 tap | 事件型別（`lib/touch.ts`） |

值與逐項規格在 [docs/specs/device-sizing/spec.md](../specs/device-sizing/spec.md)。

## 為什麼寬度不能拿來猜手指

在這之前整份 `index.css` 只有一條 `@media (max-width: 700px)`，而它同時扛著兩件事：手機的版面，
以及手機的手。那條規則說得出「這個視窗很窄」，說不出「碰它的是什麼」。

兩個具體的壞法：桌機使用者把視窗拉到 600px 寬會拿到一整套為手指做的介面，而他手上是滑鼠；
iPad 橫放是 1024px 寬，照寬度判斷會拿到 32px 的命中區，而碰它的是手指。這兩種人都不罕見，
而且**都不會來回報**，他們只會覺得這個 app 有點難用。

## 為什麼是兩種 pointer query，不是一種

看起來多餘，實際上問的不是同一件事。

- **命中區問「這台機器有沒有一根粗指標」**，所以用 `any-pointer`。觸控筆電有觸控螢幕，那塊螢幕
  被戳的時候手指的大小跟在手機上一樣。這裡猜錯的代價是按不到。
- **字級問「主要那根是不是手指」**，所以用 `pointer`。觸控筆電的主要指標是觸控板，使用者坐在
  桌前、螢幕在一臂之外，字放大到手機的尺寸只是變吵。這裡猜錯的代價是難看，不是難用。

兩個代價不對稱，所以兩個問題各自取安全的那一邊：命中區寧可大，字級寧可不動。

## 這筆帳付給誰

四件已經寫下來的事被推翻，全部集中在這裡，免得之後有人讀到舊句子以為還算數：

1. **「全部 `min-height: 44px`，桌機也一樣」**（`docs/design-system.md`）。當初換到的是「不必判斷
   這個鈕會不會被手指按到」，現在那個判斷有 `any-pointer` 可以問了，所以那塊空間換成了桌機上
   更密的排版。唯一的例外（封面的 `⋯`，臉 26 靶 44）照舊。
2. **「桌機不開側欄，一個殼給三張 sheet」**（`BottomSheet.tsx` 的檔頭）。理由是「兩套版面就是兩套
   bug」，那句話仍然是對的，所以面板與 sheet 共用一個元件，分岔只在錨在哪一邊、swipe 的方向、
   以及寬度。回來的側欄跟 ADR-0020 拿掉的那個不是同一個東西：那個是常駐的，這個是〈找〉狀態的
   一部分，而且蓋住內容不推開。

   ⚠️ **2026-08-30 補：錨法多了一種，仍然是一個元件。** 窄畫面上〈目錄〉與〈筆記〉改成佔滿整個
   畫面，〈排版〉留在底部升起（它需要上面那頁真的看得見，見上）。所以分岔變成三種而不是兩種，
   而三種仍然全部由 CSS 決定。理由與代價在
   [ADR-0044](0044-the-keyboard-takes-the-bottom-so-typing-goes-to-the-top.md)。

   上面那句話列的三項分岔裡，「寬度」那一項也跟著改了：那條線本來寫成
   `(any-pointer: coarse) and (max-width: 819px)`，而按這支 ADR 自己的表，面板錨在哪一邊屬於
   「東西排在哪裡」，該只問寬度。現在只問寬度，線在 820。
3. **「側欄已經收掉了」**（`CONTEXT.md`〈抽屜〉的 _Avoid_）。改成一條〈面板〉的定義。
4. **「`.active` 只轉字色，填底等於在一個面裡放第二個面」**（`index.css`）。頂部那一排改成加一個
   綠框；底部 bar 維持原樣。那句註解的道理只在鬆排的 bar 上成立。

## 代價

**CSS 裡同時有三種 query，讀的人一定會問為什麼**，這份文件就是為了那一刻寫的。

**手機那一半只有一家瀏覽器守著。** 瀏覽器測試原本全跑在 1000×700 的 fine 指標下，也就是每一條分岔
的桌機那一邊。現在多了 `hand-held.spec.ts`，而它能成立是因為量過：Playwright 的裝置模擬**確實**會讓
`pointer: coarse` 在 CSS 裡成立。代價是 firefox 沒有 `isMobile` 可用、webkit 在測試映像裡存不進
`Blob` 到 IndexedDB，兩家都 skip，所以那條分支實際上由 chromium 一家看著。量法與數字在
[docs/specs/device-sizing/measurements.md](../specs/device-sizing/measurements.md)，而**這件事要寫在
PR 說明裡**，不能讓它消失在一句「三家都綠」裡。

**兩種 pointer query 加上事件型別，等於同一個問題有三種問法。** 這不是重複，是三個不同的問題（這台
機器有沒有手指／主要那根是不是手指／現在碰它的是什麼），但讀 code 的人一定會先當成重複。所以每一處
分岔的註解都要說出它問的是哪一個，尤其 Scrubber 的吸附：它看的是 `pointerType`，因為
`any-pointer: coarse` 在觸控筆電上永遠成立，而那台機器的滑鼠不該吸附。
