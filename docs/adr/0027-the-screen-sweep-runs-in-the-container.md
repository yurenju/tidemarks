# 巡檢圖在容器裡產，證據圖仍在 host

日期：2026-08-18。

## 決定

**畫面巡檢**——一次走完 app 每一個畫面、把每一張都截下來——在**容器裡**跑，而且進 CI
（`scripts/capture-shots.sh`、`packages/app/playwright.sweep.config.ts`、
`packages/app/tests/sweep/`）。

**證據圖不動**，仍然照 [ADR-0007](0007-pr-evidence-is-captured-on-the-host.md)：host、
playwright-cli、三家、附數字與五項判讀。

這兩件事以前共用「截圖」這一個詞，現在分開了。分法寫在 `CONTEXT.md`，一句話是：**證據圖是為了
某一次改動而拍的，巡檢圖是不管改了什麼都拍。**

|  | 巡檢圖 | 證據圖 |
| --- | --- | --- |
| 在哪拍 | 容器 | host |
| 幾家瀏覽器 | chromium 一家 | 三家 |
| 什麼時候拍 | 你需要看的時候，加上每個 PR 跑一次確認它還跑得動 | 開 PR 前 |
| 圖留著嗎 | 不留，`.scratch/shots/` 每次覆蓋 | 傳上 R2，30 天後消失 |
| 誰在讀 | 你，以及跟你討論視覺的 assistant | 讀 PR 的人 |

## 為什麼是容器，而 ADR-0007 說的是 host

ADR-0007 那份**沒有被推翻**，它講的是另一種圖。它放棄的四樣代價裡，有兩樣在巡檢這個用途下的
輕重剛好反過來：

- **「圖沒有出處」**在證據那邊是真的痛（三十天後回頭看，圖不見了，只剩你寫下的數字），在巡檢
  這邊幾乎不痛——巡檢圖是拿來**討論**的，不是拿來**證明**的，看完就丟。
- **「換一台機器截出來的圖跟這台不可比」**反過來變成主要的理由。這個 repo 在 Linux／macOS、
  x64／arm64 之間輪替（CLAUDE.md），而巡檢圖的用途正是**隔幾天、換一台機器、再看一次同一個
  畫面**。字型解析與引擎版本會在你看不見的地方換掉行斷與頁斷，然後你會為了一個其實不存在的
  變化，去改一段本來沒問題的 CSS。

容器是這個 repo 裡唯一釘死這兩者的地方：`Dockerfile` 綁死 Playwright 版本、釘住
`fonts-noto-cjk` 的版本、用 `75-folis-cjk.conf` 綁定 generic family，並在 build 時用
`docker/verify-fonts.sh` 斷言那些綁定真的生效。[#25](https://github.com/yurenju/spine/issues/25)
就是沒有這一層時發生的事：直排日文的每個漢字都疊在一起，因為 fontconfig 把 `serif` 解析到一顆
沒有直排 advance 的字型上，而**沒有任何東西會 throw**。

host 上沒有等價的東西。ADR-0007 自己寫著：那份 provisioning 的正本在 Windows host 上，兩個
repo 裡沒有任何一行記錄它。

## 為什麼要進 CI，既然不比對像素

因為要守的是**腳本會不會腐爛**，不是畫面會不會變。

這支腳本是 27 步接續的操作：匯入四本書、開書、從目錄跳到第一章、升起 chrome、開三個 panel、
選字、劃重點、寫筆記、翻頁、換直排書、切深色主題。每一步都靠 `data-testid` 或按鈕的文字認路。
改個名字、把 drawer 換成 dialog、換一種開 panel 的方式——腳本就壞了，**而且是安靜地壞**：沒有
人在跑它，所以沒有紅燈，直到你真的需要那批圖的那一天才發現。那一天你想做的是討論 UX，不是修
一支半年沒跑過的腳本。

CI 每個 PR 跑一次，把那個延遲從「幾個月」壓到「一次 review」，而且直接指出是哪個 PR 弄壞的。
成本是掛在既有 chromium shard 上的三十幾秒。

**沒有做像素比對，是刻意的。** 那要 54 張基準圖進 repo、每次動 UI 都是二進位 diff，而這批畫面
裡有好幾個會自己動的東西（「剛剛加進來的」是時間算出來的、toast 會自己消失、chrome 是滑進來
的）。清掉那些不穩定來源的工比寫這支腳本本身還多，換到的是一批每週紅幾次、然後被所有人學會忽略
的燈。**等真的被畫面迴歸咬過一次、而且知道是哪幾張圖會咬人，再從那五到八張開始做，而不是一次
搬 54 張進去。**

## 放棄了什麼

**一、`test-in-container.sh` 那條「不掛任何可寫的東西」的規則有了例外。** 那條規則的理由是「證據
圖不該從容器出來」，而巡檢圖不是證據圖——把兩個詞分開正是為了讓這句話說得出口。做法上沒有動那支
腳本一個字，另開了 `capture-shots.sh`，所以那條規則在它自己的範圍內仍然完整。順帶一提，
`container.sh` 的檔頭寫著「如果沒有第二個 caller 出現，就把它折進 `test-in-container.sh`」——第二
個 caller 出現了，那句話的結論反過來成立。

**二、圖不是 host 上那台機器渲染的。** 你在 macOS 上跟 assistant 討論的那張圖，是 linux/amd64
容器裡的 chromium 畫的。字型與引擎跟你自己開來讀書的那個瀏覽器不一樣。**這正是要的**（見上面），
但代價是真的：巡檢圖上看到的東西，不保證在你的手機上長一樣。真機的事由
[verify.md](../agents/verify.md) 那條路守，沒有變。

**三、只有一家瀏覽器。** 巡檢圖看不到三家的歧見。這是刻意的分工——歧見由 `tests/browser/` 的
18 支 spec 在守，而它們三家都跑。

**四、「全站」由這支腳本自己定義，沒有東西在守它完不完整。** 新加一個畫面而忘了加進腳本，CI 照樣
綠燈，你照樣拿到 27 張，只是它不再是全站。這是安靜程度僅次於腐爛的一種腐爛，**目前沒有解**：
反推不出來（「深色主題的閱讀器」不是一個路由，是狀態的組合），所以只剩 review 時人眼看得見它有
沒有跟著長——這也是為什麼清單就是腳本本身，而不是另外一份 `index.md`：兩份必然漂移。

**五、已登入的〈帳號〉頁拍不到。** 巡檢不起 `wrangler dev`，所以 `/api` 與 `/auth`（Vite proxy 到
5002）是 gateway error，那格只有未登入的樣子，並且照這件事命名（`settings-account-signed-out`）。
要拍已登入版就要處理 D1 migration 與 magic code 繞道，那是另一件工程，而它會把這支腳本一起拖得
不穩——不穩正是這份決定要消滅的東西。

## 什麼時候該回來重讀這一頁

三件事，任一件發生就重讀：

- **你連續兩次因為「圖看起來變了」而白追一次**，結果是環境變的不是程式改的。那表示比對這件事
  已經有人在用眼睛做了，該讓機器接手——從最會出事的那五到八張開始。
- **腳本連續幾個 PR 都紅，而每次都只是改個名字。** 那表示它認路的方式太脆，該讓它靠更穩的東西
  認路，而不是把這個 step 關掉。
- **開始有第二個人開 PR。** 那時候「全站清單由一個人記得」會立刻變貴。
