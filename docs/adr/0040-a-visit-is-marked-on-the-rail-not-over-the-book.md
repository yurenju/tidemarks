# 回訪的線索畫在定位軸上，不畫在書上

日期：2026-08-28，同日改寫。前一版〈回訪模式在畫面上不出聲〉的決定是回訪期間畫面上一個字都不多。

## 先講現在是怎麼運作的

讀者從書架的〈回訪卡〉點一條重點，或在閱讀器的〈筆記〉面板點一條，書會跳到那條重點的位置。這時候他
原本讀到的地方不能被蓋掉，所以有〈回訪模式〉：那段期間翻頁不更新進度，讀過原本那個位置才恢復
（`packages/app/src/lib/visit.ts`、CONTEXT.md 〈回訪模式〉）。

閱讀器底部那條可以拖的軸叫 Scrubber，上面的圓點是現在這一頁在整本書的位置。

## 以前這裡有一條橫幅

回訪本來會在書上升起一條橫幅：「你讀到〈第七章〉33%」，加〈移過去〉與〈留在這裡〉兩顆按鈕。那條橫幅
是為**別台裝置同步過來的位置**做的（[ADR-0037](0037-a-position-from-elsewhere-is-offered-not-taken.md)），
回訪借用了它。它已經拿掉了：它是一條橫的卡片，橫排書只蓋掉最上面幾行，**直排書卻是每一欄都被攔腰切
斷**，一行完整的都不剩，手機上還佔掉五分之一個螢幕。

拿掉的時候就寫下了代價：畫面上不再有任何線索說「你現在不在最新進度」。補這個缺口的事留給
[#110](https://github.com/yurenju/tidemarks/issues/110)，先看看實際上有多困擾。

答案是會困擾，而且是無聲的那一種。進度在 47%，點回訪卡跳到 6%，從 6% 讀到 30% 就關掉，下次打開回到
47%。這正是回訪模式要的行為，但讀者只會覺得進度掉了，而且沒有任何一個時刻能發現自己誤會了。

## 決定

**回訪期間，Scrubber 上多一個記號**，站在被保留的那筆進度的位置，是一顆寫著 `↩ 47%` 的小膠囊。按下
去回到那一頁；到達那一頁就等於讀過了，回訪因此結束，記號跟著消失。橫幅不會因此回來：同步過來的位置
仍然是唯一會在書上升起橫幅的來源。

**這一層跟橫幅的差別不在大小，在它站的地方。** 橫幅疊在書上，所以它遮住的是字；記號站在定位軸上，
那條軸本來就在回答「我在整本書的哪裡」，而「我原本讀到哪裡」是同一個問題的另一半。直排書因此完全不
受影響：軸是橫的，字是直的，兩者不相交。

**它可以按。** #110 原本主張先只做「看得到」，把「回得去」留到下一輪，理由是可按就要處理最小點擊區
域與可及名稱。實際做下去，那兩件事各是一條 CSS 與一條詞條：手指裝置上用一個透明的 `::before` 把感應
範圍撐到 `--tap-min`（[ADR-0023](0023-width-places-things-pointer-sizes-them.md)：目標大小問的是
手指鈍不鈍），可及名稱是 `Back to 47%`，比膠囊上印的字長：記號站在哪裡，用看的一眼就知道，用聽的就
得有人把它念出來。代價比再開一張票小。

**跳的是 CFI，不是百分比。** 百分比會吸到最近的頁邊界（量到的是站在 47% 的記號跳完落在 43%），而讀者
按的是「回到我原本那一頁」。記號的位置是那筆進度的畫法，不是那筆進度本身。

## 代價

**定位軸上多了一個東西，而且它跟拖曳時的預覽泡泡站在同一條帶上。** 讓泡泡蓋住記號（`z-index`），因為
讀者把軸拖到記號附近的時候，泡泡正要說出他想要的那個百分比。反過來的話，記號會擋住讀者正在瞄的東西。

**記號的寬度是猜的。** 膠囊靠 transform 置中，而 CSS 問不到文字排出來多寬，所以 `--visit-mark-half`
是一個手寫的常數，用來把它從軸的兩端夾回畫面內（不夾的話 `overflow-x: clip` 會裁掉一半）。字級變大
到某個程度它會不準，沒有任何測試會紅。

## 考慮過但沒有選的

- **只畫記號、不能按**（#110 原本的主張）。看得到卻回不去，剩下的路是退回書架再開一次那本書，三步，
  而且沒有人會知道有這條路。
- **把記號塞進軸下方那一列**（現在印章節名的那行）。不會蓋到書，但章節名置中、記號在 47%，兩個會撞。
- **連別台裝置同步過來的位置也在軸上標一顆。** 那個來源是一個要回答的提議（去那邊、或留在這裡），橫
  幅正在講，多一個記號不會讓讀者更知道要按什麼。
