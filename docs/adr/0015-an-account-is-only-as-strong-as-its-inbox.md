# 帳號的強度等於信箱的強度

日期：2026-08-09。

## 決定

登入從 **passkey-only** 換成**兩把平行的鑰匙**：

- **passkey**——快，一鍵，走 discoverable credential，連 email 都不必輸入。
- **email + magic code**——六位數字寄到信箱，10 分鐘有效，五次試錯就作廢。

兩把都是正門，沒有主從。新帳號一律先用 magic code 進來，有了 session 之後才加得了 passkey
（這正是 `worker/auth.ts` 現在的形狀，換掉的只是新使用者那個入口）。

**recovery code 拿掉。** `SIGNUP_CODE` 那個共用註冊碼也拿掉，換成〈開放註冊〉的閘門（見
[CONTEXT.md](../../CONTEXT.md)）。

email 是帳號的**唯一識別**：一個 email 一個帳號。

## 換到什麼、付掉什麼

| 換到 | 付掉 |
| --- | --- |
| 帳號找得回來——弄丟所有 passkey 不再等於筆記沒了 | **抗釣魚保護**。passkey 的核心價值之一是釣魚站拿不到憑證；magic code 拿得到，因為受害者會自己把碼貼過去 |
| [ADR-0011](0011-the-paywall-follows-the-monthly-bill.md) 承諾的「到期前寄信通知才清」第一次寄得出去（[#88](https://github.com/yurenju/spine/issues/88)） | 第一個外部廠商（Resend） |
| 開發階段「資料丟掉之前先通知」也第一次做得到，白名單那批人才有東西可以依靠 | 多一個會壞的地方：Resend 掛掉就沒有人登得進來（緩衝是 session 有 90 天） |

所以這份 ADR 的標題就是那個代價：**帳號的實際強度是信箱的強度**，不是 passkey 的強度。
這件事要說出口，因為它推翻了意圖核心當初選 passkey-only 換到的一半東西。

補償只有一件，而且很便宜：**magic code 登入成功之後寄一封通知信**。它擋不住任何人，但讓被
入侵的人在幾分鐘內知道。同一封信也是「不綁瀏覽器」那個決定的補償——碼可以在手機上讀、在
電腦上輸入，代價是社交工程（「我是客服，請把六位數唸給我」）成立，所以信裡要寫死一句
**spine 不會有任何人跟你要這串碼**。

## 為什麼不是「passkey 為主、magic code 只在救援時開」

那個安全是假的。只要 magic code 在**任何**情況下能讓人進來，攻擊者就走那條路，而「要先按
一下『我的 passkey 用不了』」是攻擊者按得下去的按鈕。真的要擋就得做冷卻期、移除 passkey 要
等七天那一類東西——一個人維護扛不起，而且做半套等於沒做。

誠實的做法是承認強度的天花板在信箱，把它寫在這裡，然後不要假裝它比較高。

## recovery code 為什麼不留

它今天扛三件事，magic code 三件都承接得了：

| recovery code 扛的 | 誰接手 |
| --- | --- |
| passkey 全丟時的救援 | magic code，而且不用事先存好十組碼 |
| 換 hostname 時搬家（RP ID 一註冊就永久釘死，見 [ADR-0004](0004-development-phase-and-launch-line.md) 末節） | magic code 一樣跟 RP ID 無關 |
| 收尾驗證的自動登入繞道（`scripts/seed-preview-auth.sh`） | 往 D1 塞一列 magic code，比現在**更貼近真實路徑** |

留著它換不到新能力，卻要付三筆：帳號的強度等於**最弱那條入口**，多一條就多一個攻擊面；多
一套要測的不變式（[#27](https://github.com/yurenju/spine/issues/27)）；以及它本質上是一個
賭注——使用者按了「我已存好」的勾選，實際上沒存，而發現的那天正是最糟的一天。

（[#86](https://github.com/yurenju/spine/issues/86) 因此只剩一半：passkey 同時有效數設上限
那條照舊，「recovery code 一次只發一組」那條隨著它一起消失。）

## 意圖核心那條分法要修訂

[意圖核心](../intent/2026-07-15-spine-cross-device-reading.md)寫著「不要引入第二個廠商或第二個
部署環境」。寄信一定要一個，所以那條要動——但**改措辭，不是推翻**：

它當初擋掉的是 Supabase，理由寫得很清楚，是「多一個廠商就多一套部署與 secret」。Resend 不是
那個東西：沒有第二套 schema、沒有第二個要部署的地方，只有一個 `fetch`、一組 key、幾筆 DNS。
所以規則收斂成**不要引入第二個部署環境**，純 API 的服務不在此限。

## 沒設供應商的時候，magic code 寫進 log

自架的人要能零廠商跑起來——[ADR-0009](0009-open-source-buys-an-exit-not-contributions.md) 的
〈退路〉是開源要買的東西本身，而 [#70](https://github.com/yurenju/spine/issues/70) 承諾過「一個
外人架得起來，而且不需要自訂網域」。magic code 成為唯一入口之後，寄信需要一個驗證過的網域，
那句承諾就會破。

所以沒設 Resend 的時候，碼不寄信，直接寫進 log（`wrangler tail` 看得到）。**同一套流程、同一
組 schema，只換掉「怎麼送到人手上」那一步。**

承諾因此收斂成一句誠實的話：**自架給自己用不需要廠商；要給別人用就要一個。**

這條在日常也一直用得到，而且那才是它主要的用途：**沒有收信環境也能手動測登入**，本機
`wrangler dev` 與收尾驗證都不必接真的寄信。

風險是這個模式誤開在公開部署上，登入碼會躺在 log 裡。擋它的是〈開放註冊〉的白名單，以及看得到
log 的人本來就讀得到 D1。

## 這不改上線那條線

[ADR-0004](0004-development-phase-and-launch-line.md) 的線**不掛在入口的種類上**，掛在
〈開放註冊〉。email + magic code 在白名單期間就已經是註冊的唯一入口了，翻面的是閘門，不是入口。

但 ADR-0004〈原本的事件為什麼作廢〉那節有兩句話因為這份 ADR 而作廢：「passkey-only 是對的產品
決定，沒有理由拿掉」、「收費走 Stripe，email 是 Stripe 收的，spine 手上一個都不會有」。那節已
更新。**換線的理由本身沒有被推翻**——線要抓的是「資料開始屬於別人了」，不是某個實作機制，
所以線不改回去。

## 走不回頭的地方

- **email 一旦是唯一識別，回不去 passkey-only。** 那等於要求每一個人回來重做一次。
- 意圖核心自己寫過這題的時效性：「事後補 email 復原對已存在的帳號補不上，只能請所有人回來重填。
  自己一個人的時候改很便宜，有 50 個使用者的時候就不便宜了。」它同時指定了回來看的時間：
  **決定要開放給第一個非自己的使用者之前**。這份 ADR 就是在那一刻、而且帳號數還是 1 的時候寫的。
