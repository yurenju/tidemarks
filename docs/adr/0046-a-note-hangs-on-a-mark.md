# 一則筆記掛在一段重點上

日期：2026-08-31。

## 先講現在是怎麼運作的

讀者在書上選一段話、點一個顏色，畫面上就沿著字邊出現一條波浪線，那段話存成資料庫裡的一列
（`Annotation`）。那一列上有一個 `note` 欄位，想寫點什麼就寫在那裡。所以今天讀者能留下的字
只有一種：**掛在某本書某一段話上的那一則**。想記一件跟書無關的事，這個 app 沒有地方放。

詞彙表的〈筆記 / Note〉本來寫的是另一件事。它說筆記是一種思考方式而不是一個功能，打的、講的、
紙筆寫的都算，不綁一本書也不綁一段選取；然後它自己標了一句 ⚠️，說今天的實作跟這個定位對不上，
「這個落差怎麼收還沒決定」。那句話掛在那裡，每一張碰到筆記的票都要重新猜一次答案。

## 決定

**那不是落差，那是範圍。**

> **一則筆記掛在一段〈重點〉上。** 沒有重點就沒有筆記，`bookId` 與 `cfiRange` 不會變成選填。

Tidemarks 是一個劃重點、寫筆記的工具，不打算變成通用的筆記系統。〈筆記 / Note〉詞條跟著改窄，
原本那句「落差怎麼收還沒決定」刪掉。

## 為什麼要縮

**縮起來容易，撐開來很貴。** 現在把範圍收窄，改的只有一行詞條；之後真的要做獨立筆記，要動的是
IndexedDB 與 D1 兩邊的 schema、同步的合併規則、MCP 的回應形狀。既然兩個方向的成本差這麼多，那
就先選代價小的那一邊，等真的有理由再付那筆錢。

**而且「什麼都能記」不是這個 app 的賣點。** 讀者的桌上已經有一個通用筆記系統了，可能是
Obsidian、Notion，或一本實體筆記本。Tidemarks 要做好的是它們做不到的那半：把書裡的句子撈出來、
反覆送回眼前。做成第二個通用筆記系統，等於放掉自己唯一的長處，去跟那些工具比它們最擅長的事。

**讀者要帶走這些字，路已經有了。** 〈退路 / Exit〉那條說「匯出的格式別人也讀得懂」
（[ADR-0013](0013-your-copy-is-yours.md)），所以「我想把這些筆記整合進我自己的系統」這件事有家，
不需要靠「在 app 裡也能寫獨立筆記」來解。

## 放棄了什麼

放棄的是**那些不想再開第二個 app 的讀者**。他們在讀書的時候想到一件跟這一頁無關的事，現在得切
出去記。這是真的損失，不是假設的。

換到的是專注：資料只有一種形狀，所以同步、合併、匯出、MCP 每一層都少一組分支；畫面上也不會出現
「這則筆記屬於哪裡」這個讀者答不出來的問題。

## 什麼時候該回來重讀這一頁

- **讀者反覆要求記跟書無關的事**，而且不是零星幾個人。那時候要重新算一次上面那筆帳。
- **來源不只 EPUB 之後**（見〈來源 / Source〉）。文章與影片放進來的時候，「一段選取」在那些載體
  上是什麼要重新定義，這條規則的形狀可能得跟著調，但「筆記依附在某個東西上」這件事不變。
