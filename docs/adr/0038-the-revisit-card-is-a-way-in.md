# 回訪卡是一個入口，不是回訪發生的地方

日期：2026-08-26，2026-08-29 改寫。前一版〈回訪卡記得自己端出過什麼〉是一天五則，照 `lastShownAt`
排序取前 15 條當池子再隨機抽五張。

## 決定

書架第一屏那張卡改成：**一天一則畫線，隨機挑，當天固定**。卡上只有一段引文、讀者自己的筆記、書名，
以及一顆換一則。按引文回到書裡那一段；想寫東西，在書裡寫。

| | 以前 | 現在 |
| --- | --- | --- |
| 一次幾則 | 五則，可以翻閱 | 一則 |
| 怎麼挑 | `lastShownAt` 排序取前 15 當池子，池子裡隨機抽 5 | 全部畫線裡隨機抽 1 |
| 能不能在卡上寫 | 可以，有輸入框 | 不行，寫字在書裡 |
| 高度 | 桌機 507px／手機 607px | 約 150px |

「當天固定」留著沒動，它是這張卡唯一不能少的性質：讀者說不出一段話為什麼打中他，而每次回書架都換一
則的卡片，永遠不會給他想清楚的機會。

## 這張卡要守的是什麼

先說清楚，因為底下每一條都是從這裡推出來的。

畫線平常只活在閱讀器的〈筆記〉面板裡，而那個面板一次只講一本書。所以這張卡最初的用途是「讓畫過的句
子再出現」。但它真正要守的事情更具體：**讓一條畫線在讀者還說不出它為什麼重要的那段期間活著，並且反
覆回到眼前。**

那段期間可長可短。資訊書可能當天就能把想法寫成自己的話；文學可能要好幾個月，喜歡一個段落，一開始講
不出為什麼，看過幾次之後才慢慢說得出來。兩者走的是同一條路，差別只有週期長度。

⚠️ **搜尋在這條路的前段幫不上忙**，因為讀者不知道要搜什麼。一條還說不出為什麼喜歡的句子，連它跟什麼
有關都還不知道。搜尋、標籤、雙向連結全部預設「先知道自己在找什麼」，那是後段。市面上的筆記工具幾乎
都做後段，前段沒什麼人做，因為它看起來太簡單。

## 「五」答不出來

實際用了幾天之後，五則帶來的問題是它自己解釋不了自己：**為什麼是五？為什麼不能翻更多？** 畫面上沒有
任何東西回答得了這兩句，而它換來的是 ‹ ›、五個刻度、`1 / 5`、還有一顆「再挑五張」，四組控制，全部
用來管理一個讀者沒有要求過的數字。

前一版把五則和「排序＋池子」綁成一套，說少任何一件都不成立。那是對的：**五則一起端出來，就必須
保證這五則不會每天都是同一組**，所以要隨機；而隨機又會忘記誰出現過，所以要排序。一次只端一則的時候
這條道理就接不下去了，沒有「一組」可以被綁在一起。

## ⚠️ 全隨機有一個代價，選它的時候是知道的

以前量過（每天五張、跑一年、40 個隨機種子取平均），「整年一次都沒被抽中」的畫線條數：

| 收藏規模 | 池子 15 | 純隨機 |
| --- | --- | --- |
| 200 條 | 0 | 0 |
| 600 條 | 0 | **26 條** |
| 約 960 條 | 5 | **324 條** |

**這份量測沒有作廢，它是對的。** 純隨機不記得誰出現過，所以剛看過的那條明天被抽中的機率，跟兩年沒
出現的那條一模一樣；收藏越大，被冷落的那批越大。而且**畫面上沒有任何東西會說**有一批畫線從來沒被抽
到過，這種壞法不會有人回報。

還是選了它，理由是：那些數字是在**一天五張**的前提下量的，一天一張的曝光量只有五分之一，所以真正卡住的
是除法（600 條、一天一張 = 兩年才輪一遍），而那個換哪一種挑法都跑不掉。既然兩邊在小收藏
上沒有差別、在大收藏上都不夠，就先留最簡單的那一個，實際用過再說。

**什麼時候要換回去**：收藏長到幾百條，而且讀者開始覺得「怎麼老是那幾句」。那時候要做的事是把
`lastShownAt` 的排序接回來，並且**照一天一張重跑一次那份模擬**。上面的表格答的是一天五張的問題，
不能直接拿來用。

所以 `lastShownAt` **繼續寫，只是不再讀**（`revisit-store.ts`）。它是那個排序唯一需要的東西，而一個
停止寫入的欄位，等到要用的時候，中間那段時間是空的。

**被挑出來就等於被看到**，所以寫的時機不再是一個選擇（`Library.tsx` 那個以「現在是哪一則」為 key 的
effect）。一次五則的時候這是要想的：五則一起記成看過，讀者只看了第一則就關掉，另外四則會被埋掉一整
輪。一次一則的時候沒有「另外四則」。

## `lastShownAt` 同步，但它逼出一個合併特例

**`lastShownAt` 跟著畫線同步**，因為「我看過這句了」是**讀者**的事實，不是他當時拿著哪台機器的事實，
跟〈別處的位置〉刻意含糊的理由同一個。代價是一支 D1 migration 加上一天幾筆寫入，對一個已經在同步整
本書的系統來說不算什麼。

⚠️ **這件事需要合併規則開一個特例，不然這個欄位會把筆記吃掉。** 畫線本來是整列 LWW（照 `updatedAt`
挑贏家），所以如果「看過卡片」寫進同一列，A 機看了卡片、B 機改了筆記，合併只會留下一整列，另一邊的
改動就沒了。拆成兩件：

- **看卡片不動 `updatedAt`**，只寫 `lastShownAt` 與 `dirtyAt`。「我看過」不該贏過「我寫了字」
- **`lastShownAt` 用 `max()` 各自合併**，不跟著整列的贏家走。看過是單調的，兩邊取晚的那個永遠對

這個特例有個連帶影響值得記著：`mergeAnnotation` 因此可能回傳**兩個參數都不是**的第三個物件，所以
push 與 pull 兩邊本來用 identity（`merged === incoming`）判斷輸贏的地方都要改，那兩處各留了註解。

**「今天是哪一則」不同步**，住在不同步的 `meta` 表裡。要讓兩台看到同一則，得把它也搬上伺服器，換到
的只有「同一天在兩台上看到同一句話」，那不值得一張新的表加一套合併規則。兩台記得的是同一份「看過什
麼」，只是各自抽各自的。

## 為什麼在卡上寫字這件事收掉

以前那張卡上有一個輸入框，理由是「句子是拿來重新遇到的，而遇到的當下升起來的念頭要能立刻接住」。
那個理由還是對的，但接住它的地方不必是這張卡：按下引文就會進到書裡那一段，而閱讀器的〈筆記〉面板本來
就能編輯。**多的是一次點擊，省下的是書架第一屏上一整個寫字的區塊。**

留一個輸入框在書架上還有一個代價比較不明顯：那個框在畫面上就是一張欠填的表。這張卡花了很多力氣不讓
自己變成待辦清單（沒有未讀數、沒有關閉、不能清空），而一個空的輸入框把那件事又做回來了一半。

## 為什麼換一則不是「下一則」

畫面上沒有任何東西說這些畫線有順序，所以「下一則」是一個讀者驗證不了的承諾。**它是一疊東西伸手撈一
張**，跟以前那個抽籤是同一個動作，只是一次撈一張。

唯一的保證是**不會撈到剛剛那一張**（`pickOne`）。例外是整個書架只有一條畫線的時候，那就再給同一條：
按了之後拿到一張空卡，比拿到同一句話更糟。

它也**不是關閉、不是清空、沒有未讀數**，這一條原封不動接過來，理由沒有變：任何可以
被清空的東西都會變成一件欠著的事，而一個在某個畫面上欠著事的讀者，會開始避開那個畫面。按它是讀者在
要；不按它不花任何代價，也不會留下任何東西。

## 版面上剩下的三件事

**書名不再是那一屏最顯眼的書名。** 以前有一條硬規則：出處的視覺重量必須壓過〈正在讀〉的
書名，否則讀者會把引文當成下面那本書的筆記。那條規則是在「兩個大塊上下緊貼」的情況下寫的；現在上面
是一條窄卡，而且第一列明白寫著〈來自你劃的重點〉加書名，誤讀的機制不在了。

**引文與筆記各自守 `LINE_LENGTH`**（[ADR-0012](0012-line-length-has-a-ceiling-measured-in-ems.md)），
各用自己的字級去算，所以筆記比引文窄，縮在引文裡面。上限讓出來的空間放封面，卡片的框跟著內容收（`fit-content`）。
這也是為什麼 `device.css` 不再需要為這張卡重述任何東西，那裡本來有 216 行在把上限以外的空間做成側欄。

**第一列擠不下的時候丟東西，依據是量出來的**，不是斷點：同一個寬度，短書名放得下標籤、長書名放不下。
順序是標籤、時間，書名與換一則永遠留著。丟不是換行，換行的一列就是兩列，高度又長回去了。
