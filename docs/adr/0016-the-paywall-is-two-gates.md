# 付費牆是兩道門，不是一道

日期：2026-08-11。

## 決定

[ADR-0011](0011-the-paywall-follows-the-monthly-bill.md) 決定了收費的**界線**（哪些功能會長出
每個月的帳單）。這一份決定那條界線**擋在程式的哪裡**。

兩道門，位置與問題都不同：

| | 什麼時候問 | 問什麼 |
| --- | --- | --- |
| 入口 | 建帳號那一次 | 這筆付款成功了嗎 |
| 日常 | 每一次請求 | 這個帳號的〈訂閱〉還開著嗎 |

〈上線〉之後**沒付款就沒有帳號**，所以入口那道很硬：免費的那一級根本不需要帳號（不註冊就完整可
用），註冊唯一的意義就是買同步與 MCP。

## 為什麼入口那道不夠

因為 ADR-0011 承諾了「**停止付費之後不刪東西**」：帳號留著、資料留著、同步與 MCP 停掉、保留 24
個月。那條承諾直接要求「有帳號、訂閱停掉、資料還在」是一個**活得下去的狀態**。

只有入口那道門的話，這個狀態表達不出來——有帳號就等於付過錢，而付過錢跟現在還在付錢是兩件事。所
以第二道門不是保險，是那句承諾的實作。

反過來說，只有第二道門也不行：那會讓「免費建帳號」變成可能，而 spine 沒有免費帳號這種東西
（〈上線〉：註冊那一刻就是資料開始屬於別人的那一刻）。

## 第二道門要寫兩次，因為 `/mcp` 走的不是同一條路

`worker/index.ts` 分成兩半，而它們的入口不同：

- `spineApp` 的 `/api/*`，守門是 session cookie。
- `/mcp`，守門是 OAuth access token。它**只有 `OAuthProvider` 叫得到**，`ctx.props` 帶著 userId
  進來，中間不經過 `spineApp` 的任何一行。

所以「每一次請求看訂閱」在這兩個地方各要實作一次。這正是那個檔案檔頭那句話的反面：把 `/mcp` 藏在
`OAuthProvider` 後面買到的是「沒有 token 就到不了」，它買不到「沒有訂閱就到不了」。

## 訂閱過期時不撤銷已發出的 token

第二道門在 `/mcp` 那邊有一個看起來更省事的做法：訂閱一過期就把 access token 全部撤銷。不採用。

撤銷之後使用者續費，得回到 Claude 或別的 agent 重跑一次 OAuth 授權，而那件事他上一次做的時候大概
花了五分鐘找設定在哪。token 留著、每次請求檢查的話，續費當下就自動恢復，什麼都不用做。

代價是每個 MCP 請求多一次 D1 查詢，而那份鏡像本來就要查。

回給 agent 的錯誤要**講人話**（「這個帳號的訂閱已經停用」），**不要回 401**：401 會讓 agent 去重
跑授權流程，然後拿到一個一樣不能用的新 token，使用者看到的是無窮迴圈而不是一句「去續費」。

## 白名單那批人維持免費

〈開放註冊〉之前建的帳號不受入口那道門管，也不受第二道門管，而且不設期限。

人數是個位數，ADR-0011 量到的邊際成本是每人每年 US$0.05，總額低到不值得寫一行判斷。更重要的是他們
是**明知資料會被清掉才進來的**那批人（〈上線〉），拿那份信任換一年的訂閱費划不來。

## 還沒決定的事

**金流商未定**（Paddle 或 Stripe）。這份 ADR 的兩道門在兩家上是同一個形狀：它們自己的結帳頁、一個
要驗簽章的 webhook、D1 那份鏡像。所以簽章驗證與事件名稱對應關在一個檔案裡，D1 的欄位叫
`provider_customer_id` 而不是 `stripe_customer_id`，其餘可以先做完。

「為什麼是 MoR 不是 PSP」值得單獨一份 ADR，等那個決定。
