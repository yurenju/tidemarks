# 三家瀏覽器是 CI 的事，不是本地迴圈的事

日期：2026-08-28。

## 先講現在是怎麼運作的

這個 repo 有三個地方會開瀏覽器，它們共用「跑瀏覽器」這幾個字，但是三件不同的事：

|  | 是什麼 | 在哪 |
| --- | --- | --- |
| **測試** | 紅綠燈。真的開一本真的書，斷言數字與元素 | `packages/*/tests/browser/`，容器裡 |
| **證據圖** | 為了**某一次改動**拍的截圖，貼進 PR，附五項缺陷判讀 | host 上的 playwright-cli（[ADR-0007](0007-pr-evidence-is-captured-on-the-host.md)） |
| **巡檢圖** | 不管改了什麼都拍的全站截圖 | 容器裡，chromium 一家（[ADR-0027](0027-the-screen-sweep-runs-in-the-container.md)） |

前兩件到今天為止都是 **chromium、firefox、webkit 三家同級，任一紅燈即紅燈**
（frond [ADR-0004](../../packages/frond/docs/adr/0004-browser-matrix-and-test-environment.md)）。
第三件本來就只有一家。

那條「三家同級」訂下來的時候，frond 才剛開始寫，而 frond 存在的一半理由就是「別人沒把直排跨瀏覽器
做好」——所以三家不是保險，是產品本身。

## 決定

**測試那一層一家都不減，但只有 CI 跑滿三家；本地預設 chromium 一家。**

**證據圖預設 chromium 一家**，只有一個例外：**這次改動碰到 `packages/frond/src/renderer/` 或直排
相關的東西，就三家都拍。**

|  | 之前 | 之後 |
| --- | --- | --- |
| CI 的 `browser` job | 三家 × 兩 shard | **不變** |
| 兩份 `playwright.config.ts` 的 `projects` | 三家 | **不變**（CI 靠它們） |
| 本地 `test-in-container.sh` 不帶參數 | 三家 | **chromium** |
| commit 前與開 PR 前的那一趟 | 三家，6m46s | **chromium**，約兩分半 |
| 證據圖 | 三家 | **chromium**，動到渲染層才三家 |
| 巡檢圖 | chromium | 不變 |

本地要三家的時候沒有新的旗標，把引擎點名就好：

```bash
./scripts/test-in-container.sh --project=chromium --project=firefox --project=webkit
```

## 為什麼是現在

因為**改的東西換了一種**。前一段時間的工作大多是修 epub 的排版，那正是三家最會分岔的地方，所以每
一趟都值得看三次。現在的工作大多在 app 這一層——書櫃、面板、設定、同步——那些是 DOM 與狀態，三家
給出的答案幾乎一定相同。

**這是一個關於工作內容的判斷，不是關於瀏覽器的發現。** 值得說清楚，因為 frond ADR-0004 前兩次被
縮小都是量測的結果（`#4` 發現三家對 generic family 的解析在送進 fontconfig 之前就分歧，`#7` 發現
直排下三家的分欄斷頁本來就不一致），而**這一次它沒有被縮小**：測試那一層仍然三家同級、任一紅燈即
紅燈，CI 每個 PR 都在證明這件事。變的只是**哪一趟由誰跑**。

## 為什麼 CI 一格都不動

因為它不花你的時間。這個 repo 是 public，GitHub 的標準 runner 免費且不限量，六個 job 是平行的，
所以三家的成本是**牆上的時鐘不變、機器多用幾台**。真正稀缺的是你在等本地那一趟的時候——本地全套
6m46s，而其中有三分之二在跑兩個幾乎不會紅的引擎。

反過來說，這也是為什麼配置檔一個字都沒改：三家同級這條宣告仍然是真的，只是實現它的地方從「每個人
每次」變成「每個 PR 一次」。腳本裡那個預設還特地押在 `CI` 沒有設定的時候才生效，方向是安全的那一
邊——哪天有人加了一個忘記點名引擎的 CI job，它會跑滿三家而慢，不會跑一家然後綠得像跑了三家。

## 放棄了什麼

**一、firefox 與 webkit 上的視覺缺陷，現在沒有任何一層守著。** 這是最要緊的一項。五項缺陷清單
（溢出／重疊／書寫方向／空白頁／裁切）要**有人看畫面**才看得出來，而 CI 斷言的是數字與元素——一段
文字溢出容器、兩個東西疊在一起，測試可以全綠。以前補這一格的正是三家證據圖，現在那一格只剩
chromium。巡檢圖也補不到：它同樣只有 chromium，而且沒有人在比對它（ADR-0027）。

**這不是可以靠 CI 加點東西補回來的。** 補回來要的是像素比對，而 ADR-0027 已經算過那筆帳並且刻意
沒做。所以就是一個真的空格，寫在這裡是為了讓下一個人知道它是空的。

**二、只有 firefox 或 webkit 會紅的失敗，延後到 CI 才發現。** 這件事有實績：`test-in-container.sh`
檔頭那組數字是一趟全套量出來的，而那一趟同時抓到兩個 chromium 跑不出來的 Firefox 失敗。之後那類
失敗會表現成 CI 紅一次、多推一輪，大約八分鐘。跟省下來的每一趟四分鐘比，划不划算取決於它多久發生
一次——現階段的答案是很少，而那正是這份決定的全部理由。

**三、三家歧見的第一手觀察不見了。** 以前每一次跑全套都在順便回答「這三家今天還一致嗎」，那是
frond ADR-0004 說的「很有價值的第一個產出」。現在那個問題只有 CI 在答，而 CI 只會說紅或綠，不會
說「這三家的畫面長得不一樣」。

## 什麼時候該回來重讀這一頁

- **開始又在改渲染層。** 上面那個例外只管證據圖；如果 `packages/frond/src/renderer/` 連續幾個 PR
  都在動，那本地測試的預設也該跟著回到三家——這一頁的前提就不成立了。
- **CI 連續紅在 firefox 或 webkit。** 那表示「三家幾乎一定相同」這個假設在目前的工作內容下不成立，
  而每次多付的是一輪 push。
- **上線之後。** 開放註冊那一刻起，畫面壞掉的第一個發現者會是讀者而不是你（
  [ADR-0004](0004-development-phase-and-launch-line.md) 的那條線）。第一項「沒有人看 firefox 與
  webkit 的畫面」在那之後是完全不同的一件事。
