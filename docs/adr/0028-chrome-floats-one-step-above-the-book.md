# chrome 浮在書頁上面一階

日期：2026-08-19。

## 決定

chrome 的三條 bar（`.chrome-top`、`.chrome-nav`、`.chrome-bottom`）的底色從 `--surface-page`
改成 **`--surface-raised`**，比書頁浮一階。三條一起，兩個主題一起，桌機手機一起。

**不加陰影。** ADR-0022 的規則不動：黏在螢幕上的東西不投影，能被拿起來的才投影。這裡換的是面，
不是高度的第二種說法。

**分界的髮線留著。** 深色主題那一階只有 1.08:1，戶外強光或低亮度螢幕下會糊掉，那時候線是唯一
撐住的東西。

## 為什麼原本是同色，而那為什麼不夠

原本三條 bar 吃的是 `--surface-page`——跟書頁**同一個 token**，不是相近，是同一個值。兩層之間
只剩 1px 的 `--line-hair`。

那個選擇本身有道理，而且道理就是 [ADR-0020](0020-the-interface-steps-behind-the-book.md)：介面
要退到書後面去，所以它盡量不宣告自己存在。同色是那句話最徹底的做法。

不夠的地方在於，ADR-0020 同時規定 chrome 是**蓋在**書上的，不是把書擠小——「蓋上去的東西會
重新分頁，而問『我在哪』不該把讀者移動」。既然是蓋上去的，讀者就需要看得出哪一層在上面：
〈找〉狀態下畫面上有兩個平面，而它們長得一模一樣。1px 的髮線要同時承擔「這裡是分界」與「上面
那層是另一個東西」，第二件事它扛不動。

## 為什麼是浮，不是沉

紙的語彙裡，蓋在上面的東西該是浮的。沉下去會暗示「書站在 chrome 上面」，也就是 bar 佔掉了自己
的版面——那正是 ADR-0020 明確拒絕的排法。方向要跟那支 ADR 說的同一件事。

## 為什麼是 `--surface-raised`，不是 `--surface-cover`

兩個都在 [ADR-0022](0022-the-interface-is-a-print-shop.md) 的紙階梯上，差別是走多遠：

| | 淺色 | 深色 | 對書頁的對比 |
| --- | --- | --- | --- |
| `--surface-raised` | `#f0efe6` | `#211f1a` | 1.08 : 1（兩色相同） |
| `--surface-cover` | `#ece7dc` | `#2a2721` | 1.15 / 1.19 : 1 |
| （參考）現在的髮線 | `#e4dfd2` | `#2f2c26` | 1.09 / 1.19 : 1 |

`raised` 那一步的對比剛好等於現在那條髮線，差別是它攤在整條 bar 上——同樣強度的訊號，面積大
兩個數量級。這是能說完「這是另一層」的最小一步，而 chrome 是隨手叫、隨手收的東西，最小的那步
就是對的那步。

`cover` 被否決有一個具體的代價：`button.ghost:hover` 用的正是 `--surface-cover`，而 ghost
button 就是這三條 bar 裡的每一個入口。選 `cover` 會讓 hover 直接消失，而且 `index.css` 已經
寫明 cover 是「一條 bar 能走到最深、還讀得出跟周圍是同一張紙的那一階」——用掉上限，hover 就
沒有下一階可退。要走到 `cover` 得先替 hover 找到新的一階，那是一筆獨立的帳。

## 代價

- **`--surface-raised` 從此有兩個用途**：`button:hover` 的底，以及 chrome 的面。兩者不會同時
  出現在同一塊區域（bar 裡的入口是 ghost，hover 走 `--surface-cover`），但這個 token 從「一個
  狀態」變成「一個狀態加一個材質」，之後改它要看兩處。
- **書頁與 bar 的分界從此有兩個說法**（面與線），拿掉線是一個可以之後再做的減法。先加面、看
  真機、不夠再減線——反過來做的話就沒有東西守著低亮度那個情境。
- 這條線最難逆轉的部分不是 CSS，是**讀者對「哪裡是書」的直覺**。同色時整個螢幕都是書；換色
  之後書的邊界變得具體，而書的可用高度一格都沒有變。
