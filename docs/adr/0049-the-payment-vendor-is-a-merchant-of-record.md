# 金流商是 MoR，不是 PSP

日期：2026-09-02

## 兩種金流商差在哪

收錢的服務有兩種。**PSP**（payment service provider，Stripe 是代表）只負責把卡刷過去，
賣東西的人是你：買家的合約對象是你，發票是你開的，稅是你申報的。**MoR**（merchant of
record，Paddle 是代表）反過來，它才是賣方：買家跟 Paddle 簽約、Paddle 開發票、Paddle
在各國申報稅，你收到的是它扣掉手續費之後的匯款。

差別不在技術，兩邊要接的東西幾乎一樣：一個結帳流程、一個要驗簽章的 webhook、自己這邊記
一份「這個帳號現在算不算有訂閱」。差別在**誰扛稅務與發票**。

## 決定

**用 Paddle，也就是走 MoR 這條路。**

理由只有一個，但它是決定性的：**這個專案只有一個人維護**。走 PSP 的話，賣數位商品給歐盟
要處理 VAT MOSS、賣給不同州要處理 sales tax、發票格式各國各有規定，而且這些事**不會做完**，
它們是每年重來一次的行政工作。那些時間本來可以拿去寫閱讀器。

MoR 把整包接走。代價寫在下面，都是真的代價。

## 代價一：手續費高

MoR 抽得比 PSP 多，因為它多做了稅務與發票。以 US$20 的年費來說差額是每筆幾十美分等級的事。
接受它，是因為省下來的不是那幾十美分，是每年好幾天的行政工作。

## 代價二：結帳頁不完全是自己的

Paddle 的結帳視窗由 Paddle.js 開，而 **Paddle.js 一定要載在我們自己網域的一頁上**。它叫
default payment link：Worker 建好交易之後拿到的網址，是「那一頁加上 `?_ptxn=交易 id`」，
Paddle.js 讀到那個參數才把視窗打開。完全由 Paddle 代管、不必載 Paddle.js 的結帳頁，正式帳號
只開放給核准過的手機 app 公司，我們用不到。

所以 Paddle.js 躲不掉。做法是**只讓它出現在一頁獨立的頁面上**（`GET /billing/pay`，由 Worker
直接吐 HTML），PWA 本體照舊不載任何第三方 script。

⚠️ **但那不是一道安全邊界，寫清楚免得日後誤讀。** 瀏覽器的邊界是**來源**（origin），不是頁面。
`/billing/pay` 跟 app 同一個來源，所以 Paddle.js 在那一頁上拿得到整個 IndexedDB（讀者的書與
筆記），也能用讀者的 session 打 API。要真的隔離只有換一個來源，例如 `billing.tidemarks.io`，
而那條路對沒有自訂網域的部署走不通（`CF_ROUTE` 不填的話 Worker 跑在 `workers.dev` 上，
加不了子網域）。所以同源這條必須留著；加子網域是多一種模式，不是換掉一種。之後要補代價很小
（那一頁沒有狀態，Paddle 後台改個設定就好），所以現在不做。

## 三個取捨，都是因為真相在 Paddle 那邊

D1 存的是鏡像，webhook 負責更新（CONTEXT.md〈訂閱〉）。「真相在別人家」這件事直接推出三個做法。

### 看 status，不看事件名

Paddle 對同一筆訂閱會送出好幾種事件，而且**不保證順序**。所以程式訂閱所有 `subscription.*`
事件，但只讀裡面的 `status`：`active` 與 `trialing` 給無上限，`canceled` 與 `paused` 縮回三本，
其他一律不動。

status 講的是「現在是什麼狀態」，事件名講的是「那一刻發生了什麼」。亂序之下只有前者還算數。
順帶把重送也解掉了：同一個事件收兩次，算出來是同一個答案。

### `past_due` 不動

卡刷失敗的時候 Paddle 不會馬上取消，它在三十天內重試七次，全部失敗才轉成 `canceled`。所以
`past_due` 期間什麼都不做，等 Paddle 給出最終答案。第一次刷失敗就把書收走，處罰到的是一張過期
的卡，不是一個不想付錢的人，而這跟 ADR-0011 的信任方向是同一件事。

### 亂序用 `occurred_at` 擋

`users` 多一欄 `billing_event_at`，記著這個帳號套用過的最新事件是什麼時候發生的。比它舊的事件
回 200 丟掉。回 200 而不是 4xx，因為那不是錯誤，而 4xx 會讓 Paddle 重試一個月。

**4xx 只留給簽章錯的請求**，那才是「這不是 Paddle 打來的」。對不到帳號、狀態看不懂、事件太舊，
三種都回 200 加一行 log：它們都是正常會發生的事（共用的 Paddle 帳號、重試超車、資料庫被重置過），
而它們沒有一種是重試能解決的。

## 價格：一年 US$20，只有一級

只有一個價、只有年繳。理由同樣是一個人維護：每多一級價格、每多一種週期，就多一套要測的組合與
一種要處理的續訂失敗。實際數字與「為什麼不照成本訂」在
[ADR-0011](0011-the-account-is-free-and-the-quota-is-paid.md)。

**價格是寫在程式裡的一個字串，不去問 Paddle。** Paddle 有一支 pricing-preview 可以按讀者所在國家回
一個在地化的金額，本來也接了，後來拿掉：Paddle 目錄裡只有一個美金價，所以那支 API 回來的永遠是同一個
「$20.00」，跟寫死的完全一樣。它換不到任何東西，卻要付一個 endpoint、一層 Cache API，以及一支沒登入
也打得到、會消耗這個部署 Paddle 額度的路徑。讀者仍然看得到自己的幣別，那是 Paddle 的結帳視窗在做的事。

退款是 **14 天無條件**，在 Paddle 後台手動退、手動取消訂閱，webhook 自然把額度縮回三本。程式不做
退款流程：一個人維護的專案，退款的次數少到不值得寫一條路徑，而手動做的那一次順便看得到是誰、
為什麼。

## 換掉它要付什麼

**簽章驗證、status 對應、Paddle 的每一個 API 路徑，全部關在 `packages/app/worker/billing.ts`
這一個檔案裡**，換金流商就是換這個檔。D1 那一欄叫 `provider_customer_id` 而不是
`paddle_customer_id`，也是同一個打算。

換不掉的是**稅務那一半**：從 MoR 換成 PSP 不是換一個檔案，是自己開始扛 VAT 與發票。所以這份
ADR 真正鎖住的不是 Paddle 這個名字，是「不自己扛稅」這個決定。

## 這張票不做 CSP

這個 repo 現在一條 CSP 都沒有（Worker 的 header、`index.html` 的 meta、`public/_headers` 全部
沒有），所以沒有東西需要為 Paddle 放行，接 Paddle 也沒有讓現況變差。

而且 Paddle 沒有官方的網域清單可抄。結帳視窗不只載一支 script，還會開 iframe、打 API、載自己的
字型，自己猜漏一個的下場是**視窗開不起來、錯誤只出現在瀏覽器 console、測試全綠，只在真人刷卡那
一刻才現形**。要做是另一張票，而且要先跑過一次真的結帳，從 console 把 Paddle 實際用到的網域抄
下來。
