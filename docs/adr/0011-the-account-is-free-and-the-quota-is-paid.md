# 帳號免費，額度收費

日期：2026-08-04，2026-09-02 改寫。前一版〈收費的界線是每個月的帳單〉的決定是**註冊就要收費**：
不註冊完全免費，註冊換到同步與 MCP，一個級距，沒有免費帳號這種東西。這一版把「帳號」與「額度」
拆開，帳號免費，收費的是額度。

## 決定

**不註冊完全免費，而且功能完整**：匯入、閱讀、直排、highlight、筆記、統計、匯出，全部在
使用者的瀏覽器裡跑完。這一條沒有變。

**建帳號也免費，不看付款。** 有帳號的人可以同步**三本書**，MCP 看得到那三本。

**付費一級，不分級**，買到的是同步與 MCP 沒有本數上限。其餘限制（[ADR-0013](0013-your-copy-is-yours.md)
的裝置數上限）付費之後照舊。

收費的界線仍然是**這個功能會不會長出每個月的帳單**：本機閱讀跑在使用者的瀏覽器裡（維護者零成本），
同步與 MCP 跑在 Worker + D1 + R2 上（按量付費）。變的只是那條界線上多開了三本的口。

## 為什麼要多開三本

前一版的理由是「多一級就多一組結帳狀態、權限判斷、說明」，一個人維護付不起。那個代價還在，
這次是判斷它值得付。

**MCP 要用過才知道它好在哪。** 「讓 agent 讀得到你的書」這句話對沒用過的人是空的：他想像不出
問 Claude「我上週劃的那段在講什麼」是什麼感覺。前一版的形狀下，體會到這件事之前得先掏錢，而
MCP 正是這個產品最特別的東西，所以那道牆擋掉的是最該被看到的部分。三本足夠讓人真的問出幾個
問題，又不足以當作一輩子的免費方案。

三本是試用，**而且沒有到期日**。它取代了前一版「免費層就是試用」的角色，理由也一樣：不做時間制
試用，見下面那節。

## 哪三本怎麼決定

**由程式決定，讀者不挑也不能換。** 一本書到伺服器的那一刻，這個帳號同步的書還沒滿三本就收下，
之後就一直是同步中的；滿了就留在裝置上。書架不滿三本的時候有幾本同步幾本，之後再加進來的書補到
三本為止。

不讓讀者挑，是因為挑的那個開關付費之後就用不到了：付費是「所有的書」，三本是試用，試用不值得
一個只有試用期會碰的介面。**先送到的先算，由 Worker 判**，不用 client 的時間排「最新」，因為兩台
裝置各自離線加書，各自都會以為自己還沒滿三本，只有伺服器給得出唯一的答案。一次丟十本進來哪兩本
被收下，對讀者來說本來就是隨機的，就讓它隨機。

**刪掉一本同步中的書，就少算一本，下一本新書進得來。** 「刪了也照樣算」要多存一份用過的歷史，
而且刪錯一本就永久少一本額度，說明不了。願意用「刪掉再匯入」繞的人付出的是真的代價：書與筆記都沒了。

## 一本書要嘛整本在伺服器上，要嘛不在

沒被收下的書**一個位元組都不上去**：書名、閱讀位置、筆記都留在裝置上，不是只有 epub 檔留著。

另一個做法是書目與閱讀位置照樣同步、只擋檔案，跨裝置看起來友善一點。不採用，因為那會發明第二種
「半同步」的狀態：MCP 列得出書名但打不開，說明與測試都要多一倍。「同步」只有一種意思，
agent 看得到的書、跨裝置接得上的書、伺服器保管的書，講的是同一批。

## 價格不照成本訂

量到的數字（2026-08，Cloudflare 官方價目表）：

| | |
| --- | --- |
| Workers Paid | $5/月，含 1000 萬 requests、3000 萬 CPU-ms |
| R2 儲存 | $0.015/GB/月，**免費額度 10GB/月** |
| R2 對外流量 | **$0** |
| D1（Paid） | 含 250 億 rows read、5000 萬 rows write、5GB |

一個典型使用者（50 本、150MB）一年的邊際成本**不到 US$0.05**。年費抓 NT$800 的話，**三個
付費使用者就打平整年的 Cloudflare 帳單**。免費的三本按同一個比例算，一個免費帳號一年不到
US$0.01，本數不是要擔心的成本，所以付費那一級也不設本數上限。

所以照成本訂會訂出一年台幣一百塊，而那個價格會殺死這門生意，不是因為賺不夠，是因為
**它直接攻擊開源要換的那個東西**。使用者要把整櫃書搬進來之前，心裡問的是「這東西五年後
還在嗎」。太便宜的價格回答「不在，這是副業，作者膩了就關」。

價格對照的是**一本書的錢**：一年不到一本書，換所有的書在所有裝置上都在。使用者算得出來，
而且這個對照會跟著書價一起通膨，將來要調價有現成的說法。

實際數字未定。

## 唯一會長大的成本：CPU

MCP 的取節與搜尋要真的 parse epub、算 CFI，那是 CPU time，超過 3000 萬 CPU-ms 之後
$0.02/百萬 ms。免費帳號讓這個成本第一次落在沒付錢的人身上，三本這個上限同時也是它的上限。

所以 [spec](../specs/mcp/spec.md) 裡那份「匯入時預建的純文字 ↔ CFI 對照表」有第二個
身分：**它不只是效能優化，是唯一的成本控制閥**。順序不變，它是快取，不是第二份真相。

## 不做時間制試用，做無條件退款

**三本就是試用，而且沒有到期日。** 使用者可以用一個月確定自己喜歡這個閱讀器，也真的讓 agent
讀過三本書，才決定要不要買全部。他唯一沒試到的是「更多本」，而那跟三本會不會動是同一件事，
時間制試用要解決的問題，在這裡不存在。

所以改成 **14 天無條件退款**。

綁卡試用（Stripe 的 `trial_period_days`）工一樣少，轉換率明顯較高，但**忘了取消被扣款是
網路上最被討厭的模式之一**。Tidemarks 整個產品的定位是信任：local-first、開源、不續訂也不刪
你的書，**在收錢的那一步用一個被討厭的模式，會讓前面全部失效**。這是這個產品特有的取捨，
不是通則。

## 停止付費之後不刪東西

帳號留著、資料留著，額度縮回三本。**保留 24 個月**，到期前寄信通知才清。

**留下來繼續同步的是最近讀過的三本**，其餘凍結。這裡不用「先送到的先算」，因為降級時每一本都
早就在伺服器上了，沒有先後可言；而最近讀過的三本是唯一跟「讀者現在在乎哪幾本」有關的規則，
伺服器有閱讀位置的時間戳，算得出來。

**凍結的書在每一台裝置上就是一本沒同步的書**：伺服器那份留著但不再收變更，MCP 看不到。讀者在
A 機繼續讀它，位置與筆記留在 A，B 機不會知道。這是他停止付費那一刻選的。重新訂閱的時候，
兩邊的變更照現有的 LWW 合併，不需要新機制。另外兩個做法都不採用：只凍檔案、位置與筆記照樣
同步，違反上面「整本在或不在」；讓凍結的書從其他裝置上消失，那是拿走讀者裝置上的東西，
違反 ADR-0013。

成本上這件事幾乎不存在：一個使用者留一年 US$0.03，三千個殭屍帳號一個月 US$7。

而因為 Tidemarks 是 local-first，停止付費的那一刻**書本來就還在使用者的裝置上**。所以留著
伺服器那一份，風險是零、成本是零，但可以大聲講出來：

> 你不續訂，我不刪你的東西。同步會停，書和筆記留在原地，你隨時可以匯出，也隨時可以回來。

那句話是開源換不到的另一半：開源證明「你收掉了我架得起來」，這句話證明「你還在，但我不付
了，你也不會扣我的書」。反面很醜：「不付錢就刪你的書」是那種會被截圖轉發的事，一個人扛
不起。

24 個月這個數字的用意是**比任何人「我明年再回來」的時間長**。有上限是為了將來真的需要清
的時候不必食言；寄信通知是為了那一天不會有人覺得被偷襲。

**匯出永遠不鎖在付費牆後面。** 一個不能把資料拿走的服務，前面所有的信任建設都白做。

## 〈上線〉不再等金流

前一版的形狀下沒付款就沒有帳號，所以金流是上線的前置。現在帳號免費，上線那天可以完全沒有付費
這回事：超過三本的書就是不同步。先開免費帳號，讓三本試用提前被真人用到；付費那一級之後加上去，
不動任何既有帳號的資料。
