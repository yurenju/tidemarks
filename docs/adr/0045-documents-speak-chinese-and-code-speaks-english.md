# 文件說中文，程式碼說英文

日期：2026-08-30。

## 決定

界線切在**檔案類型**上，不切在內容上：

> **程式碼檔一律英文，文件一律中文，兩份 README 是文件裡唯一的英文。**

程式碼檔裡「每一種敘述」都算：檔頭註解、行內註解、識別字、錯誤訊息、`console` 輸出、
`describe` / `test` 的名稱、config 檔裡的註解、commit message。文件是 `docs/`、
`packages/*/docs/`、`CONTEXT.md`、`CLAUDE.md`、`README.zh-TW.md`、`.scratch/`，加上
GitHub 的 issue 與 PR 內文。

這條界線在 CLAUDE.md 裡已經寫了很久，這支 ADR 做的是三件之前沒做的事：**把它掃乾淨、
讓詞彙表兩種語言都講得出來、加一支檢查**。

## 之前那條規則為什麼守不住

規則本身沒問題，問題是它**收不了尾**。CLAUDE.md 當時明文寫著「不做一次性全 repo 掃描，
編輯到某個檔案時順手把那個檔案轉掉」，理由是避免一大包純翻譯的 diff 蓋掉真正的變更。
那個理由是對的，但它的後果是這件事永遠做不完：沒被改到的檔案就一直是中文的，而
**沒有任何檢查分得出「這個檔案還沒輪到」與「這個檔案剛剛被寫壞」**。

掃之前的數字：91 個程式碼檔（`.ts` / `.tsx` / `.mjs`）的註解裡有中文，加上 CSS，這一輪動到 77 個
檔案、換掉 223 行（其中 53 行在 CSS）。這個規模用一個 commit 掃得完，而掃完之後剩下的中文就全部
是資料了，腳本才有辦法判斷（怎麼判斷見〈檢查抓的是什麼〉，它比「有沒有中文字」複雜一點）。

## 真正卡住的不是那兩百多行

註解已經是英文的檔案，裡面夾著中文的詞。`chrome.ts` 寫著 `The three panels 〈找〉 can
raise`，`App.tsx` 寫著 `〈設定〉's 帳號 tab`：英文的句子，中間一個中文詞。這種形式在程式碼裡
有 221 處。

原因不是誰偷懶，是**那些詞沒有英文名**。詞彙表整份是中文寫的，`〈找〉` 是它定義過的專名，
而英文註解要指那個概念的時候，沒有第二個名字可以用。

所以這支 ADR 真正的內容是：**詞彙表的每個詞條有中英文兩半**（`### 手勢 / Gesture`），而
**程式碼裡有名字的，英文那半就是那個名字**：`gesture.ts` 決定了 `Gesture`，`markVar()` 決定了
`Mark`，`PANEL_KINDS` 決定了 `Contents` / `Notes` / `Layout`。英文名不是翻譯，是同一個概念在
程式碼那邊的名字，所以識別字改名的時候詞彙表要跟著改。

⚠️ **有些概念程式碼裡還沒有東西**（〈退路 / Exit〉、〈寄物櫃 / Locker〉這些決策層的詞），它們的
英文名是先取的，哪天真的長出程式碼就用它。要提前取而不是留白，是因為「哪個詞以後會被英文註解引用
到」只能用猜的，而猜錯的代價是下一個人就地造一個名字，那正是兩套叫法的起點。

**專名的記號兩種語言各一個**：中文文件寫 `〈手勢〉`，程式碼寫 `[[Gesture]]`。`〈〉` 是中文的
篇名號，英文裡沒有對應的標點，而 `<Gesture>` 撞 JSX 與泛型、`` `Gesture` `` 在註解裡已經
表示「這是識別字」而詞條指的是概念。`[[Gesture]]` 沒有衝突，而且 wiki 那套寫法多數人看得懂：
這個詞在別的地方有定義。（它在 `git grep '\[\['` 上會撞到 TypeScript 的巢狀陣列與 bash 的
`[[ -n "$x" ]]`，那是它唯一的代價，而且只影響搜尋，不影響閱讀。）

**這個記號也用在畫面上那幾個字**（`[[Keep reading]]`、`[[Margin]]`），寫的是英文那半，因為介面
文案的原文就是英文（ADR-0031）。所以它指的是兩種東西：詞彙表的詞，或畫面上的那個字串。共通點是
**它們都有一個唯一的、寫得出來的名字**，而註解在指那個名字，不是在描述它。

## 為什麼註解用英文

維護者的母語是中文，寫中文註解本來比較快，所以這個選擇要講得出理由：

- **這個 repo 是公開的**，而且開源換到的東西是〈退路〉：維護者收掉服務之後別人架得起來
  （[ADR-0009](0009-open-source-buys-an-exit-not-contributions.md)）。架得起來的前提是讀得懂，
  而讀的人不限中文使用者。
- **改這些程式碼的多半是 agent**，而 agent 在英文的技術敘述上表現比較穩。這一點沒有量測，
  是判斷。
- **一個檔案一種語言**。混著寫的檔案沒有一條線分得出哪句該是哪種語言，而那正是前一版規則
  留下的狀態。

反過來，**文件維持中文**的理由同樣具體：這些文件在解釋「為什麼」，而那一半是最需要語氣與
分寸的地方。ADR-0031 已經記過同一件事的另一半：把中文降級成譯文之後，介面文案有被磨平的
風險，而擋它要三道機制。文件沒有那三道機制可用，所以文件不翻。

## 例外怎麼分

**換成英文之後那句話還成不成立**：成立就翻，不成立就是資料。

`scrubber.ts` 的註解講「直排書書首在右」，換成 "vertical books start at the right" 完全成立，
該翻；`chinese.ts` 的 `书→書` 對照表換掉就沒有東西可測了。同一條標準之下，
`scripts/zh-rules.ts` 的規則字串（那些中文**就是被檢查的對象**）、`.po` catalog、語言選單自己
的三個名字、測試 fixture 的中日文，全部是資料。

⚠️ 這條分法**不用目錄切**。`scripts/deploy.ts` 是正常的程式碼、該用英文，跟同目錄的
`zh-rules.ts` 情況完全不同，用目錄切會把兩者綁在一起。

## 檢查抓的是什麼

`scripts/check-language.ts` 掛在 `npm run lint` 後面（CI 已經在跑那一行），形狀跟 `check-i18n.ts`
一樣：I／O 一半、純判斷一半，判斷那半有測試。

⚠️ **規則不能是「程式碼檔裡不准有中文字」**，雖然那是最好寫的一條。掃下來有**大約 130 個檔案**的
中文是**資料**：量測是對著哪本書做的（草枕、《入境大廳》）、哪些字的字形會因地區而異（骨、直）、
簡繁對照表、fixture 的日文。照那條規則寫，這 130 個檔案每一個都要進豁免清單，而一份那麼長的清單
沒有人會讀。

所以拆成三條窄的，每一條對著這條界線實際會破掉的一種方式：

1. **程式碼檔裡出現 `〈…〉`**。那個記號是用來引用詞條的，而用它的註解就是「英文句子中間一個中文詞」。
2. **一行裡，字串以外的部分中文比英文多**。引用書名的英文句子仍然以拉丁字母為主，用中文寫的註解
   不是，比例分得出來。字串先被挖掉，因為 fixture 與書名本來就住在那裡。
3. **測試名稱裡有中文**。那些名字是報告，而報告寫英文。

第二條是鬆的，而且刻意鬆：它抓的是最明顯的那一種，不保證抓得完。整句中文的註解逃不掉，
引用草枕的英文句子不會被誤抓。

豁免清單因此只剩下**中文本身就是主題**的那幾個檔案，九個項目：`zh-rules.ts` 與它的測試、
`zh-lint.ts`、`language-scan.ts` 與它的測試（它們得寫出自己在找什麼）、`chinese.ts` 與它的測試、
`locale.ts`、`prototype/`。⚠️ 豁免是整個檔案的，所以被豁免的檔案裡寫了中文註解，腳本看不到。清單短正是這件事
還可以接受的原因，**它開始變長就是規則在鬆掉，不是清單變好用。**

## 兩份 README 與法律文字

`README.md` 與 `packages/frond/README.md` 是英文，因為它們的讀者是路過這個 repo 的陌生人。
`README.zh-TW.md` 是前者的中文版，兩份是同一份內容的兩個語言，**改一邊就要改另一邊**。

`LICENSE` 與 `THIRD-PARTY-NOTICES.md` 也是英文，但理由不同：授權條款的中文譯本沒有法律
效力，出處要照原文抄。這兩份**不翻**，寫下來是因為不寫的話，下一個讀到規則的 agent 看到
它們是英文的，合理的反應就是動手翻。

`docs/deployment.md` 以前是英文，這一輪翻成中文了。它的讀者是改這個 repo 的人，不是外部
使用者，外部自架看的是兩份 README。留一份例外的代價是規則從「只有 README 是英文」變成
「README 加一份」，而規則一有例外，下一份英文文件就有前例可以引。

## 這個決定要反悔的話

代價是再掃一次同樣規模的檔案，方向相反：兩百多行註解、221 處記號、加上詞彙表要拆掉一半。
掃得動，但沒有人會想做第二次，所以這支 ADR 存在。
