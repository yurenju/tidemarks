# 記號只畫在真的字旁邊

日期：2026-08-22。

修訂 [ADR-0005](0005-the-reader-adjusts-their-own-reading-not-this-book.md) 的一格：行距的
**「書籍預設」**從「完全不介入」變成「以書為準，但不低於一個下限」。那支 ADR 的其他每一句都成立：
排版只有一層、存在這台裝置上、直橫排共用一組值，字型的「書籍預設」也照舊完全不介入。

## 決定

波浪記號的落點，一條規則：

> **一行的記號，畫在這一行所有墨跡的最外緣之外，貼著它，而且是一條不斷的線。**

「所有墨跡」涵蓋正文、ruby、上標、下標。四條要求由它導出：

1. **不重疊到字上面。** 這是硬規則，不是「讀得出是記號就好」。
2. **不中斷。** 落點整行取最外緣，所以 ruby 與上下標只會把那一行的線往外推，不會把它切斷。
3. **靠近被畫的那一行**，不落在兩行中間讓人分不出標的是哪一行。
4. **跟被畫的字看起來是一個整體。**

要在真的書上做到，四件事：

| | 決定 |
| --- | --- |
| **波浪高度** | **4px**，到處都一樣（原本 6px）。波長按同一比例縮到 5.33px |
| **落點** | 離本行墨跡 **0.7px**，並保證離下一行墨跡 **1.3px** 以上 |
| **行距下限** | **只作用在行距的「書籍預設」這一格**：書自己的行距不夠時，撐到剛好夠 |
| **一行一個框** | 同一行的矩形先合併再畫，不逐矩形畫 |

外加兩條落在同一族的：ruby 的注音**不畫**波浪（但留在 hit test）；`U+3000` 與 NBSP 的連續段從
記號裡剪掉，整段都是空白的段落一個記號也不畫。

**傍點不解**，列為 known limitation。

## 行框不是墨，這是整件事的地基

之前每一次量測都在量**盒子**，而盒子不是墨：行框上下各帶著半行距，字型的 ascent 還在最高的字母
上面多留一段內部行距。扣掉之後，可用空間有一個乾淨的形式，而且**跟半行距無關**，它在兩邊各加
一次又各減一次：

```
兩行墨跡之間的空白 ＝ 行距 − 墨跡高度
```

Alice 的內文（15.33px Times New Roman，行距 18px，chromium，真的 app）：

| | 值 |
| --- | --- |
| 墨跡 ascent（`bdfhklt` 那一類） | 11px |
| 墨跡 descent（`gjpqy`） | 3px |
| 墨跡高度 | 14px |
| **墨到墨的空白** | **4px** |

用**字型**的 ascent + descent 算會得到 1px，那個數字說「無解」；用**墨跡**算得到 4px，說「差一點」。
兩者差在字型 metrics 裡的內部行距，而那一段是空的。**這一族的每一個決定都建立在用墨跡量，不是用
盒子量。**

直排那半寬裕得多：草枕 18.4px 的字、行距 32.2px、字身框 15px，兩側各 8.6px。問題只在右側被 ruby
的 8px 佔滿。

## 為什麼是 4px，而不是維持 6px 或縮到 2px

三種高度都做過 1:1 的原型（真的字級、真的 mask、跟 `HighlightLayer` 一樣的畫法），結論只有實際
大小看得出來：

- **2px**：不管波長縮不縮，讀起來是**一條普通底線**，波形消失。
- **3px**：幾乎也是。
- **4px**：看得出是波浪。
- **6px**：明確是波浪。

2px 是唯一不必動書的排版就塞得進 Alice 那 4px 的選項，而它換掉的是波浪本身，而波浪是這個 app
的記號（[ADR-0022](0022-the-interface-is-a-print-shop.md)）。所以不取。

6px 保住波浪，但要把 Alice 的行距撐到 22px（1.43×），介入太深。4px 只要 20px（1.30×）。

**4px 是到處都一樣的一個值，不隨書變動。** 可變高度會換到「大部分書維持 6px」，代價是三個東西必須
同步產生（tile 的 viewBox 與 stroke、`mask-size`、元素的 height），而其中任何一個沒跟上，畫面上
不會報錯，只會靜靜地畫出被切碎的波浪或什麼都不畫。一個值省掉那整類缺陷。

## 行距下限，以及它跟 ADR-0005 的關係

需要的墨到墨是 `0.7 + 4 + 1.3 = 6px`，所以

```
行距下限 ＝ 這個字型在這個字級下的墨跡高度 ＋ 6px
```

Alice 落在 20px，也就是 1.30×。**這是算出來的，不是一個常數**：墨跡高度隨字型而異，也隨字級而異
（那 6px 是絕對的），寫死一個比值會在 ascender 特別高的字型或很小的字級上失效。

### 它只碰得到一格

`LINE_HEIGHTS` 的階梯是 `書籍預設(0) / 1.4 / 1.6 / 1.8 / 2.0 / 2.2`，而下限在 app 的整個字級範圍
內都低於 1.4：

| 字級（`FONT_SIZE_MIN` 80% 到 `FONT_SIZE_MAX` 200%） | 需要的行距 |
| --- | --- |
| 12.8px | 1.38× |
| 16px | 1.29× |
| 18.4px（預設的 115%） | 1.24× |
| 32px | 1.10× |

所以**讀者只要選過任何一個行距，記號就一定放得下**，下限一次也不會動作。會不夠的只有
**「書籍預設」**那一格，因為那一格讓書自己決定。

（`LINE_HEIGHT_MIN` 是 1.2，但那是存值的驗證下界，UI 只給上面那六個，所以 1.2 走不到。）

這就是為什麼這支 ADR 只修訂 ADR-0005 的一格而不是推翻它的一半：**「書籍預設」的語意從「完全不介入」
變成「以書為準，但保證讀得下去」**，其餘五格與字型的「書籍預設」一個字都沒動。

考慮過而沒取的兩條：

- **維持純粹不介入。** 那些書上記號只能退回 2px，而 2px 在 1:1 之下是一條底線不是波浪，等於放棄
  這支 ADR 想要的東西。
- **把「書籍預設」從行距階梯上拿掉**，預設改成 1.4。程式最乾淨：下限的邏輯整段消失，但它把不介入
  整個拿掉，對每一本書、每一位讀者都定死行距，換到的只是省下一段判斷。

⚠️ **書用 `font:` 簡寫的時候，下限碰不到它。** `font: 16px serif` 會把 `line-height` 一併重設成
`normal`，而那是一條**寫在元素上的宣告**，贏得過從根繼承下來的值。就 cascade 而言書已經開口了，
而分辨「作者刻意選了 normal」與「作者只是用了簡寫」需要一條特化到足以蓋掉真正選過的書的規則，
那個代價比這個缺口大。實測釘在 `marked-rects.spec.ts`。

⚠️ 仍然是介入，而且是這個專案第一次在讀者沒開口的情況下改書的排版。design-system 的〈我們管容器，
不管內容〉因此多了一個例外，而那個例外的範圍窄到一句話寫得完：**只有行距，只有「書籍預設」那一格，
只有不夠的時候，只補到剛好夠。**

還有一個副作用得認：選「書籍預設」的讀者，在少數書上會看到行距跟別的閱讀器不一樣，而畫面上沒有任何
字說明為什麼。要不要在〈排版〉面板說一句，留給實作那支 issue。

## 為什麼一行要合併成一個框

`rectsFor` 逐個文字節點收矩形（`coveredParts`），所以一行裡只要有 `<em>`、`<a>` 或 ruby，就會被切
成好幾個矩形。今天每個矩形是各自的 `.highlight-box`，而 `mask-repeat` 從各自的左緣開始，量到一段
帶 `<em>` 的標記，三個框的相位是 3.45 / 1.17 / 0，**接縫處波浪會跳一下**。

那是現在就有的缺陷，不是新規則帶來的。而第 2 條（不中斷）要的不只是「共用一個外緣」，是**一條線**，
所以同一行的矩形要先合併成一個框再畫。

合併只影響**畫**。`boxesContain` 的命中判定仍然用 `rectsFor` 原本的矩形，注音與空白的矩形也留在
裡面，讀者點在自己標過的段落的注音上卻沒反應，說不通，而留著的成本是零。

## 這需要 frond 補兩個事實

app 拿得到選取的文字，也拿得到一排 `DOMRect`，但拿不到「哪一段文字對應哪個矩形」，也拿不到墨跡在
哪裡。兩個都只有 frond 知道（frond
[ADR-0002](../../packages/frond/docs/adr/0002-frond-owns-facts-spine-owns-policy.md)）：

1. **矩形帶角色**：`text` / `ruby` / `blank`，並在角色交界處把矩形切開。同一個改動解掉 ruby 與
   空白兩件事。
2. **墨跡的範圍**：每一行墨跡的外緣，以及這個字型在這個字級下的墨跡高度。

⚠️ 第 2 條要**用固定的探針量，不要量被標到的那段字**。逐段量的話，標到 `mono` 與標到 `happy` 會
得到不同的墨跡下緣，記號的高度就會隨標到什麼而抖。探針是固定的兩個字串（ascent 用 `bdfhklt`、
descent 用 `gjpqy`），對「字型＋字級」量一次並快取。

決定丟哪些矩形、線畫在哪一側、要不要撐行距，全部留在 app。

## 空白：兩種形狀，一條規則

掃過 25 本流通中的中文書、85,574 段（觀察用，書不進 repo，frond
[ADR-0007](../../packages/frond/docs/adr/0007-test-fixtures.md) 的第三層）：

| 形狀 | 長什麼樣 | 分布 |
| --- | --- | --- |
| **A 段落開頭的縮排** | `　　` 兩個全形空格，**跟正文同一個矩形** | 兩本書幾乎每段（97%、81%），其餘幾乎沒有 |
| **B 整段都是空白** | `<p>　</p>` 之類，用來製造一行空白 | 八本書共 761 段（最高 11%） |

A 只在跨段落選取時看得到；B 則是整條矩形都在空白上，跨過章節分隔就會憑空多一條波浪。

規則只管**會佔一格的字元**：`U+3000` 與 NBSP。行首的半形空格、tab 與換行畫不出空白（瀏覽器的空白
處理會收掉它們），把它們也切開只會讓矩形變多而畫面不變。

B 那種矩形整個丟掉之後，跨越章節分隔的螢光中間會空一行沒有記號。那是對的：那一行沒有東西被標記。

## 代價

- **`rectsFor` 的回傳型別要換**，`lib/highlights.ts` 的 `visibleBoxes` 與 `boxesContain` 跟著改。
  這是唯一動到 package 邊界的地方。
- **行距會被撐開**，在選了「書籍預設」而書自己排得很緊的拉丁書上。ADR-0005 的承諾破了一個小口。
- **波浪從 6px 變 4px**，每一本書都變，包括本來沒問題的中日文書。換到的是一個值到處通用。
- **傍點沒有解**。它是 `text-emphasis`，DOM 上沒有對應的節點，frond 要回報它就得為了一個裝飾去讀
  computed style，而症狀是波浪穿過幾個小圓點。
- **畫的範圍與點得到的範圍不再一致**，合併與丟棄都只作用在畫的那一半。

## 還沒決定的，留給實作

- **下一行不存在的時候**（段末、頁末），或下一行是圖、是不同字級的標題，落點怎麼算。
- **撐開之後還是不夠的時候**怎麼辦。撐行距讓這一格幾乎不會發生，但「幾乎」不是「不會」，
  書明確宣告了緊的行距、或用 `font:` 簡寫（等於宣告 `normal`），都落在這裡。
- **0.7 / 1.3 這組間距**是從 1:1 原型上看順眼取的，不是量出來的最佳值。

## 什麼時候回來重讀這一頁

- **frond 的 `rectsFor` 換了幾何。** 這裡每一個數字都是量出來的，不是規範保證的。
- **有人回報傍點。** 那表示「罕見」這個判斷錯了。
- **有人回報「這本書的行距被改掉了」。** 那表示下限的範圍還是太寬，該回頭看 ADR-0005 那一節。
- **行距的階梯改了，或最小的那一階降到 1.4 以下。** 上面那張表就不再成立，下限會開始蓋過明確
  選過的值，而那不是這支 ADR 談的範圍。
