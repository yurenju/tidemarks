# 介面是印刷廠：紙、墨、葉綠

日期：2026-08-12。

## 決定

Folis 的視覺由**三個材質**決定，任何新畫面都從這三個字推出來：

- **紙**＝容器，讀者改不動的：底、卡、封面、抽屜、bar。四階明度，無漸層，無貼圖。
- **墨**＝痕跡，讀者留下的：字、筆記、螢光、讀過的段落、讀完日期。階層只用**濃度**做，
  不用字重、不用底色塊、不用框。
- **葉綠**＝可以動的東西：主要動作、拖曳的手、你在這裡。一屏上綠色的地方應該數得出來。
  **數的單位是控制項，不是格子**：一組 segmented 的選中格跟它所屬的控制項一起算一個綠，
  因為那塊綠說的是「這一格是現在的值」，不是「這一格可以按」——整組都可以按（2026-08-18 補）。

三條硬規則從它們掉出來：

1. **直角是預設。**只有被手指捏住的東西是圓的（Scrubber 的 thumb 與端點、螢光色票）。
2. **陰影不擴散，而且有意義：有影子＝這個東西能被拿起來**（書、抽屜、sheet、toast、
   thumb）。黏在畫面上的沒有影子（bar、表單、唯讀進度條）。位移是硬的、方向是固定的，
   **只有邊緣可以糊**——見〈為什麼陰影是硬的〉。
3. **質感只出現在讀者碰過的地方。**介面本身乾淨、對齊、克制：不用手寫字體、不做紙纖維與做舊
   貼圖、不做翻頁的 3D 曲面、不畫墨滴與羽毛筆。

介面的字是**襯線**（`--font-ui`），拉丁那半用自帶的 Source Serif 4。

token 的值、新舊對照與每個元件的規則在 [docs/design-system.md](../design-system.md)。

## 為什麼是這三個

這個 app 只做一件事：把一本書放在讀者面前。那意味著畫面上永遠同時有**兩種東西**——出版社與作者
給的（書的字、封面、排版），跟 Folis 自己的（bar、抽屜、按鈕）。**這兩種東西不能長得像同一種**，
否則讀者分不出哪些字是書講的、哪些是軟體講的。

一般的做法是靠「品牌色」分開。這裡不行：封面的顏色是出版社說了算，書的內文顏色是書說了算，
Folis 能控制的只有它們周圍那一圈。所以分法只能靠**材質**，不能靠顏色：紙不是內容，內容是印在
紙上的墨。

葉綠只有一個用途，而且是唯一有顏色的東西，這讓「哪些東西按得動」變成**看一眼就數得出來**的事，
不必記規則。代價是綠色的預算很小，一屏超過三處就要有東西退回墨——這正是要換到的約束。

`#3f5c46` 而不是別的綠：它跟四個墨水色（蓼藍、赭石、苔綠、松煙）都不撞，所以「我畫的」跟
「我可以按的」在同一頁上不會混。這是選色時唯一的硬條件，其餘是品味。

## 為什麼陰影是硬的

模糊陰影模仿的是**點光源加空氣**，那是螢幕在假裝自己是一個立體空間。硬位移陰影模仿的是**紙壓在
紙上、光是斜的**，那是印刷品真的會有的樣子。兩者都可以，選後者是因為它讓陰影變成一個**可以查證
的事實**而不是裝飾：有影子代表這個東西能被拿起來。

規則反過來也成立，而那才是它值錢的地方：**bar 不能有影子**，因為 bar 拿不起來。以前的
`box-shadow: 0 8px 24px` 出現在 bar、卡片、浮層、toast 上，一律是為了「看起來有層次」；那種用法
沒有任何一句話可以判斷對錯，所以每個新元件都要重新猜一次。

### 邊緣可以糊，位移不行（2026-08-18 修訂）

原本寫的是「blur 永遠 0」，那句話多綁了一件事。**撐起這個比喻的是位移與方向**——紙壓在紙上、
光從固定的一角來——而不是邊緣要銳利到像切出來的。真的紙壓在紙上，交界那一兩公釐本來就是散的。

所以現在的陰影是兩層：一層 `blur 0` 但透明度砍半，維持那塊硬的位移；上面疊一層短 blur、
更淡的，把交界那一兩個 pixel 化開。遠看還是同一個東西，近看邊不再是刀切的。

**能糊多少有上限，而上限就是「不擴散」**：blur 不得大於位移的兩倍，也不准加 spread。超過那個
比例，陰影會開始往物件四周均勻散開，那就是點光源加空氣的樣子，這條規則也就沒了。

深色主題本來就沒有陰影可花（近黑上面的黑位移等於沒有東西），「浮起來」在那邊是靠比較亮的表面
說的。這次修訂對深色是無感的，照樣套同一組值只是為了不讓兩個主題各有一套規則。

## 為什麼直角

圓角在這裡沒有東西可以對應。書是切出來的、紙是切出來的、印刷品的邊是直的。而且圓角一旦開放，
半徑就會變成一個旋鈕：現行的 CSS 裡同時有 6、8、12、14、999px 五種半徑，沒有一種說得出為什麼是
那個數字。

留下來的三個圓形有一句話可以判斷：**手指會捏住它**。thumb 是拖的、端點是 thumb 的兩個極限、
螢光色票是點的。要加第四個圓形之前，先問這個東西是不是被捏住的。

## 代價

**每一個新畫面都要先問三個材質。**這比「照著 Figma 畫」慢，尤其是碰到既有的 UI 慣例時：一個
沒有陰影的 bar、一個沒有底色的 active 狀態、一個 44px 高但沒有圓角的按鈕，看起來都比業界常見的
樣子「素」。那是刻意的，但它需要每次都重新說服自己一遍。

**綠色的預算會不夠用。**當一屏上有三個以上真的很重要的動作時，規則會逼人做取捨——決定哪一個是
primary。那個取捨本來就該做，只是以前可以靠「全部都上色」逃掉。

**亮色的 muted 被迫壓深。**設計稿的 `#8a8278` 對紙是 3.54:1，過不了 WCAG AA；實作用的是
`#6f675d`（5.2:1）。四階墨因此有一階（`--text-faint`，2.7:1）**不是文字色**，只畫線與 disabled
的圖示。這是設計與 [ADR-0021](0021-accessibility-is-borrowed-not-written.md) 之間唯一一次正面
衝突，解法是讓最淡那一階不承載字，而不是把它調到跟上一階分不出來。

## 反過來的證據

如果哪天出現一個**必須靠顏色分類**的畫面（例如多個帳號、多個書庫、標籤系統），三個材質會撐不住：
那種畫面需要一組互相區分的顏色，而這裡只有一個綠跟四個墨水色，而且四個墨水色已經被螢光佔走了。
那不是這套系統壞了，是那個功能在問「Folis 要不要變成一個分類工具」，該回去問產品。
