# 介面是印刷廠：紙、墨、潮

日期：2026-08-12。**2026-08-22 就地改寫**：第三個材質從葉綠換成潮，圓角與陰影兩條硬規則整組換掉，
視覺方向改採 Indigo Dye。

> **這份文件被改寫過，不是加註修訂。** 舊版寫的是「紙、墨、葉綠」加上「直角是預設」「有影子＝拿得
> 起來」，值是一個綠（`#3f5c46`）配四個墨水色。那一版的推理沒有錯，是它要服務的視覺方向換掉了。
> 改寫而不是另開一支 supersede，是因為這個 repo 的 ADR 已經多到會互相稀釋，往後的做法是**在原處
> 保留縮減過的脈絡**，而不是讓每一次轉向都長出一支新編號。下面凡是寫「舊版」的段落，就是那份縮減。

## 決定

Tidemarks 的視覺由**三個材質**決定，任何新畫面都從這三個字推出來：

- **紙**＝容器，讀者改不動的：底、卡、封面、抽屜、bar。四階明度，無漸層，無貼圖。
- **墨**＝**讀者留下的痕跡**：螢光、筆記。它的顏色是四個墨水色，預設那個就是品牌記號色。
- **潮**＝可以動的東西：主要動作、拖曳的手、你在這裡。一屏上潮色的地方應該數得出來。
  **數的單位是控制項，不是格子**：一組 segmented 的選中格跟它所屬的控制項一起算一處，因為那塊顏色
  說的是「這一格是現在的值」，不是「這一格可以按」——整組都可以按。

⚠️ **「墨」的範圍比舊版窄。** 舊版的墨包含「所有的字」，階層只用濃度做；現在**正文的四階濃度仍然
存在而且規則不變**（`--text-primary` / `-body` / `-muted` / `-faint`），只是「墨」這個材質名專指
讀者留下的東西。這樣分是為了讓下面那條硬條件有東西可以指。

三條硬規則從它們掉出來：

1. **圓角有四階，而且每一階都有一句話說得出為什麼**：結構 6px（卡、彈窗、閱讀區、封面）、
   控件 3px（按鈕、欄位、標籤）、999px 只給開關與進度條、50% 只給圓點。要第五種半徑之前，先回來
   改這份文件。
2. **沒有任何投影。**「浮起來」由**表面階數**說：`--surface-raised` 比書頁亮一階，
   `--surface-sunken` 暗一階。見〈影子換成階數〉。
3. **質感只出現在讀者碰過的地方。**介面本身乾淨、對齊、克制：不用手寫字體、不做紙纖維與做舊
   貼圖、不做翻頁的 3D 曲面、不畫墨滴與羽毛筆。

介面的字是**襯線**（`--font-ui`）。字型策略見〈四個家族，兩種待遇〉。

token 的值與每個元件的規則在 [docs/design-system.md](../design-system.md)。

## 為什麼是這三個

**這一節整段是舊版的，一個字沒改，因為它是這整套東西存在的理由。**

這個 app 只做一件事：把一本書放在讀者面前。那意味著畫面上永遠同時有**兩種東西**——出版社與作者
給的（書的字、封面、排版），跟 Tidemarks 自己的（bar、抽屜、按鈕）。**這兩種東西不能長得像同一種**，
否則讀者分不出哪些字是書講的、哪些字是軟體講的。

一般的做法是靠「品牌色」分開。這裡不行：封面的顏色是出版社說了算，書的內文顏色是書說了算，
Tidemarks 能控制的只有它們周圍那一圈。所以分法只能靠**材質**，不能靠顏色：紙不是內容，內容是印在
紙上的墨。

## 「我畫的」跟「我可以按的」不可同色

這是選色時**唯一的硬條件**，其餘是品味。舊版由「葉綠 `#3f5c46` 跟四個墨水色都不撞」擔保；現在整個
畫面都是藍的，所以改由兩個藍分擔：

| | token | 亮 | 暗 |
| --- | --- | --- | --- |
| 我畫的 | `--mark-indigo`（預設墨水） | `#1b2e4d` | `#a9c4de` |
| 我可以按的 | `--tide` | `#2e4a75` | `#7ea6ce` |

**這一條偏離了 Indigo Dye 的字面規定，而且是刻意的。** 那份 handoff 把 `blue-mark` 同時派給
「波浪底線、已標記填色、**主按鈕**、**書封**」，但它自己的規則 1 又寫著「`blue-mark` 只代表使用者
留下的東西」——兩句話互相牴觸。它的稿子上看不出來，因為那張閱讀畫面只畫了一句被標記的句子；真實的
一頁上會有十幾條線，而底下那顆〈標記〉主按鈕就在同一屏。

所以主按鈕與書封退到 `--tide`。代價是主按鈕比 handoff 想的淺一階，而那一階量過了：`#2e4a75` 對紙
7.7:1、`#7ea6ce` 對暗底 6.5:1，兩個都遠在門檻之上，按鈕沒有變弱。

## 影子換成階數

舊版的規則是「**有影子＝這個東西能被拿起來**」，硬位移、固定方向、只有邊緣可以糊。它值錢的地方是
反過來也成立：**bar 不能有影子**，因為 bar 拿不起來。那讓陰影變成一個可以查證的事實而不是裝飾。

Indigo Dye 沒有投影，所以那個事實需要另一個人來說，而**這件事其實已經有先例**：
[ADR-0028](0028-chrome-floats-one-step-above-the-book.md) 讓 chrome 的三條 bar 吃
`--surface-raised`，理由正是深色主題本來就沒有影子可花（近黑上面的黑位移等於沒有東西），「浮起來」
在那邊只能靠比較亮的表面說。現在兩個主題都採用它：

> **浮起來的東西比它下面那層亮一階；凹進去的暗一階。**

主幹是三階：`--surface-raised` ／ `--surface-page` ／ `--surface-sunken`。**需要第四階的時候要真的
加一階，不能讓兩階共用同一個值**——Indigo Dye 自己記的第一條 known debt 就是這個（亮色的
`bg-sunken` 與 `bg-skeleton` 都是 `#ede5d6`，所以「彈窗裡的載入卡」會沒有層次）。既然階數現在要
擔責任，那條 debt 不能留到「做到那個畫面時再決定」。

第四階已經有一個了：**`--surface-cover`**，沒有封面圖的書躺在書架上用的那張紙。它一開始跟
`--surface-sunken` 共用一個值，也就是這一節明文擋掉的事——而暗色更糟，共用的那個值比書頁**暗**，
封面於是沉進書架裡。寫下規則跟守住規則是兩件事，這是證據。

分界的髮線留著。深色主題那一階只有 1.08:1，戶外強光或低亮度螢幕下會糊掉，那時候線是唯一撐住的。

## 為什麼現在有圓角了

舊版寫的是「圓角在這裡沒有東西可以對應。書是切出來的、紙是切出來的、印刷品的邊是直的」，而且擔心
半徑會變成一個旋鈕——當時的 CSS 裡同時有 6、8、12、14、999px 五種半徑，沒有一種說得出為什麼是那個
數字。

那個擔心是對的，解法卻不必是零。**現在的四階各自綁著一句話**：6px 是「這是一張紙」（卡、彈窗、
閱讀區、封面）、3px 是「這是一個控件」（按鈕、欄位）、999px 是「這條軌道有兩個端點」、50% 是
「這是一個點」。判斷一個新元件用哪一階，問的是它是哪一種東西，不是它看起來該多圓。

舊版留下的那句話仍然成立而且沒有被取代：**手指會捏住的東西是圓的**（Scrubber 的 thumb 與端點、
螢光色票）。那是 50% 那一階的內容。

## 四個家族，兩種待遇

Indigo Dye 要四個字型家族各司其職：Noto Serif TC 給內容與標題、Spectral 給字標與西文數字、
Noto Sans TC 給控件與 meta、IBM Plex Mono 給 uppercase 微型標籤。它假設四個都從 Google Fonts 拿。

**拉丁那半自帶，漢字那半名平台堆疊**，沿用 [ADR-0014](0014-spine-carries-the-font-rather-than-borrowing-it.md)
的做法。理由是尺寸而不是潔癖：`NotoSerifCJKtc-Regular.woff2` 是 16 MB、`NotoSansCJKtc-Regular.woff2`
是 11 MB，而那兩支照 ADR-0014 是**開了真的有漢字的書才下載**、存在 Dexie。把第二個 11 MB 搬到
「介面按鈕」這個位置上，等於讓書架在下載完成之前沒有字。

要誠實講的是這條買到的東西比 handoff 想的少：**中文的按鈕字在不同機器上仍然長得不一樣。** handoff
那種「逐值採用就會長得一模一樣」的保證，在漢字那半拿不到，只有拉丁那半拿得到。

## 對比度上的偏離

[ADR-0021](0021-accessibility-is-borrowed-not-written.md) 說無障礙照 WCAG 借，不自己發明。這套色票
逐值量過之後有兩處要調，兩處都記在這裡：

- **`blue-static` 亮色 `#7a93ae` 對紙只有 2.7:1**，過不了非文字圖形的 3:1，而它的用途裡有「pressed
  填色」——一個按下去跟沒按下去在陽光下分不出來的狀態。所以 pressed 沒有用它，改用把互動藍再壓深
  一階的 `#24395c`（紙色字在上面 10:1）。handoff 沒點名這個值，它只點名了 `decor-faint`。
- **`blue-static` 上面不能放紙色字。** 紙色 `#f4eee2` 對 `#7a93ae` 是 2.7:1。handoff 的書封規格
  寫著「四階藍為底、紙色字」，那在最淺的兩階上讀不出來——而書封這件事最後是另一個答案：有封面圖
  就用封面圖（[ADR-0013](0013-your-copy-is-yours.md)：讀者匯入的書長什麼樣不是 app 說了算），
  沒有圖的用 `--surface-cover` 加 `--text-primary`，四階藍一階都沒有用上。

**結果是 `blue-static` 沒有變成 token。** 兩個用途一個換了值、一個消失了，剩下的「非互動裝飾」
在這個 app 裡沒有東西要畫。量測留在這裡是因為它是「不能照抄」的證據；哪天真的有用途，要從
`#6e88a6`（3.2:1）起算，不是從 handoff 的原值。

舊版也有一處同類的偏離，照舊有效：設計稿的 muted `#8a8278` 對紙是 3.54:1，實作用的是 `#6f675d`
（5.2:1）；四階墨因此有一階（`--text-faint`）**不是文字色**，只畫線與 disabled 的圖示。解法一律是
讓最淡那一階不承載字，而不是把它調到跟上一階分不出來。

## 代價

**每一個新畫面都要先問三個材質。**這比「照著設計稿畫」慢，而且 Indigo Dye 是一份 high-fidelity 的
稿子，看起來像是可以逐值抄的。上面兩節就是抄不得的地方。

**潮色的預算會不夠用。**當一屏上有三個以上真的很重要的動作時，規則會逼人做取捨——決定哪一個是
primary。那個取捨本來就該做，只是可以靠「全部都上色」逃掉。這條跟舊版一字不差，換了顏色沒有讓它
變鬆。

**「拿得起來」現在說得比以前弱。**影子是一個看一眼就成立的事實，一階表面差不是——亮色那一階只有
一步，暗色 1.08:1。換來的是整套跟 handoff 對得上，而且深色主題不再是「規則在這裡失效」的特例。
這是這次改寫裡最貴的一筆，如果之後發現讀者分不出彈窗與 bar，要回頭看的就是這一條。

## 反過來的證據

如果哪天出現一個**必須靠顏色分類**的畫面（多個帳號、多個書庫、標籤系統），三個材質會撐不住：那種
畫面需要一組互相區分的顏色，而這裡只有三個藍加四個墨水色，而且四個墨水色已經被螢光佔走了。那不是
這套系統壞了，是那個功能在問「Tidemarks 要不要變成一個分類工具」，該回去問產品。

（這一節也是舊版的，把「一個綠」換成「三個藍」之後結論沒有變——這正好說明那個結論不是從綠色推出來
的，是從「顏色的名額很小」推出來的。）
