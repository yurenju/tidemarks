# 閱讀器的四個狀態跟著讀者的迴路走

日期：2026-08-12，2026-10-08 改寫。前一版〈介面退到書後面去〉的決定是：閱讀器同一時間只成立三個
狀態（讀／找／標），chrome 不再常駐，三個狀態互斥、沒有例外；〈筆記〉是〈找〉的三張面板之一。
這一版保留「一個狀態，不是五個開關」與「chrome 不常駐」，把狀態從三個改成四個，加上〈回看〉，
互斥規則也多了一個例外。

## 決定

閱讀器同一時間只成立四個狀態的其中一個：〈讀〉〈找〉〈標〉〈回看〉。chrome 不常駐。定義在
[CONTEXT.md](../../CONTEXT.md)〈chrome〉與〈回看〉，規則都在 `packages/app/src/lib/chrome.ts` 那一個
純函式裡。

- **〈標〉包含當場寫筆記。** 劃完按「加筆記」就在原地寫，chrome 從頭到尾不出現，寫完回〈讀〉。
  寫的地方借〈回看〉的版面（桌機是右欄，手機蓋在書上），兩種寬度只要一套寫筆記的畫面；但狀態仍是
  〈標〉，所以寫完不會留在列表裡。例外是在〈回看〉裡選字再按「加筆記」：那時候讀者本來就在回看，
  就在面板裡寫，寫完仍在〈回看〉。
- **〈回看〉是新的狀態。** chrome 退場，〈筆記〉面板就是它的樣子。在裡面可以前後翻書，也可以再劃新的。
- **四個狀態互斥，例外只有一個：〈回看〉裡選字不離開。** 〈讀〉與〈找〉裡選字，〈標〉照樣取代它們。

**輕觸一次叫出 chrome**，桌機的滑鼠點擊也是。翻頁不由 tap 負責
（[ADR-0024](0024-turning-a-page-is-a-swipe-and-nothing-else.md)）。

## 為什麼要有一個狀態，而不是五個開關

前一版要解決的問題現在還在：閱讀器上曾經有五層東西可以同時在畫面上（頂列、Scrubber、目錄側欄、
筆記側欄、設定 popover），每一層各自有自己的顯示條件，**沒有任何一層負責回答「這一刻讀者在做什麼」**。
結果是閱讀時介面太吵、匯出匯入像 debug 按鈕、書架答錯問題，三個症狀其實是同一件事。

換成狀態機之後，每一層的出現都是讀者剛剛做的動作換來的，而**互斥是它的大部分價值**。所以這一版
加的那個例外要說得出理由，而且只能有一個，見下面〈為什麼〈回看〉裡選字是唯一的例外〉。

## 為什麼從三個改成四個

前一版的三個狀態是從**介面**分出來的：什麼都沒有、chrome 全出來、顏色列。這一版從讀者的**使用迴路**
重分：讀 → 被打中、劃起來（有時趁熱寫幾句）→ 回頭看自己劃過與寫過的 → 帶回自己的知識系統。

照介面分的結果是迴路的後兩步沒有落腳處。「回頭看」沒有自己的狀態，只能借〈找〉的入口：先輕觸叫出
chrome，再按〈筆記〉，於是頂列、Scrubber、面板三樣同時在畫面上，書被夾在中間。「寫」又跟「劃」分在
兩個地方，劃在〈標〉，寫卻要跳進〈筆記〉面板。

照迴路分，每一步各有一個狀態：讀是〈讀〉，劃與趁熱寫是〈標〉，回頭看是〈回看〉。〈找〉留著，它管的
是迴路以外的事：去別的章、調排版、回書架。最後一步（帶回知識系統）在 app 外面，不需要狀態。

## 為什麼〈標〉包含寫筆記

趁熱寫的價值在**不打斷**。讀者被一段話打中，劃起來，想到一句話；這時候把畫面換成一張面板、一組
頂列和一個進度軸，那句話很容易就散了。所以寫在原地，寫完回到書上，劃、寫、讀是一條順的路。

改舊的筆記不在這裡，從〈回看〉進去改。改舊的跟寫新的是兩件事：寫新的時候讀者在書裡，改舊的時候
讀者在回顧。

## 為什麼〈回看〉裡翻頁不離開

在〈找〉裡翻頁就回〈讀〉，因為〈找〉是借來用一下的介面，翻頁表示那一下已經過去了。〈回看〉不一樣：
跨頁的重點要翻過去才看得完，讀者在這裡是有意地在書裡移動，邊看筆記邊看書。翻頁就把面板收掉的話，
每翻一頁就要再走一次進來的路。

選中的那一則如果還在新的這一頁上就留著，不在就取消，書上與列表上不會留著一則看不到的「選中」。
「翻到的那一頁上有哪幾則重點」只有 Reader 量得到，所以由它在翻頁落定之後帶進狀態機，狀態機自己
不去查。

### 這不是前一版拿掉的常駐側欄

前一版拿掉了桌機的目錄與筆記側欄，〈回看〉看起來像把筆記側欄放回來。差別在誰選的：常駐側欄是讀者
沒有選擇、一直都在的；〈回看〉是讀者自己走進去的，出口是一個明確的動作（✕、Esc、返回鍵、`N`、點一下
書頁）。前一版反對的是前者，那條理由對〈回看〉不成立。

## 為什麼〈回看〉裡選字是唯一的例外

讀者在回頭看自己劃過的東西時，又看到一段想劃的，這正是〈回看〉要讓人做的事。照互斥規則把面板收掉，
等於在讀者最投入的時候把面板收走，劃完還要再走一次進來的路。所以在〈回看〉裡選字，顏色列疊在書上，
面板留在旁邊，新的那則出現在列表裡並被選中。

〈找〉不比照辦理。前一版反對例外的理由（留一個等於留五個，每個例外都會長出自己的條件）還成立，
所以只在理由站得住的地方開：〈找〉是借來用一下的介面，選字就表示那一下已經過去了，留著它換不到
東西，只會讓顏色列多一層要閃避。

## 明確拒絕自動退場

chrome 出現後 N 秒沒動作自己收，不做。那是一個讀者看不見的計時器，人正在目錄裡找章節時它會把
東西收走，比誤觸更難受。誤觸的代價只有一次多餘的 tap。

## 整頁的 tap 都要取消預設動作

`preventTapDefault()` 的條件是「手指或觸控筆、不是連結」，**不看位置**，而現在整頁的 tap 都有
動作要保護，所以那個條件正好。不取消的話 Chrome for Android 會在那裡一點就選走一個詞，而讀者
以為自己在叫出介面。

## 桌機那一半是白撿的

CONTEXT.md〈Navigator〉早就寫死「滑鼠點擊一律不翻頁」，理由是它會跟「點一下定位游標」「雙擊選詞」
打架。所以桌機上點擊這個動作的語意本來就是空的，拿來叫 chrome 不必付任何代價。

## 代價

- 讀者的肌肉記憶要重建，而且建了兩次：前一版拿掉常駐的 chrome，這一版把點重點從「開始寫」改成
  「看那一則」。這是這個決定裡最難逆轉的部分，也是它值得一支 ADR 的原因。
- 互斥規則有了一個例外。它是刻意開的，但從此「四個狀態互斥」這句話後面都要跟著一個「除了」，
  下一個想開例外的人可以拿它當前例。擋的方式是上面那條：說得出理由才開，而且要寫進這裡。
- 〈回看〉裡翻頁不離開，翻頁這條路比以前多走了一段：每翻一頁，Reader 要在落定之後再告訴狀態機一次
  這一頁上有哪幾則重點。沒有變化的時候狀態機回傳同一個物件，所以它不多一次重繪，
  `turn-pacing.spec.ts` 守著這件事。
