# 開源買的是退路，不是貢獻

日期：2026-08-04。

## 決定

spine 的原始碼公開，授權 **MIT**，**含 `worker/`**。

開源要換到的是**退路**——兩件具體的事：**維護者收掉服務之後，讀者自己架得起來**；
**維護者漲價之後，讀者搬得走**。

明確**不**打算換到貢獻。README 要寫明：這裡沒有回覆保證、預設不收 PR、這是一個人維護的
專案。

## 為什麼要開源：使用者得先把整櫃書交出來

spine 打算靠託管服務收費（見 [ADR-0011](0011-the-paywall-follows-the-monthly-bill.md)），
而使用者付錢之前要把自己買的書上傳到別人的伺服器。他猶豫的不是「這個 app 好不好用」，
是「我敢不敢」。

那份懷疑有四種，開源都回答得了，但**第一種的回答方式跟其他三種不一樣**：

| 懷疑 | 開源怎麼回答 |
| --- | --- |
| 會不會偷看我的書、拿去訓練、外洩 | **證明不了。但不信的人可以自己架一份** |
| 服務收掉了，我的書和筆記怎麼辦 | 自己架得起來 |
| 這東西夠不夠好，值不值得我搬進來 | 程式碼在那裡，自己看 |
| 付了錢之後會不會被漲價綁架 | 搬得走 |

第一項為什麼證明不了，理由很硬：**開源證明的是 GitHub 上那份程式碼，不是
`app.folis.ink` 上跑的那份。** 使用者驗不了部署的是哪個 commit，也驗不了 Worker 裡有沒
有多一行。沒有任何授權補得起來——那是託管服務的本質。

**但「證明不了」不等於「沒辦法」。** 開源給的是另一種東西：不信任維護者的人，不必被迫在
「相信」和「不用」之間二選一，他可以**自己架一份**——那份的程式碼他讀得到、部署的是哪個
commit 他自己決定。這正是〈退路〉，只是這裡它回答的不是「服務收掉了怎麼辦」，而是
「我從一開始就不想信你」。

所以這四項其實是同一個答案的四種問法，而它也解釋了為什麼 `worker/` 非開不可（見下一節）：
只開前端的話，不信任的人連自己架都做不到，第一項就真的變成沒有答案。

而它**不能靠端對端加密繞過去**，因為 MCP 已經把那條路關掉了：`/mcp` 的取節與搜尋要 Worker
自己 parse epub、算 CFI（[docs/specs/mcp/spec.md](../specs/mcp/spec.md) 的「定位下沉」），
密文做不到這件事。**只要 spine 賣 MCP，伺服器就一直看得懂使用者的書。**

所以第一項只能靠**架構**買，而且只買到免費的那一級：**不註冊就完全不上傳**。不開帳號，
spine 完整可用，書一個 byte 都不離開那台裝置。這句話可以講，因為它是真的。

超過這一級的保證一律不給。理由不是做不到，是**不保證保證不了的事**。「開源所以我看不到你
的書」是一句經不起追問的話，被戳破一次的損失比從來沒開源還大。

（還有一件便宜、而且**是**承諾得起的事：**條款上只主張營運需要的最小授權**。它證明不了伺服器
乾淨，但它是有拘束力的。內容與同類服務的對照在
[ADR-0010](0010-spine-is-never-the-path-to-a-book.md)。）

## `worker/` 一定要一起開

只開前端、留著 worker 閉源，退路就沒買到：使用者拿到一個連不上任何後端的殼。付了開源的
全部代價，換到零。

推論還有一步：**退路要可信，得真的有人架得起來。** 所以「一個外人照 `docs/deployment.md`
架得起來，而且不需要自訂網域」是開源**之前**要驗的事。等到收費那天才發現自架路徑是壞的，
那時候它已經是行銷承諾了；現在它還只是一份沒人試過的文件。

## 開源的動作是「新開一個 repo」，不是把這個轉 public（後半已作廢，2026-08-20）

> **路標**：這一節的計畫執行了——`yurenju/tidemarks` 是 2026-08-19 新開的 public repo，歷史從
> 單一個 `Initial commit` 開始。但它換到的第二件事**不再成立**：舊 repo 沒有繼續當工作台，往後
> 的開發都在公開的這一個進行。現在的規則在 [CLAUDE.md](../../CLAUDE.md) 的〈這個 repo 是公開
> 的，而且沒有私有的另一半〉。底下的推論一個字都沒動，那是 2026-08-04 那天的判斷。

`yurenju/spine` 現在是 private，而且一直是**工作台**——文件裡有寫給自己看的東西（風險評估、
還沒想清楚的推論、當初對使用者行為的觀察）。那些東西改掉之後檔案是乾淨的，但 **`git log` 裡
的舊版本還在**；而且 GitHub 連 PR 碰過的 commit 都會永久保留，**force push 也清不掉**。

所以開源那天的動作是：**另開一個 public repo，把當時的檔案內容當成單一 initial commit 推上去。**

丟掉的是 commit 歷史，而那個代價比想像中小——〈退路〉要的是「程式碼在那裡、自己架得起來」，
不是誰在哪一天改了哪一行。

換到兩件事：**一次清乾淨**（不必逐句掃歷史，而逐句掃一定會漏），以及**這個 repo 可以繼續當
工作台**——寫東西的時候只要顧好檔案的當前內容，不必每寫一句就自我審查。


## 為什麼是 MIT

先問過要不要用 AGPL 或 BSL 那類擋人的條款，答案是不要，因為**擋不到東西**：

- 程式碼不是護城河。UI 本來就抄得到，想抄的人叫 agent 讀一遍重寫也有。
- 真正的風險不是有人抄，是**沒有人付錢**。抄的人要自己吃 R2 與 D1 的帳單、自己回信、
  自己維護五年——那是一門會自己收掉的生意。
- BSL 換到的代價是不能自稱開源，而它嚇跑的正好是最看得懂 local-first、最可能付費的那群人。
  拿一個不會發生的風險，換一個一定會發生的損失。

考慮 AGPL 的唯一理由是**它走得回來**：唯一的著作權人隨時可以放寬成 MIT，反過來不行。這個
理由被上一段推翻了——如果程式碼真的不值錢，就不存在「哪天想收緊」的那個未來。

frond 維持 MIT 不動。兩邊一樣不是偷懶：**函式庫非寬不可，應用程式可寬可不寬**，這裡剛好
兩個都選寬。

## MIT 放掉、而且不該用授權去補的那一件事

任何人可以拿去改成「偷偷把書送到別處」的版本、掛出來、不公開改動。這傷不到生意，但可能傷到
「Spine」這個名字。

**解法是名字，不是授權**：README 寫明 `app.folis.ink` 是官方唯一的託管服務。

## 貢獻：講一次，寫在看得到的地方

開源與收費會同時打開三個入口，欠的東西完全不同：

| 入口 | 欠什麼 |
| --- | --- |
| GitHub issue / PR | 開源帶來的道德義務——模糊、沒有上限 |
| 付費使用者的信 | 契約義務，硬的，該履行 |
| 功能請求 | 最危險：它不是工作，是未來所有工作的來源 |

**只有第二項有義務。** 第一項的音量遠大於第二項，混在一起的下場是付錢的人等最久。

第一項要**白紙黑字放棄**，不能靠默默不回——默默不回的代價更高：會愧疚、然後在錯的時間回、
然後更累。誠懇的形狀是**講一次、寫在看得到的地方**，不是每封信都認真解釋；之後貼連結不是
敷衍。

功能請求一律導向一份公開的路線圖。「這件事在不在路線圖上」比「你覺得這個功能怎麼樣」好回
一百倍。

GitHub 的 issue 功能**現在不關**，因為維護者自己的工作台就在上面（見
[docs/agents/issue-tracker.md](../agents/issue-tracker.md)）。保留將來關掉的權利。
