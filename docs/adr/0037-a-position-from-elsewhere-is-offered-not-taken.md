# 別處的位置是拿來問的，不是拿來套的

日期：2026-08-25。

## 決定

同一本書在別的地方讀到別的位置時，Tidemarks **問讀者要不要移過去**，而不是自己移。

〈閱讀位置〉的合併規則**不改**：還是 last-writer-wins，還是按 `lastReadAt` 比，**不改成
furthest-wins**（「進度只進不退」）。加上去的是閱讀器裡一條浮在書上的橫幅，兩個答案：「移過去」
與「留在這裡」。

伴隨的三件事，因為少了任何一件這個決定就不成立：

| | 決定 |
| --- | --- |
| **什麼時候問** | 遠端那筆比較新，**而且**它的點落在本機當前那一屏的範圍之外 |
| **橫幅怎麼消失** | 只有按下其中一顆按鈕。不自動消失，翻頁也不會讓它失效 |
| **「留在這裡」做什麼** | **寫一筆本機當前位置**（`lastReadAt` = 現在） |

## 為什麼不是 furthest-wins

「進度只進不退」這個做法很多閱讀器在用，而且它有一個真的好處：不必問，不必畫橫幅，不必處理兩顆
按鈕之後的狀態。

它的代價是**把翻回去重讀吃掉**。讀者在 A 裝置往回翻十頁重讀一段，然後拿起 B 裝置，furthest-wins
會把他送回還沒重讀之前的那一頁，而且不會說。那不是同步失誤，那是這條規則本來就規定的行為，而它
規定錯了：翻回去是讀者做的一件事，不是一次意外。

`merge.ts` 早就選過這一次。它的註解寫著「deliberately not furthest-wins, so『flip back and
reread』is respected」，那句話今天仍然成立，這支 ADR 沒有推翻它，是替它補上它一個人做不到的
那一半。

## LWW 一個人做不到的那一半

LWW 比的是「誰後寫」。這對兩台**輪流**在讀的裝置是對的，但對一台**開著沒關**的裝置不是：

1. B 在第 3 章開著這本書，切去別的 app，分頁沒關。
2. A 讀到第 7 章，推上 server。
3. B 切回前景 → 同步把第 7 章寫進 B 的本機資料庫。
4. **畫面上還是第 3 章**：閱讀器只在開書那一刻問過一次位置。
5. B 翻一頁 → 寫下第 3 章的新位置，`lastReadAt` 是現在，比 A 那筆晚 → **A 讀的第 7 章沒了。**

第 5 步在 LWW 的規則裡完全正確，B 確實是後寫的那一個。錯的是第 4 步：**B 的「後寫」不是讀者的
意思，是一台不知道自己過期了的裝置的意思。** 補的就是這件事：讓那台裝置知道，然後讓讀者說話。

## 三件伴隨的事，各自為什麼非有不可

### 用「屏」當門檻，不用百分比

A 只往前翻兩頁就跳橫幅是噪音。但「差多少才算多」用百分比回答不了，同樣 1%，在一本小說裡是三頁，
在一本字典裡是三十頁。

本機答得出更好的版本：位置那一筆存著 `pageRange`，也就是**當時那一屏涵蓋的範圍**。遠端那個點落在
裡面就是同一頁，不必問。這不是一個挑出來的數字，是讀者眼睛看得到的那個範圍。

`pageRange` 是 `null` 的時候（整頁圖，或那列寫在這個欄位存在以前）退回比**印出來的整數百分比**，
橫幅上寫的就是那個整數，會顯示同一個數字就沒有東西好講。它比較粗，而那正是沒有屏可比的誠實
結果。

### 橫幅不自動消失

它握著的東西有時效：同步已經把遠端那筆寫進本機資料庫了，而 B 的下一次翻頁就會蓋掉它。橫幅自己
淡出、或翻一頁就消失的話，讀者去泡杯咖啡回來，那個位置已經不在了，而他從頭到尾沒有機會回答。

所以遠端那筆**存在閱讀器的 state 裡**，橫幅活到被回答為止。這也是為什麼不用改 LWW、不用加鎖：
真正的問題只有「還沒回答就翻頁」，一份記憶體裡的副本就解決了。

### 「留在這裡」是一次寫入

這一條最容易漏掉，漏掉之後那顆按鈕會變成假的。

橫幅出現的時候，遠端那筆**已經在本機 Dexie 裡了**，是同步寫進去的，橫幅只是在講這件事。只把
橫幅關掉的話，讀者關掉分頁再開這本書，`recallPosition` 取比較新的那筆，就會開在別處那個位置，
**跟他剛剛按的那顆按鈕講的話相反**。

所以「留在這裡」寫一筆本機當前位置，`lastReadAt` 是現在。它跟翻一頁做的是同一件事，也就是說
「留在這裡」在資料上的意思是「我現在人在這裡」，本來就該是這個意思。

## 代價

- **多一個要回答的東西擋在書前面。** ADR-0020 說介面要退到書後面，而這是唯一一個讀者沒叫它、
  它自己出現、而且不理它就不會走的東西。理由是它握著的資料會過期，但這條例外從此存在了，下一個
  想加常駐提示的人會拿它當前例。
- **橫幅在 chrome 收著的時候，上面留著一條 bar 的空白。** 它排在 chrome 的 grid 裡固定的一列，
  所以升起 chrome 不會推到它、收起 chrome 也不會有東西滑過它，換到的是「永遠在同一個位置」，
  付的是〈讀〉狀態下那一段空隙。
- **「多久以前」會過期。** 讀數在橫幅出現那一刻取一次，不掛計時器（`lib/elsewhere.ts` 的
  `ponytail:` 註解記著這個天花板）。橫幅擺一小時的話它還寫著「5 分鐘前」。
- **講不出是哪一台裝置。** 位置裡沒有裝置身分，要有就得多一張表加一頁設定（取名、列表、刪除）。
  文案因此只能寫「別的地方」，而讀者心裡想的是「我的 iPad」。這是刻意先不做的，資料結構沒有擋住
  之後補。

## 替代方案

- **furthest-wins**：見上，吃掉重讀。
- **開書時才問**：漏掉這支 ADR 唯一在講的那個情境（書已經開著）。
- **不問，但把別處的位置留成一個書籤**：讀者要自己想起來去找它，而這件事的性質是「你可能正要在
  錯的地方繼續讀」，那不是一個可以晚點再看的東西。
- **加一顆「檢查同步」按鈕**：把偵測的責任丟回給讀者。切回前景本來就會同步，缺的從來不是那次
  同步，是沒有人把結果講出來。
