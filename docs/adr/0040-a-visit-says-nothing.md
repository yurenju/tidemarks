# 回訪模式在畫面上不出聲

日期：2026-08-28。

## 先講現在是怎麼運作的

讀者從書架的〈回訪卡〉點一條畫線，或在閱讀器的〈筆記〉面板點一條，書會跳到那條畫線的位置。這個時候
他原本讀到的地方不能被蓋掉，所以有〈回訪模式〉：在那段期間翻頁不更新進度，讀過原本那個位置才恢復
（`packages/app/src/lib/visit.ts`、CONTEXT.md 〈回訪模式〉）。

到這份 ADR 為止，進入回訪會在書上升起一條橫幅：「你讀到〈第七章〉33%」，加〈移過去〉與〈留在這裡〉
兩顆按鈕。那條橫幅本來是為另一件事做的：**別台裝置同步過來的新位置**
（[ADR-0037](0037-a-position-from-elsewhere-is-offered-not-taken.md)）。回訪借用了它，理由是
「同一句話、同一組答案，讀者要做的決定一模一樣」。

## 問題

**那條橫幅在直排書上會把整頁都變成不能讀。**

它是一條橫的卡片，貼在頂端工具列那一列的下面。橫排書被蓋掉的是最上面幾行，眼睛從下面接著讀還連得
起來；直排書每一行都是從上往下走，所以一條橫的卡片會把畫面上**每一欄都攔腰切斷**，一行完整的都
不剩。

在手機上它還特別大：卡片本身量到 103–132px（`packages/app/src/styles/reader.css` 裡的數字），佔
393px 寬螢幕的五分之一，而它上面還有一個工具列的高度。工具列收起來的時候那一列是
`visibility: hidden`，**位子還在、只是看不見**，所以卡片不是貼著螢幕上緣，是浮在文章中間。

## 決定

**回訪不再升起任何東西。** 進入回訪只設 `visitRef`，畫面上一個字都不多。那條橫幅回到只有一個來源，
就是同步過來的位置。

**因為兩個來源要做的事其實不一樣**：

|  | 同步過來的位置 | 回訪 |
| --- | --- | --- |
| 讀者知道自己怎麼到這裡的嗎 | 不知道，是別台裝置寫的 | 知道，三秒前自己點的 |
| 不理它會怎樣 | 下一次翻頁就把那筆蓋掉，**而且救不回來** | 什麼都不會怎樣，狀態只活在記憶體裡 |
| 值得打斷閱讀嗎 | 值得 | 不值得 |

同步那條留著不動，它擋的是真的會掉資料的情況。

## 代價

**回不去最新進度的那一鍵沒了。** 替代路徑是退回書架再點一次那本書：回訪期間進度沒被寫掉，正常開書
就會開在最新的位置。三步，通的。

**畫面上不再有任何線索說「你現在不在最新進度」。** 情境是：進度在 47%，點回訪卡跳到 6%，從 6% 讀到
30% 就關掉，下次打開回到 47%。這正是回訪模式要的行為，但讀者會覺得進度掉了。
[#110](https://github.com/yurenju/tidemarks/issues/110) 要在定位軸上標一個記號補這個缺口。這一版先
不做，是想先看看少了橫幅之後這件事實際上有多困擾。

**〈Stay here〉變得幾乎按不到。** 它是全 app 唯一能讓進度往回走的動作，現在只有在同步的橫幅剛好站著
的時候才按得到。要把進度定在早一點的地方，剩下的路是用定位軸或目錄跳過去讀。

## 考慮過但沒有選的

- **把書縮小、讓橫幅有自己的位子。** 不遮字，但出現與消失各要重排一次版，那正是整層 chrome 在避免的
  事（[ADR-0020](0020-the-interface-steps-behind-the-book.md) 的延伸：問你在哪不該把你移走）。
- **只在工具列升起的時候顯示。** 幾乎不用寫東西，也保住了回去的入口。沒選是因為它把一個「不值得打斷」
  的提示留在畫面上，只是換個時機出現；真的需要一個回去的入口的時候，記號的代價比橫幅小（#110）。
- **跟著書的方向擺**（橫排放下緣、直排放左緣）。版面對了，但要維護兩套，而且直的卡片塞兩顆按鈕不好
  看。真正的問題是這個提示該不該存在，不是它擺在哪。
