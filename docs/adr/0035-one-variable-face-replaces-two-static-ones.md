# 一支可變字型取代兩支靜態字重

日期：2026-08-24。

## 決定

Tidemarks 自帶的 CJK 字型，從**一種字型兩支靜態檔**（Regular 400、Bold 700）換成**一種字型一支
可變字型**。

讀者選了字體之後，那支可變字型被兩條窄的 `@font-face` 釘在兩個字重上：

| 〈字體〉設定 | `font-weight` descriptor | 效果 |
| --- | --- | --- |
| 書籍預設 | 一條，整條軸（黑體 `100 900`、明體 `200 900`）| 書寫什麼畫什麼 |
| 黑體 | `300 300` ＋ `600 600` | 內文 300、粗體 600 |
| 明體 | `300 300` ＋ `800 800` | 內文 300、粗體 800 |

`weightRange()` 沒有了。它做的事（把 500 以上歸到粗體）改由 frond 重述書自己的宣告，登記為它的第
六條 `reader-blocked` 介入 `quantise-font-weight`（frond ADR-0003 的修訂）。

## 為什麼

### 一般字重與粗體的差距不夠大

量到今天是明體 1.37×、黑體 1.42×（墨水總量的倍率）。換上新的兩個字重之後是 **1.56×** 與 **1.74×**
（[measurements.md](../specs/cjk-web-font/measurements.md) 第十四節）。

**內文那一半才是增益的主要來源。** 這件事違反直覺，而且量出來才知道：黑體把內文從 400 降到 300 是
+23%，把粗體從 700 加到 900 而內文不動只有 +14%；黑體 400/600 甚至是 **−9%**，比今天更糟。原因是
Noto Sans CJK 在 300 到 400 之間有一個大跳。

黑體 600、明體 800 的不對稱是刻意的：黑體筆畫等粗，早一階就分得出來；明體筆畫有粗細對比、字腔小，
要到 800。

### 那兩個字重沒有現成的靜態檔

Source Han 出貨的字重跳過黑體的 600 和明體的 800。所以要那兩個值，只有兩條路：從可變字型切靜態實例，
或直接帶可變字型。**兩條都拿得到那些字重**，所以「用可變字型」不是必要條件，它是被下面這件事選中的。

### 可變字型比兩支靜態小 43%

| woff2 | 兩支 static | 一支 VF | |
| --- | --- | --- | --- |
| 明體 | 32.93 MB | **18.83 MB** | 省 14.10 |
| 黑體 | 22.46 MB | **12.86 MB** | 省 9.60 |

這**推翻了 spec 原本的結論**。`measurements.md` 當時寫「Variable font 不划算」，那是拿 **OTF** 比出來
的，而 VF 的 woff2 那格標著「未量」。兩支 static 各帶一整套完整輪廓、只能各壓各的（壓縮率 68%）；
VF 帶的是一套輪廓加上差分，而差分壓到 34–42%。壓縮之後方向相反。

repo 裡的字型檔也跟著從 55.4 MB 降到 31.7 MB。

## 「500」這一格，以及為什麼要動到 frond

窄範圍宣告會夾住可變字型的 wght 軸（CSS Fonts 4 §4.6），三家實測成立。但匹配規則有一個結構性的
缺口：請求落在 400 到 500 之間時「**先往上找到 500 為止，再往下找**」，所以請求 400 和請求 500 走
同一條路，都落到內文那條 face 上。

**只有剛好 500 這一格會錯**（450、499 落到內文是對的；501 以上落到粗體）。而它**在 CSS 這一層補不
起來**：中間補一條 `500 500` 會被請求 400 先抓走，內文整個變成 500，這也實測過。

所以改由 frond 重述書自己寫的字重。app 做不到這件事，因為書在 iframe 裡，外面的樣式表碰不到書裡
一個字（frond ADR-0006）。**值由 app 決定**（哪兩個字重、界線在哪），套用到書上由 frond 執行，跟
app 傳 `genericFamilies` 與暗色主題三個顏色給 frond 是同一個模式，frond ADR-0002 那條線沒有被跨過。

`font` 簡寫也蓋得到，做法是**追加一條長寫法而不是重寫簡寫**。frond 既有的兩個缺口（字級與泛用字族
不碰簡寫）理由是「拆開重寫會把宣告寫壞」，而追加不拆開任何東西：讀不出來就什麼都不加。三家十個案例
實測，含 `italic`、`/1.2` 行高、`small-caps`、`!important`，簡寫的其他部分完全沒被動到。

## 代價

### 沒有「先讀起來」那個中間狀態了

以前 Regular 排在 Bold 前面是刻意的：拿到第一支的讀者已經在用對的字讀了，第二支到了標題再重畫。
一支檔案就沒有這個中間狀態，全部到齊之前一個字都套不上。

明體從「15.94 MB 就能開始讀」變成「要等 18.83 MB」，**開始讀慢約 18%**；全部到齊從 32.93 MB 變
18.83 MB，快 43%。這是這個決定裡唯一真的變差的東西。

### frond 多了一條介入

那份清單刻意讓加東西有摩擦，而這一條的 `why` 必須誠實：**它是我們自己選了可變字型才產生的需求**，
不是書擋住讀者，切靜態實例就完全不需要它。它通過門檻的理由跟 `theme-colors` 同一條：讀者選了那個
字體，那個系統只有兩個字重，而一個讓強調變得看不見的書寫值，harm 的類別跟「在選定的底色上讀不到的
文字」是同一種。

### 讀者裝置上的舊檔要清

每一台曾經下載過字型的裝置，都存著兩支舊的靜態檔（黑體 22 MB、明體 33 MB），key 是舊的
`family/weight`。這些**刪掉**，不是留著忽略。ADR-0004 的「資料可以丟」講的是我們的資料庫；佔著別人
手機 33 MB 是另一回事。

### 黑體那支可變字型帶著 Reserved Font Name

`NotoSansCJKtc-VF` 的 copyright 是 `© 2014-2021 Adobe, with Reserved Font Name 'Source'.`，而同一家
的靜態檔沒有這一句。保留的名字是 `Source`，我們註冊的是 `Noto Sans CJK TC`，所以轉檔與散布都在 OFL
授權內，但 spec 第七節原本那句「改名都在授權內」對這支不成立，已經更正。

## 被否決的替代方案

**從可變字型切兩支靜態實例。** 拿得到同樣的字重、`weightRange()` 一個字不用改、500 完全正常（靜態
face 的宣告範圍只是匹配標靶、不夾任何東西），而且不必動 frond。**代價是整個 43% 的體積優勢都沒了**，
切出來的兩支實例還是 22.5／32.9 MB。這是最接近的一條路，值得記著：如果哪天 frond 那條介入被判定
不該存在，退回這裡就能拿回全部的字重效果，只是不省體積。

**`font-variation-settings` 當 `@font-face` descriptor 用。** 這是最直接的釘法。**Safari 完全不支援**
（MDN browser-compat-data：`version_added: false`，`safari_ios` 鏡射），而 iOS 上每一個瀏覽器都是
WebKit。而且它壞得很安靜：不支援就被忽略，字照樣顯示，只是字重不對，iPhone 讀者拿到 400/700 而其他
人拿到 300/800，正好違反 ADR-0014 的整個目的。

**內文留在 400，只加重粗體。** 不製造任何回歸（500 的行為跟今天完全相同），但換到的太少：400/800
兩種字型都只有 +5%，而配上原本挑的 600 兩種都比今天更糟（明體 −12%、黑體 −9%）。整張表在
[measurements.md](../specs/cjk-web-font/measurements.md) 第十四節。
