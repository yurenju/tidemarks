# UX 重新規劃：介面退到書後面去

> **這份 spec 描述的是底下三個工作項目當時做出來的樣子，其中排版與〈設定〉那一段已經不算數了。**
> [ADR-0026](../../adr/0026-the-reader-adjusts-their-own-reading-not-this-book.md) 把排版收成
> 一層、把〈設定〉從抽屜改成一層樓（`#/settings/typography`、`#/settings/account` 兩個 tab），
> 所以底下的路由表、「閱讀器留四項覆寫」、「以後每本書都這樣排」與〈裝置預設〉這個詞都已經過期。
> 其餘各段（書架、chrome 的三個狀態、Scrubber）不受影響。


狀態：已對齊，未實作。對齊日期 2026-08-12。基準：`main`（`Library.tsx`、`Reader.tsx`、`Scrubber.tsx`、
`AuthPanel.tsx`、`CONTEXT.md`）。

這份文件是**決定**，不是提案。用詞照 [CONTEXT.md](../../../CONTEXT.md)，那份表是上游；這一輪新定的
〈chrome〉與〈抽屜〉已經寫進去了。決定背後的取捨在
[ADR-0020](../../adr/0020-the-interface-steps-behind-the-book.md) 與
[ADR-0021](../../adr/0021-accessibility-is-borrowed-not-written.md)。

工作項目三件，見底下〈三個工作項目〉：兩個抽屜、閱讀器 chrome、書架第一屏與「還要多久」。
另外還有「連上的 agent」那一面，**不在這一輪**。

## 根因

功能面已經足夠，缺的是秩序。這個 app 有四件事要做（讀書、管書、調這台裝置、管伺服器那一半），
它們現在擠在兩個畫面裡。三個症狀（閱讀時介面太吵、匯出匯入像 debug 按鈕、書架答錯問題）是同一個
根因的三種長相：**每一層都常駐，因為沒有人負責決定「這一刻讀者在做什麼」。**

## 新的資訊架構

四個面，每個面只答一個問題。答不出來的東西就不屬於那一面。

| 面 | 它答的問題 | 裡面有什麼 | 明確不放什麼 |
| --- | --- | --- | --- |
| 書架 | 接下來讀哪一本？ | 正在讀的那一本（大）、封面牆、拖放加書、排序 | 登入、同步狀態、整櫃匯出、build 編號 |
| 閱讀 | 現在這一頁寫了什麼？ | 預設只有字；叫出來才有 chrome | 帳號、〈裝置預設〉六項 |
| 設定 | 這台裝置上，書該長什麼樣？ | 〈裝置預設〉六項、自帶字型狀態、build 編號 | 任何跨裝置的東西 |
| 帳號 | 伺服器那一半，我要不要？ | 免費／付費界線、登入、同步、訂閱、匯出備份 | 排版設定 |

**介面語言不在〈設定〉這一輪的清單裡。** `lib/language.ts` 的 `UI_LANGUAGE` 今天是常數 `zh-Hant`，
放一個切不動的項目比不放更糟。那一項等語言切換自己做（見 `CONTEXT.md` 的〈書名排序〉）。

導覽：〈書架〉是家。〈閱讀〉從書架進、從書架出。〈設定〉〈帳號〉〈書的詳情〉是**抽屜**，疊在當前
畫面上，不是分頁。

## 路由

底層兩條不變，抽屜寫成 hash 的 query 段。

| hash | 底下是什麼 | 抽屜 |
| --- | --- | --- |
| `#/` | 書架 | 無 |
| `#/book/<id>` | 閱讀器 | 無 |
| `#/?d=settings` | 書架 | 設定 |
| `#/?d=account` | 書架 | 帳號 |
| `#/?d=about/<id>` | 書架 | 書的詳情 |
| `#/book/<id>?d=settings` | 閱讀器 | 設定 |
| `#/book/<id>?d=about/<id>` | 閱讀器 | 書的詳情 |

抽屜是疊上去的，所以底層路徑不變，query 段只答「現在開著哪一個抽屜」。走路徑尾段的話每個抽屜會有
N 條路由（N 是底層畫面數），加一個底層畫面就要補一輪。

詳情抽屜**一律帶完整 bookId**，即使底層已經是同一本書（`#/book/abc?d=about/abc`）。冗餘的那幾個字
沒有人在看，換到的是「讀 hash 的程式不必看底層是誰」。

`bookIdFromHash()` 只要先切掉 `?` 以後的部分就繼續成立。

## 閱讀器：三個狀態取代五個常駐層

狀態機的定義在 CONTEXT.md〈chrome〉，這裡只寫要動的東西。

### 點擊分區

- 畫面**下方三成**分左右兩半等於上一頁／下一頁。
- 其餘（中間與上方）任何一處輕觸一次，把整組 chrome 叫出來。不做兩段式、不留常駐細線。
- **桌機的滑鼠點擊叫出 chrome，而且不分區。** 滑鼠本來就不翻頁，那一半語意是空的。左右箭頭與
  方向鍵不變。

分派住在 `touch.ts` 的 `tapAction()`：回傳型別從 `"next" | "prev"` 變成三值，Navigator 收到第三種
就往上丟一個 callback。三成線只有一份真相，兩邊才不會算出不同的邊界；Navigator 不必知道 chrome 是
什麼，它只回報「這一下不翻頁」。

### `preventTapDefault()` 不必動

replan 的初稿寫著「要補上位置條件」，那是誤判。[navigator.ts](../../../packages/app/src/lib/navigator.ts)
的 `preventsTapDefault()` 現在是 `return turnsPageByTap(e)`，**本來就不看位置**，中間帶一直都在擋。
新分區底下每一處 tap 都有動作（下方翻頁、其餘叫 chrome），沒有死區，所以取消預設動作在兩邊都是對的。

`tap.spec.ts` 已經斷言 0.9／0.6／0.3 三個位置都 `cancelled`，那條測試照原樣就是新行為的守門。

### 要改寫的那條測試

`tests/browser/reader/tap.spec.ts` 有一條斷言「中間點也前進」，那是當初把整個畫面都做成翻頁區時
留下的守門。它要改寫成「中間點叫出 chrome、不翻頁」，
而下方三成的左右各補一條。

### 誤觸不做自動退場

chrome 出現後**只靠翻一頁或再輕觸一次收掉**，不加計時器。看不見的計時器會在讀者正翻目錄找章節時
把東西收走，那比誤觸更難受。誤觸的代價只有一次多餘的 tap。

**但要量**：這一塊收尾時在真機上用實際的書滑十分鐘，數誤觸次數，寫進 `measurements.md`。每 50 次
翻頁誤觸超過 5 次，就回頭考慮把翻頁帶放大到下方一半。

### 〈找〉狀態的版面

> **這一段的三個決定在 2026-08-18 被推翻了兩個半**，改寫在下面的〈2026-08-18：chrome 第二輪〉。
> 「Scrubber 恆在」現在**只適用桌機**；桌機的側欄回來了，而且會把書推窄。留在這裡的是當初的理由，
> 因為推翻它們的那一輪是拿這些理由去比的。

- 頂：回書架、書名、章節。
- 底：一排按鈕（目錄、筆記、這本書的排版）加 **Scrubber，而且 Scrubber 恆在**。點按鈕升起的浮層
  停在 Scrubber 上方，不蓋住它。

Scrubber 跟目錄答的是同一個問題的兩種問法（「我要跳到哪」），拿走一個去用另一個，等於逼讀者記住
剛才瞄到的百分比。

**桌機的側欄收掉**，一律走底部浮層。兩套版面就是兩套 bug，而〈找〉狀態下讀者本來就不是在讀，浮層
蓋住內文沒有損失。

### 〈找〉狀態下不翻頁

底部三成整個讓給底列，不接受翻頁 tap。〈找〉狀態下翻一頁換不到什麼（讀者剛叫出介面就是為了跳），
而誤觸 Scrubber 會把人丟到書的別處，且沒有「回到剛才」。只擋底列實際佔到的高度的話，邊界落在哪一
個 pixel 讀者感覺不到，那是最難查的一類 bug。

### 設定面板拆成兩半

- 閱讀器裡只留「這本書」的四項覆寫（字型、字級、行距、留白）與「設為所有書的預設」。
- 〈裝置預設〉六項移進〈設定〉抽屜。
- 閱讀器裡放一個入口直接開〈設定〉抽屜（`#/book/<id>?d=settings`）。

最後那一條是必要的，不是方便：CONTEXT.md〈書的覆寫〉寫死了主題與欄數不可覆寫，所以讀者躺下來想切
深色，沒有這個入口就得先退回書架。

## 2026-08-18：chrome 第二輪

第一輪做出來的東西拿去對著 54 張全畫面截圖看了一遍，外加一份外部設計 handoff 的判讀。
**只收下 handoff 裡今天還成立的部分**：它有一半建立在已經被推翻的前提上——輕觸下方三成翻頁
（[ADR-0024](../../adr/0024-turning-a-page-is-a-swipe-and-nothing-else.md) 拿掉了 tap 翻頁）
與「這本書的排版」（[ADR-0026](../../adr/0026-the-reader-adjusts-their-own-reading-not-this-book.md)
把排版收成一層）。它另外兩項提案（直排翻頁鏡射、手機 chrome 不推內文）當時就已經做完了。

### 桌機：面板改成右欄，而且推書

〈排版〉的六項是即時套用的，而面板從左邊蓋住內文、外面再壓一層 scrim，等於**讀者在調的東西正好
是被蓋住的那個**。ADR-0026 選擇把面板放在閱讀器裡的理由就是「上面留著真的書當預覽」，而實作沒有
兌現那句話。

所以：**面板變成右側一欄，書往左縮，scrim 拿掉。**

**推書而不是蓋書，是這一輪唯一一個推翻自己理由的決定。** 原本不推的理由是「窄一點就要重新分頁，
問你在哪反而會把你移走」。那句話對〈目錄〉成立，對〈排版〉不成立——**調字級本來就會重新分頁**，
而看不看得到結果是它唯一的價值。兩個面板兩種行為就是兩套 bug，所以三個面板一起推，代價由〈目錄〉
與〈筆記〉付：開關一次會重新分頁一次。

**如果那個代價在真機上難受**（翻目錄找章節，關掉之後頁碼變了），退路是把〈目錄〉與〈筆記〉改回
覆蓋、只讓〈排版〉推。那時要一起接受的是兩套版面。這件事要在收尾驗證時實際跑一遍再判。

面板在右邊還順手修掉一個 bug：它原本在左邊，用的是預設的右下投影，那個**向下**的分量會穿出書的
框、落在 Scrubber 那條上——一個站在 bar **旁邊**的東西，卻把影子投在它**下面**。

**從右邊進來的面板往左投**（`--shadow-panel-left`，既有的 token），沒有向下分量。它往左投到的是
書，以及兩條 bar 收在面板左緣的那個端點——那兩處是真的在它底下（面板整欄從上到下，疊在 chrome
之上），所以投在那裡是對的。**消失的是「投在自己旁邊那條 bar 上」，不是「完全不碰到 bar」。**

### 桌機：頂列併成一排，章節下放 Scrubber

原本是 52px 的「書架／書名／章節／⋯」加一排「目錄／筆記／排版」，兩排都半空。併成一排。

併完之後書名與章節搶同一行，**留書名**：頂列答的是「這是什麼書、我能做什麼」，
**「我在哪」整個交給底部那一行**——章節名與 Scrubber 是同一個問題的兩種說法，本來就該長在一起。
手機同一條理由，只是那邊本來就塞不下兩個。

`⋯`（書的詳情）跟著三個入口走，不留在書名那一格：它是入口，不是標題。

### 手機：sheet 打開就收掉另外兩層

sheet ＋入口列 ＋ Scrubber 三層疊起來，書只剩最上面 25%，而且六列的表單自己還被切掉兩列。

**sheet 站著的時候，入口列與 Scrubber 一起退場。**〈找〉狀態的「Scrubber 恆在」因此改成**桌機
限定**：那條規則的理由是「拿走 Scrubber 去換目錄，等於逼讀者記住剛才瞄到的百分比」，而手機上
兩個都要的結果是**兩個都看不清楚**。叫出〈排版〉的那一刻讀者要的是看見改動，不是知道自己在哪；
上方留下的四成是沒有 scrim 的真書，那才是這個面板待在閱讀器裡的理由。

sheet 因此也不再需要停在 Scrubber 上方，高度上限（`min(60vh, 29rem)`）跟著鬆綁一階——那一筆的
債就是在這裡還掉的。

### 樣式細節

| 項目 | 決定 |
| --- | --- |
| 低選項數的設定 | 主題、欄數、字型、留白改 segmented（選中＝實心綠底）；**行距留 `<select>`**，六項而且標籤長 |
| 桌機翻頁箭頭 | 整條帶給一個 hover 底，不再只換一個字元的顏色 |
| chrome 的 ghost button hover | 從 `--surface-sunken` 換成 `--surface-cover`；前者對紙只差一階，看不出來 |
| 陰影 | 兩層（硬位移砍半＋短 blur），見 ADR-0022 的 2026-08-18 修訂 |
| 手機選字工具列 | 折行時分隔線從 `border-left` 改成整行的 `border-top` |

segmented 為什麼繞得過「6 個原生 `<select>` 不換」那條：**它不是 `Select`**。當初拒絕的兩個理由
（手機上原生 select 開的是作業系統選單、Base UI `Select` 有一條主執行緒凍死的 open issue）都是關於
「把選項藏起來、點開才看得到」的元件，而 segmented 把選項全攤在畫面上，一組 radio 而已。行距留著
`<select>`，正是因為它的六個長標籤攤不開——這條線畫在**選項數與標籤長度**上，不畫在元件庫上。

## 書架第一屏

- 正在讀的那一本大到不必挑：封面、書名、作者、兩行狀態、「繼續讀」。其餘退成一面封面牆（手機三欄、
  桌機五欄）。
- **這一屏在各個寬度下的實際尺寸另有一份**：[device-sizing/spec.md](../device-sizing/spec.md)。
  1280 起是兩欄（大書一欄 sticky、牆一欄），封面牆改成加欄而不是放大——那份文件寫的是同一個第一屏
  在不同裝置上的樣子，不是另一個第一屏。
- 排序邏輯不動（〈最近碰過〉已經對準「接下來開哪一本」）。
- 累計時長與場次不在第一屏。它們答的是回顧，收進〈書的詳情〉。

### 哪一本是「正在讀」

**有 `progress` 且未讀完的書，就挑最近碰過的那一本**，即使只讀了 1%。**一本都沒有**（全新，或全部
讀完）就不出現大書，整屏是封面牆。把一本沒翻開的書放大到半個螢幕像在催人。

挑的時候看的是 `lastReadAt`，不是〈最近碰過〉的 `max(lastReadAt, addedAt)`：今天早上匯入的書是書架上
最近碰過的東西，但它不是讀者讀到一半的那一本。

**「讀完」是 `percentage ≥ 0.99`**（`lib/book-status.ts` 的 `FINISHED_AT`）。不要求 1，是因為 epub
最後那一段是版權頁、廣告與譯後記，讀完書的人常常根本不會捲過去；要求最後那 1% 的話，讀完的書會一直
留在書架上當成沒讀完。這個數字跟下面三個門檻同一種性質，要調就改這裡。

### 兩行狀態的四種說法

沒話說就不說，不留空位。

| 情況 | 說什麼 |
| --- | --- |
| 讀過幾場，算得出速度 | 讀到第七章 / 大約還要 3 小時 |
| 第一場，還沒有速度 | 讀到第一章 / 才剛開始 |
| 從沒打開過（剛匯入） | 還沒翻開 / 剛剛加進來的 |
| 讀完 | 讀完了 / 八月三日 |

後兩列是給封面牆上的小卡用的。

### 「還要多久」怎麼算

在 `lib/stats.ts` **加函式**（那個檔案已經存在，裡面是 `totalReadingMs` 與 `formatDuration`）。

算得出來的前提是**每一場 session 要記下它從書的哪裡到哪裡**（`ReadingSession` 的 `startFraction`
與 `endFraction`），因為時間長度本身不是速度。同理，「讀到第七章」的章名記在 `Progress` 的
`chapterLabel`：章名要查目錄與 section 邊界，也就是要打開 epub，而書架一屏要畫二十本。兩者都只有
**當時開著那本書的那台裝置**知道，過了那一刻就算不回來。三個欄位都可以是 `null`（整書索引還沒建好
的那一場、以及這些欄位存在以前寫的列），而 `stats.ts` 把那種場次**排除在速度之外**，不是當成
「沒有前進」。

三個門檻，全部滿足才顯示：

- 至少 **2 場**已結束的 session
- 那些 session 的累計 fraction 位移 **≥ 0.02**
- 累計時間 **≥ 5 分鐘**

速度取**最近 5 場的總位移除以總時間**，不加權。「最近 5 場」這個窗本身已經是加權，老場次直接掉出去；
再疊一組權重，就是在沒有資料支持的情況下多一個旋鈕。

結果**無條件進位到 0.5 小時**（「大約還要 3 小時」「大約還要 3.5 小時」）。這個數字本來就不準，給到
小數點只會讓它看起來比實際可信。

門檻與窗都是要調的，所以它們住在 spec 不住在 ADR。調過就改這裡，並在 `measurements.md` 留下依據。

## 帳號：免費與付費的界線

界線本身：**書在瀏覽器裡跑，所以讀書不收錢；同步與 MCP 要燒別人的主機，所以那半邊收錢。**

畫面上的順序是先講免費，再列帳單，最後留「自己架」那條路。

- 第一句話：「讀書不必註冊。書、筆記、閱讀位置，一個位元組都不離開這台裝置。」
- 永遠免費：匯入、閱讀、劃重點、寫筆記、排版、匯出，都在你的瀏覽器裡跑。
- 要付錢：兩台裝置之間同步、讓 agent 讀得到你的書。
- 停掉之後：伺服器留 24 個月，這台裝置上的那一份不受影響（ADR-0011）。
- 收尾：不想付、又想要兩台裝置？同步那半邊可以自己架（〈退路〉）。

**書架上不放登入框。** 付費的邀請只出現在打開〈帳號〉抽屜的那一刻。agent 授權那條路不必放邀請，
沒註冊的人根本用不到 MCP。

**價格未定**，畫面上的數字是佔位，金流這一輪不做。

**上線前的唯一差別**：這一面就照上線版做。`OPEN_SIGNUP` 沒開的時候，寄登入碼那一步多一種結果，
不在白名單就顯示「尚未開放註冊」。開放之後這句話消失，訊息改成一律含糊。

**「連上的 agent」不在這一輪。** 那個畫面今天
不存在，需要 Worker 加 endpoint 與 D1 查詢。〈帳號〉的版面留一格給它。

## Base UI

引入 **`@base-ui/react`**（注意：`@base-ui-components/react` 已經 deprecated、凍在 `1.0.0-rc.0`），
版本範圍 `~1.7.0`。取捨見 [ADR-0021](../../adr/0021-accessibility-is-borrowed-not-written.md)。

### 用在哪裡

| 東西 | 動作 |
| --- | --- |
| 〈設定〉〈帳號〉〈書的詳情〉抽屜 | `Drawer` |
| 閱讀器的目錄、筆記、排版浮層 | `Dialog` 或 `Popover` |
| 6 個原生 `<select>` | **不換** |
| `Scrubber` | **不換**，但補 a11y |
| `toolbar-position.ts` | **這一輪不動** |

原生 `<select>` 留著，是因為手機上它開的是作業系統的選單，Base UI 的 `Select` 換不到那個；而且
`[select]` 有一條「開關時主執行緒凍死」的 open issue（mui/base-ui#5358）還沒關。

`Scrubber` 留著自幹，是因為它的語意是 commit-on-release、rtl 鏡射、索引沒建好就 disabled，那是政策
不是 slider。**要補的是 `role="slider"`（現在是 `progressbar`）、`tabIndex`、方向鍵**，那件事跟換不
換 library 無關。

`toolbar-position.ts` 不動，是因為 Base UI 的 `Popover` 要一個真的 DOM 元素當 anchor，而 highlight 的
anchor 是 frond 從 iframe 換算出來的矩形。要換得先做一個 virtual anchor，那是獨立的一件事。

### 硬性條件

**閱讀器裡一律不用 `modal={true}`。** 那會 render 一層 `position: fixed; inset: 0` 的攔截元素，並在
桌機上對 `<body>` 寫 `height: 100dvh; overflow: hidden`。兩件事都會跟翻頁手勢與 frond 的 `pointerup`
打架。用 `modal={false}` 或 `'trap-focus'`，那兩種都不 render 攔截層。

### 兩個容易漏的 setup

- app root 的 div 要 `isolation: isolate`，否則 portal 出去的浮層堆疊順序不保證。
- iOS 26+ Safari 要 `body { position: relative }`，否則 `position: absolute` 的 backdrop 蓋不滿
  visual viewport。

## 測試

**改用 `data-testid`**，kebab-case，名字取自 CONTEXT.md 的詞（`chrome`、`scrubber-track`、
`book-card`、`drawer-settings`）。現在的 spec 大量用 `.panel-backdrop`、`.settings-panel label`、
`.book-card .book-info strong` 這種選擇器，等於把版面結構當成契約，而這一輪必然全面打到它們。

不走純 role 定位，是因為好幾個東西**現在根本沒有正確的 role**（Scrubber 是 `progressbar`、toggle 是
帶 `.active` 的 button）。要靠 role 就得先把 a11y 補完，那會把兩件事綁在一起。先給 `data-testid` 讓
測試在重寫期間站得住，a11y 由 Base UI 那條路慢慢補。

動到 reader 就跑 `npm run test:container`（三家瀏覽器）。
