# 深色模式留下書自己的顏色

狀態：已實作。對齊與實作日期 2026-08-14。基準：`main`（`packages/frond/src/renderer/`）。

這份文件是**決定**，不是提案。它改的是 frond
[ADR-0003](../../../packages/frond/docs/adr/0003-css-authority-and-intervention-threshold.md)
的介入面在顏色這一項上做到多少，理由與取捨寫在 frond
[ADR-0014](../../../packages/frond/docs/adr/0014-a-theme-recolours-only-what-cannot-be-read.md)，
量到的數字在 [measurements.md](measurements.md)。

## 根因

深色模式下，書裡每一個字都是同一個顏色。

淺色模式不是這樣：Folis 的淺色模式**根本不給 frond 主題**，所以書的顏色一個字都沒被碰過，章名是
書設計的顏色、圖說比內文淡一階、強調的字是紅的。切到深色，這些全部變成讀者的墨色。

原因在 `readerStylesheet`：只要設了主題，它就寫下 `:root, :root * { color: 前景色 !important }`。
那一行是為了另一件真的事存在的，就是書寫死 `color: #000` 的時候深色模式會失效（ADR-0003 的實例表
有這一列）。它有效，代價是**連書刻意選過的顏色一起蓋掉**。

量過 34 本流通中的書之後，這個代價的大小是知道的：951 次 `color` 宣告裡，有 190 次在深色底上本來
就讀得到。今天這 190 次全部被蓋掉。

## 讀者看到什麼

深色模式下，**書自己的顏色留著，讀不到的那些才被換掉**。

- 章名、小標那種帶顏色的字，維持書設計的顏色。
- 圖說、註解那種調淡一階的灰，維持比內文淡，只是淡得剛好還讀得到。
- 內文的黑字變成讀者的墨色，跟以前一樣。
- 書拿深藍或深紅寫的強調字，變成同一個顏色的亮版本，看得出來仍然是藍的、是紅的。

淺色模式**完全不變**，它本來就不給主題。

## 規則

frond 拿到主題的時候，對書宣告的每一個 `color` 值做一次判定，順序固定：

1. **讀不懂那個值** → 不動。`inherit`、`transparent`、`currentColor`、`var(--x)`、`oklch()` 都在
   這裡。
2. **對比已經 ≥ 4.5** → 不動。這是 WCAG 對內文的標準，而 frond 分不出一段字是標題還是內文，所以
   用嚴的那一個。
3. **沒有色相而且很暗**（chroma < 0.15 且 HSL 亮度 < 0.25）→ 換成讀者的墨色。這是書的內文墨色，
   讀者的主題本來就是來接手它的。
4. **其餘**（有色相的，或是不那麼暗的灰）→ 保留色相與飽和度，只把亮度調到**剛好**過門檻。

對比算的是讀者背景色與這個值之間的 WCAG contrast ratio。半透明的值先跟讀者的背景合成再算，因為
那才是讀者真的看到的顏色。

讀者的墨色本身仍然寫在根元素上（`:root { color: … }`），書沒有宣告顏色的地方就繼承它，跟以前一樣。
差別只有一個：那條規則不再套用到每一個元素，所以書宣告過的地方輪得到書講話。

### 這條規則只碰 `color`

`background-color` 維持現在的做法：根元素是讀者的背景色，其餘一律 `transparent`。這是另一個問題，
不在這一輪。`-webkit-text-fill-color`、`text-emphasis-color`、SVG 的 `fill` 也不碰，34 本書裡出現
次數是 0。

### 連結顏色不變

讀者設了 `theme.link` 的話，連結還是讀者的顏色（`:root a` 的權重比書的 `a` 高）。沒設的話，書宣告
過的連結顏色現在會**留下來**（走上面同一套規則），而以前它會變成內文的顏色。這是同一件事的一部分：
書把連結畫成深藍，那是資訊，不是雜訊，把它提亮比抹平好。

## 不做的事

- **不做整體反轉**。把每個顏色的亮度翻過來會連讀得到的顏色一起改，跟這次要的正好相反。
- **不做「一律換成讀者的墨色」**。那是今天的行為，也是這張票要修的東西。
- **不展開 `var(--x)`**。要展開就要在 frond 裡跑一套自訂屬性的 cascade，而那是猜。代價記在
  [measurements.md](measurements.md)：34 本裡有 35 次宣告因此不會被處理，其中 30 次來自同一本書。
- **淺色模式不給主題**。這次的變更在淺色模式下影響是零。

## 怎麼知道有沒有壞

- frond 的 node 測試蓋顏色運算與 CSS 改寫（`color.test.ts`、`css.test.ts`、`settings.test.ts`）。
- frond 的瀏覽器測試蓋五種情形：內文黑字換成墨色、對比夠的彩色標題原樣留著、對比不夠的彩色字提亮、
  中灰圖說原樣留著、寫在 `style` 屬性裡的顏色走同一套規則（`reader-settings.spec.ts`）。
- 「對比夠的彩色標題原樣留著」是這次的重點，也是最容易在之後被改壞的一條。
