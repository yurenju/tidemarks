# Design system

怎麼分，加上值。**為什麼**長這樣在 [ADR-0022](adr/0022-the-interface-is-a-print-shop.md)，
**值本身**的正本在 [`packages/app/src/index.css`](../packages/app/src/index.css) 的 `:root`
（這份文件會過期，那個檔案不會）。詞的定義在 [CONTEXT.md](../CONTEXT.md)。

同一個畫面在不同寬度、不同指標型別底下長什麼樣**不在這裡**，在
[docs/specs/device-sizing/spec.md](specs/device-sizing/spec.md)。

要畫一個新畫面的時候，這份文件從〈怎麼判斷〉開始讀就好。

## 怎麼判斷

三個材質，照順序問：

1. **這是紙、墨、還是葉綠？**紙是容器（讀者改不動），墨是痕跡（讀者留下的），葉綠是可以動的。
2. **它拿得起來嗎？**拿得起來才有影子，而且影子的位移是硬的。
3. **手指會捏住它嗎？**會才是圓的。

第三題答「是」的東西目前只有三個：Scrubber 的 thumb、它的兩個端點、螢光色票。要加第四個之前先
回來改這份文件。

一屏上綠色的地方應該數得出來。超過三處，就有東西該退成墨。**數的單位是控制項，不是格子**：一組
segmented 的選中格跟它的控制項一起算一個綠，因為那塊綠說的是「這一格是現在的值」，不是「這一格
可以按」——整組都可以按。

## Token

三層：原色 → 語意 → 元件。**元件只引用語意層**，直接寫 `--paper-300` 的規則等於已經決定了一個
顏色要用來做什麼，卻沒說出來。

### 紙

| token | 亮 | 暗 | 用在 |
| --- | --- | --- | --- |
| `--surface-page` | `#faf7ef` | `#1a1815` | 底、抽屜、sheet、按鈕、欄位 |
| `--surface-sunken` | `#f5f2ea` | `#14120f` | hover、筆記卡、進度條的軌 |
| `--surface-cover` | `#ece7dc` | `#2a2721` | 封面（沒有封面圖時的底） |
| `--line-hair` | `#e4dfd2` | `#2f2c26` | 結構線：bar 的邊、小標的下緣 |
| `--line-firm` | `#ddd6c7` | `#35322b` | 控制項的邊：按鈕、欄位、封面、Scrubber 的軌 |
| `--line-actionable` | `#ddd6c7` | `#6f695d` | 暗色下**單獨站著**的可按邊（見下） |
| `--surface-raised` | `#f0efe6` | `#211f1a` | 按鈕的 hover；**閱讀器 chrome 的三條 bar**。「抬起來」的底，暗色沒有影子可用的時候 |
| `--surface-inverse` | `#1c1a17` | `#e8e3d7` | 只給浮動工具條，全站唯一反白的東西 |
| `--backdrop` | 28% | 50% | 浮層底下那層 |

暗色下色差、邊、影子三個訊號同時變弱，所以規則是：**單獨站著的可按物件一定有一條看得見的邊。**
「單獨站著」是關鍵——`.ghost` 從來不單獨站著，它永遠在一個已經有邊界的容器裡（bar、面板的頭、
確認框），容器本身就答完了「這裡可以按」。給它加邊的代價是確認框的取消鍵會變得跟旁邊那顆
`.danger` 一樣重，而那一格是刻意讓「不做」比「做」輕的。

暗色的 `--line-hair` 是 `#2f2c26`，不是設計稿的 `#2a2721`：那個值跟 `--surface-cover` 同色，
畫在封面上的細線會看不見。

### 墨

| token | 亮 | 暗 | 對紙的對比（亮） | 用在 |
| --- | --- | --- | --- | --- |
| `--text-primary` | `#1c1a17` | `#e8e3d7` | 16.2:1 | 標題、按鈕的字、書名 |
| `--text-body` | `#4d463e` | `#c9c2b4` | 8.7:1 | 內文（`body` 的預設） |
| `--text-muted` | `#6f675d` | `#9c948a` | 5.2:1 | 次要文字、小標、唯讀進度條 |
| `--text-faint` | `#a09788` | `#7d766c` | 2.7:1 | **不是文字色**：線、disabled 的圖示、佔位 |

`--text-muted` 比設計稿的 `#8a8278` 深兩階，因為那個值是 3.54:1，過不了 WCAG AA 的 4.5。
`--text-faint` 維持原值但**不承載字**：2.7:1 沒辦法拿來寫任何要讀的東西。

### 陰影

**兩層：硬的那層帶位移，糊的那層只化開邊。** 撐起「紙壓在紙上」的是位移與方向，不是邊要銳利到像
切出來的——真的紙壓在紙上，交界那一兩公釐本來就是散的（[ADR-0022](adr/0022-the-interface-is-a-print-shop.md)
的 2026-08-18 修訂）。

兩條限制，超過就不是這回事了：**blur 不得大於位移的兩倍，而且不准加 spread。** 過了那個比例，
影子會開始往四周均勻散開，那是點光源加空氣的樣子。而且**硬的那層要比糊的那層重**，不然主導的
就變成糊邊。

| token | 值（亮） | 用在 |
| --- | --- | --- |
| `--shadow-lift` | `2px 3px 0` 5% ＋ `2px 3px 4px` 3.5% | 封面、Scrubber 的 thumb |
| `--shadow-panel` | `6px 8px 0` 7% ＋ `6px 8px 12px` 5% | 確認框、螢光工具列、toast |
| `--shadow-panel-up` | `0 -6px` 同上 | sheet（從底下升起，所以往回打） |
| `--shadow-panel-left` | `-6px 0` 同上 | 抽屜（從右邊進來）、閱讀器的面板（同理） |

**影子往它來的方向打。** 沒有 `-right`，因為沒有東西從左邊進來了。

**bar、表單、唯讀進度條、封面牆的底沒有影子。**

深色主題等於沒有影子（近黑上面的黑位移看不見），那邊的「浮起來」是靠比較亮的表面說的
（`--night-700`）。值照樣是兩層，只為了不讓兩個主題各有一套規則。

### 字

`--font-ui: "Source Serif 4", "Noto Serif CJK TC", "Noto Serif TC", "Source Han Serif TC",
"Songti TC", "PMingLiU", serif`

拉丁那半是自帶的（`packages/app/public/fonts/`，variable，latin 與 latin-ext 兩個 subset 共
90 KB）。漢字那半走系統堆疊，名單跟 `lib/chinese.ts` 的 `SERIF_TC` 一樣，理由也寫在那裡
（重點：裸的 `serif` 在 Apple 平台上會落到 PingFang，那是無襯線）。

讀者如果為了看書下載過自帶明體，**下一次開 app** 的時候介面也會用它
（`lib/ui-font.ts`），中文粗體那時候起是真的 Bold 字形，不是瀏覽器合成的。不在下載完成的當下
換，因為讀者那一刻正盯著那個面板。

**一律 `rem`，不是 px。** `settings.ts` 的字級是讀者根字級的百分比（ADR-0006），所以讀者放大瀏覽器
字級的時候書會跟著長，而介面只有寫成 rem 才會跟著長。寫 px 的結果是書變大、介面顯得更小。

手機那一欄不是「小螢幕所以放大」，是**襯線漢字的量法**：漢字沒有 x-height、字身塞滿，宋體的橫筆
在 DPR 3 上靠灰階抗鋸齒會發灰。看的是字面方框，不是幾 px。切換條件是 `pointer: coarse`（主要指標
是不是手指），不是寬度，理由見 [ADR-0023](adr/0023-width-places-things-pointer-sizes-them.md)。

| token | fine | coarse | 用在 |
| --- | --- | --- | --- |
| `--type-display` | 1.875rem | 同左 | 還沒有畫面用到 |
| `--type-title` | 1.3125rem | 同左 | `Tidemarks`、大書的書名（另有 `clamp`） |
| `--type-lede` | 1rem | 1.125rem | 抽屜標題、確認框標題、〈帳號〉第一句 |
| `--type-body` | 0.9375rem | 1rem | 內文、目錄項、引用 |
| `--type-ui` | 0.84375rem | 0.9375rem | bar 上的字、label、清單 |
| `--type-note` | 0.78125rem | 0.875rem | 狀態行、註解、次要按鈕 |
| `--type-eyebrow` | 0.6875rem | 0.75rem | 小標（`letter-spacing` 跟著 `.16em` → `.14em`） |

**小於 1rem 的漢字不用 400 以下的字重，也不用 `--text-faint`。** 需要更淡就換更短的句子。

行高只有兩個：`--leading-text` 1.68（任何由句子組成的東西）與 `--leading-title` 1.3。中文需要
鬆的那個。所有會變動的數字吃 `font-variant-numeric: tabular-nums`（寫在 `body`）。

### 間距

`--space-1` 4 ／ `-2` 8 ／ `-3` 12 ／ `-4` 16 ／ `-5` 22 ／ `-6` 30 ／ `-7` 44。

`index.css` 裡還有一批 rem 寫的 padding 沒有換過來，**那是刻意的**：rem 跟著讀者的根字級走，
px 不會，整批換掉是在改一件無障礙行為，不是在整理格式。新寫的規則用 token。

## 元件的規則

### 按鈕：三階加一個紅

| | 長什麼樣 | 用在 |
| --- | --- | --- |
| `button`（裸的） | `--line-firm` 的邊、紙底 | 預設，其餘全部 |
| `.primary` | 實心 `--accent`、字 `--text-on-accent` | **一屏最多一顆** |
| `.ghost` | 沒有邊、沒有底 | 只在 bar 裡、關閉鈕（`✕`）、單一字元的鈕，以及確認框裡的取消鍵 |
| `.settings-tab` | 沒有邊、沒有底，開著的那一個在字底下畫一條 accent 的線 | 只有〈設定〉那一排 tab |
| `.danger` | 邊與字是 `--danger`，hover 才填滿 | 刪除 |

確認框的取消鍵是 ghost，而且放左邊：那一格要讓「不做」比「做」更容易走到，而一個有框的取消鍵跟旁邊的
破壞性動作看起來一樣重。

app 裡的 primary 只有三顆：〈繼續讀〉、〈寄登入碼給我〉、〈登入〉。〈排版〉的〈回到預設值〉刻意不是
primary：它會把六項全部推回去，不該長得像在邀請人按。（〈設為所有書的預設〉曾經是這一條的例子，
[ADR-0026](adr/0026-the-reader-adjusts-their-own-reading-not-this-book.md) 把它連同第二層一起
拿掉了。）（agent 授權那一頁的〈允許〉不在這裡——它由
`worker/authorize.ts` 自己吐 HTML 與自己那份 CSS，還沒吃這套 token，見 #136 的收尾。）

命中區看的是**有沒有一根粗指標**（`any-pointer: coarse`），不是視窗多寬：有的話 `--tap-min` 是
44px，沒有的話 32px（密集列表 28px）。觸控筆電因此拿到 44px，而桌機拿到更密的排版。理由見
[ADR-0023](adr/0023-width-places-things-pointer-sizes-them.md)，那支 ADR 也記著它推翻了什麼。

**唯一的例外是封面右上的 `⋯`**：它必須貼齊封面的角，44px 的方塊在手機上會蓋掉封面四分之一。解法
是**臉 26px、靶 44px**——`::after` 把可按範圍往左下撐開，蓋在封面的圖上但不畫任何東西。

### 欄位

圓角 0、`min-height: var(--tap-min)`、紙底、`--line-actionable` 的邊。`type="range"` 不進這個框
——滑桿沒有內部可以填，框住它等於在一條線外面再畫一個框。

錯誤只換邊框與 label 的顏色，不換底色。`.error` 是左邊一條 3px 的 `--danger` 加 `--surface-sunken`
的底，不是紅底粉框。

### segmented

**選項少又短的設定，就把選項全攤在畫面上**，不要藏進 `<select>` 裡點開才看得到。線畫在**選項數與
標籤長度**上，不畫在元件庫上：三到四個、每個一兩個字就用 segmented（主題、欄數、字型、留白）；
〈行距〉六個而且長得像「更寬鬆（2.0）」，攤不開，留 `<select>`。

- 一組共用一個外框，格與格之間一條 hairline（相鄰的邊互相收掉一個 pixel，讀起來才是一個控制項
  的幾格，不是幾顆剛好靠在一起的按鈕）。
- **選中＝實心 `--accent`**，不是底線。填滿禁得起被瞄一眼，也禁得起深色主題；一條 2px 的線在
  近黑面板上的 Song 體底下是看不見的。
- **整組 disabled 的時候選中格不上綠**，改用 `--surface-cover` 加 `--text-muted`。綠是「可以動」的
  顏色，一格按不下去的綠正是那條規則要擋的東西。
- 一組只有一個 tab stop（落在選中的那格），左右上下方向鍵換選項並帶著 focus 走。`role="radiogroup"`
  宣告出去就等於答應了方向鍵。

### focus

一般控制項：`outline: 2px solid var(--accent)` + `outline-offset: 1px`，外面再加一圈
`box-shadow: 0 0 0 3px var(--halo, var(--surface-page))` 當暈。

**那圈暈是一個洞，不是一個顏色**：它靠的是跟背後那張紙同色，所以焦點讀起來是一圈環，不是控制項
外面又多一個形狀。全站都是 `--surface-page` 的時候它可以寫死，ADR-0028 之後不行了——所以**背後不是
書頁的那張紙要自己報名**，在自己身上設 `--halo`。目前只有 chrome 那三條 bar 需要，而那裡正好是全
app 最常被鍵盤走到的四顆按鈕。

**封面例外**：底色是出版社說了算，綠框壓在深色書封上看不見。所以焦點畫在封面**之外**的紙上——
四個角的 L 形**裁切標記**，16px 長、2px 粗、離封面 7px（落在格線的 gap 裡，不會碰到鄰居）。
實作是 `::before` 加八道 `linear-gradient`，不是八個 span：那是裝飾，不該進 accessibility tree。

### 能拖與不能拖

同一個面板裡會同時出現字型下載進度與閱讀進度軸，**必須一眼分得開**。

| | 可拖曳（Scrubber） | 唯讀（進度條） |
| --- | --- | --- |
| 顏色 | `--accent` | `--text-muted`，**永遠不用綠** |
| 高度 | 觸控區 22px；rail 靜止 3px／hover 6px，coarse 永遠 6px | 固定 3px |
| 端點 | 起點實心、終點空心 | 無 |
| thumb | 14px 綠圓點 hover 出現；coarse 永遠在，22px | 無 |
| 互動 | `cursor: pointer`、可聚焦、方向鍵可動 | `pointer-events: none` |
| a11y | `role="slider"` | `role="progressbar"` |

唯讀進度條**不佔自己一列**，緊貼在它所解釋的那行字下面（4px）。算不出總量就滑一段，不要假造寬度。

守門的測試在 `packages/app/tests/browser/reader/draggable.spec.ts`。

### busy

一律 `--text-muted`，不用綠：綠代表「你可以動它」，而下載中的按鈕正是不能動的。

- `.busy-underline`：一條 2px 的線在按鈕文字底下左右掃過（1.5s）。給〈排版〉，因為它正在做的事
  就是重排字。包住 label 不是包住按鈕，這樣線的寬度是字的寬度。
- `.busy-edge`：底緣一條 3px 的線，40% 寬來回走（1.6s）。**其餘按鈕的預設**，之後有真的百分比
  可以無痛換成有寬度的版本。
- `prefers-reduced-motion` 之下兩者都停，改成靜止的淡墨線。狀態還在，只是不動。

### 螢光

四個墨水色，`Annotation.color` 存的是**色名不是色值**：

| 名字 | 亮 | 暗 |
| --- | --- | --- |
| `indigo` 蓼藍 | `#4a6d94` | `#7aa3cf` |
| `ochre` 赭石 | `#a4622f` | `#cf8b4e` |
| `moss` 苔綠 | `#5f7a4e` | `#8aab72` |
| `soot` 松煙 | `#3d4348` | `#9aa4ab` |

形態亮暗一致：一塊 `color-mix` 的底（亮 22%／暗 30%）加一條下緣的筆壓線（亮 40%／暗 75%）。
那條線是暗色下還讀得到的原因，不是裝飾。

四色都不撞葉綠，所以「我畫的」跟「我可以按的」不會混。舊的四個名字（`yellow` / `blue` /
`green` / `pink`）在 `markVar()` 裡對到最近的一個新色，**沒有 migration，也不需要**。

**要盯住的代價**：暗色下被標記那段字的對比從約 12:1 降到 8:1（仍高於 AA 的 4.5）。若有讀者反映
刺眼或難讀，**先調底的透明度 30% → 22%**，不要換做法。

### 圖示

不引圖示字型、不畫線條圖示。全站只有五個字元：`⋯`（詳情）`✕`（關閉）`‹`（回書架，桌機的上一頁鈕
也是它，下一頁是鏡射的 `›`）`⌄`（排序，目前由原生 `<select>` 自己畫），加上螢光色票的圓。每個都在
44×44 的直角方框裡、無底色。

**要第六個圖示之前，先問這件事能不能用兩個字說完**——bar 上的「目錄／筆記／排版」就是那個答案。

## 文案

大書區固定**兩行**：第一行位置、第二行時間感。算不出來就換一句成立的話，**不留空行**。四種說法
與門檻在 [docs/specs/ux-replan/spec.md](specs/ux-replan/spec.md) 與 `lib/book-status.ts`。

空狀態是一句名詞加一句怎麼開始（「還沒有書 / 把 epub 放進來，就從這裡開始。」），沒有插圖也沒有
按鈕——拖放本身就是入口。

錯誤說「發生什麼事＋怎麼辦」，不說錯誤碼。

## 界線：我們管容器，不管內容

design system 管〈排版〉這個 sheet 的樣式、控制項與文案；sheet 裡的那些數字（字級、
行高、每行字數）歸 spec 與 `settings.ts` / `line-length.ts`。那是可讀性工程，不是視覺風格。

由此四條：

1. **預設不是下載字。**`DEFAULT_SETTINGS.fontFamily` 維持系統字堆疊。書要能在打開的那一秒就讀。
   品牌一致由介面的襯線負責，不是由書負責。
2. **只補，不覆寫。**書只宣告了 `font-family: serif` 這種沒指名字面的情況才補上具體字族；書指名
   了就尊重它。唯一例外是書用絕對值寫的 `font-size`，一律轉成相對值——那會擋住讀者放大，屬於
   無障礙。
3. **可選字體最多三個。**每多一個 face 就是一次十幾 MB 的下載。用讀者的語言命名（「宋體／黑體」），
   選項上寫出下載大小。
4. **字級、行高、每行字數的預設值不寫進這裡**，留在 `settings.ts` 與 `line-length.ts`。
